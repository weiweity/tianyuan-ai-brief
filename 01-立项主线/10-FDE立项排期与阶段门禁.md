## 0. 产品逻辑（四层，按顺序做，不并行瞎冲）

| 层 | 能力 | 业务白话 | 依赖 |
|----|------|----------|------|
| **L1** | 知识库 + 知识库问答 + **管理端改库生效** | 标准答法有一个地方管、问得着；管理者改一条，坐席侧能搜到 | 话术真源 Owner、权限 |
| **L2** | 话术算法 + 意图检索 | 客户问什么，能推到合适快捷语 | L1 库质量够用 |
| **L3** | **全员推送 / 过期提醒 / 版本·审批**（非「能改库」本身） | 改库后的广播同步、过期治理、版本流 | L1 改库流程已稳 |
| **L4** | 桌面端嵌入聊天 | 坐席在工作台里一键用，不用另开网页 | L1–L3 可用 + 客户端/嵌入条件 |

**边界（立项必须写死）：**

- 人在环：推荐 → 坐席确认 → 发出（**不是**全自动代回）  
- 先内部，后外包（外包无内网是战略背景，不是本周交付）  
- 与 BI：BI 看服务结果；本项目改「应答这一步怎么干」

```
① 摸底调研  →  ② 立项/预算批准  →  ③ 范围冻结  →  ④ 方案与排期
     →  ⑤ 分阶段交付  →  ⑥ 小范围试点采用  →  ⑦ 复盘扩面
```

| 关卡 | 状态（2026-07-26） | 证据 |
|------|-------------------|------|
| ① 摸底调研 | **已完成（第 0 周）** | 多部门访谈 + 任务取舍 + 主候选锁定话术库 |
| ② 立项 / AI 费用批准 | **进行中 · 本阶段主线** | 软件未开发；材料服务于申请与启动 |
| ③ 范围冻结 | 未开始 | 待立项通过；**进入前置**见下表 + `16` 检查表 |
| ④ 方案与详细排期 | 仅有方向稿 | 待费用与立项齐 |
| ⑤ 分阶段交付 L1–L4 | **未开工** | — |
| ⑥ 试点采用 | **未开始** | 不得写成「试点准备中」 |
| ⑦ 复盘扩面 | 未开始 | — |

**结论：** 按 FDE/项目流程，你现在 **正确停在②**。  
若下周就写「名单培训、部署上线」，才是**跳关**，不专业。

## 2. 非 AI 视角排期（一人 FDE · 保守可讲给金主）

> 周期 = **立项与费用批准之后**才起算交付；批准前只算「申请准备工时」。  
> 单位：**可用工作周**（出差/全职旁线占用周不计入 6–8 周，或单独加注）。假设你主轨约 70% 时间；供应链等布局 **≤20% 且非本项 KPI**。

### 2.1 立项前（现在 → 立项会）

| 周次 | 你做什么 | 交付物 | 金主可见 |
|------|----------|--------|----------|
| **W0 已完成** | 多部门摸底、收敛主候选 | 纪要、任务包、边界 | 调研完成 |
| **W1（本周/下周）** | 立项说明 + 费用申请材料 + 周会同步 | 1 页立项卡 + 费用科目说明 | **是否批立项/费用** |
| **W2（缓冲）** | 补材料、对齐客服负责人「愿不愿意立这个项」 | 业务侧原则同意记录 | 条件齐了再批 |

**立项前成功标准：** 金主拍板「做 / 不做 / 降级」；若做，批费用或明确费用路径。  
**不是：** 系统上线、试点人数、周活。

### 2.2 立项通过后 · 交付总览（约 4–5 个月到可试点）

| 阶段 | 周期量级 | 做什么 | 可验收 |
|------|----------|--------|--------|
| **G0 范围冻结** | 1–2 周 | 写死 L1–L4 本阶段做到哪、不做清单、成功指标 | 书面 Scope v1 |
| **G1 交付 L1** | 3–5 周 | 知识库 + 问答 + 管理端改库生效 | 内部可访问；改一条同日可检索 |
| **G2 交付 L2** | 3–4 周 | 意图/检索推荐快捷语 | 黄金问法 Top3 门槛见 `16` |
| **G3 交付 L3** | 2–3 周 | 推送 / 过期提醒 / 版本·审批 | 广播与治理闭环 |
| **G4 交付 L4** | 3–5 周 | 桌面端嵌入聊天（依赖环境） | 试点机可嵌入使用 |
| **G5 内部试点** | 3–4 周 | 3–5 人采用运营 | 连续使用 + 缺口清单 |
| **G6 复盘** | 1 周 | 是否扩面/接外包/接质检 | 书面结论 |

**粗时间盒（立项日 = D0）：**

```
D0 ───────── 立项/费用批
D0+2w ────── Scope 冻结
D0+6~8w ──── L1 可用
D0+10~12w ── L2 可用
D0+13~15w ── L3 可用
D0+16~20w ── L4 嵌入（环境顺利时）
D0+20~24w ── 内部试点可汇报
```

**并行旁线（全程 ≤20% 带宽）：** 仓储查重、备案跟会、挡设计主 R 需求、周报。

### 2.3 若金主要「更快看见东西」

可砍成 **最小立项包（建议写进申请）：**

| 包 | 周期 | 包含 | 不含 |
|----|------|------|------|
| **MVP-A（推荐写入首期费用）** | 立项后 **6–8 周** | L1 + L2 初版 + 网页/内网入口（非必须桌面嵌入） | L4 桌面、外包开通、质检 |
| **MVP-B** | 再 **+4–6 周** | L3 + 采用运营 | 全自动代回 |
| **MVP-C** | 再 **+4–6 周** | L4 桌面嵌入 | — |

首期费用申请建议只背 **MVP-A**，避免一次承诺四层全上。

## 3. 周会怎么讲（给金主 · 30 秒）

> 挂您线下第一周：完成中台摸底。客服因转外包、无内网，适合做「话术库/快捷语」立项。  
> **软件还没做**；当前按流程停在 **立项与 AI 费用申请**。  
> 产品方向四层：知识库问答 → 意图检索 → 统一更新 → 桌面嵌入聊天。  
> **请您看：是否同意以此立项并推进费用**；批了再排开发与试点。

**本周不说：** 本周五上线、本周培训、本周周活。
