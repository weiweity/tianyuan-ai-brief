## 1. 页面 Goal

让决策者在一场会议内，分别为两个候选项目选定 A / B / C 路径，确认预算与止损、具名 Owner、超线停扩权和会后责任，并带走不会被误认成正式审批的可校验会议草稿。

本轮 10 分标准不是“页面永远无需迭代”，而是：在当前 Goal、浏览器范围和威胁模型内，无已知 P0 / P1；每个关键结论都有可复跑的自动证据。

## 4. 对抗 Review

已关闭的代表性攻击 / 误用场景：

1. 同长度文案变化不能再被弱结构指纹吞掉；内容身份只认经过验证的 SHA。
2. 老页面发现新 shell 时用带 release 的 URL 整页刷新，不把新内容套进旧 JS。
3. HTTP 模块图打成一个带版本的 Bundle，避免“新主程序 + 旧子模块”。
4. release 指纹绑定真实 Bundle、CSS、bootstrap、规范化 HTML / CSP、Mermaid 和 Logo 字节。
5. SHA 正确但页签、区块、表格、meta 或 t6 门禁结构错误的正文不会覆盖 LKG。
6. `//evil`、`assets/%2e%2e`、SVG 外链 CSS / filter / marker / fill 被清洗，`url(#fragment)` 保留。
7. Mermaid 慢、缺失或即时打印时，页面仍有同步可读文字且 PDF 恰好七页。
8. 冷启动无缓存且 manifest 失败时，HTTP 用户得到 ≥44px 的重试操作，不会看到本地开发命令。
9. 密集页面的左右翻页浮层不会覆盖表格、Owner 或详情；页签和键盘导航仍可用。
10. 流程图支持 Enter / Space 打开；模态框令背景 inert、Tab 不逃逸，Esc 关闭并回焦触发元素。

## 6. 10 分的事实边界

- 页面不会替业务方填写真实 Owner，也不会把本机勾选伪装成审批人签字。
- 供应链准确率、业务收益和最终采用仍需真实样本、业务终审和正式组织留痕。
- SHA-256 证明文件未被无痕修改，不等同于电子签名或权威审计后端。
- 本报告的工程 10 分只覆盖当前页面 Goal、浏览器范围和仓库内交付链；远端 PR、CI、Pages 与线上 release 需在发布后另行核验。
