### 5.2 生命周期标签

| 标签 | 含义 | 维护规则 |
|------|------|----------|
| **现行** | 当前决策或执行真源 | 状态变化当日更新 |

| **生成物** | PDF、HTML、截图、Bundle | 必须指回可编辑源 |

## 6. 更新协议

| 发生了什么 | 先更新 | 再同步 |
|------------|--------|--------|
| 组合优先级、健康度或阶段变化 | 本驾驶舱 | 对应项目章程 |
| 客服范围、成功标准或里程碑变化 | 项目章程 | G0 台账的 DEC / CR、驾驶舱摘要 |
| Owner、截止日、证据或风险变化 | G0 台账 | 仅在影响组合状态时更新驾驶舱 |
| 日期或团队资源变化 | 总排期 | 项目章程里程碑、周状态 |
| 验收公式、阈值或数据集变化 | Scope 与验收 | G0 台账的决定记录 |
| 新增原始访谈 | `03-调研与叙事/notes/` | 纪要索引 |
| 供应链状态变化 | `05-供应链布局/` | 影响组合顺序时更新驾驶舱 |
| 汇报 Web 重新启用 | 先形成独立变更决定 | 不得直接改成客服 Agent 执行台 |

维护频率：

- 驾驶舱：组合状态变化当日更新，至少每周复核一次；
- G0 台账：G0 活跃期每个工作日更新；
- 章程、总排期、Scope、费用：相关决定生效当日更新；
- 分类汇总：新增、移动、归档文件当日更新。

## 7. 防丢失与交付边界

> **仓库状态不在文档内静态断言。** 客服核心目录已进入版本控制；是否已提交、被忽略或已推送，交接时必须以实时 Git 检查为准。`08-工具/` 只允许白名单脚本进入版本控制，禁止整目录盲加。

- 换电脑、交接或发布前，先运行 `git status --short --untracked-files=all`；
- 同时运行 `git check-ignore -v <目标文件>` 与 `git log -1 --oneline`，分别确认忽略来源和最后提交；
- 受限纪要、人员信息和飞书资源标识是否进入 Git 必须单独决策；
- 已收尾 Web 的在线版本可能仍是旧汇报，只能辅助回看，不能替代本地业务真源；
- 未经明确要求，不提交、不推送、不部署。
