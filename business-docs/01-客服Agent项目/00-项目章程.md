### 1.2 名称边界

“客服 Agent”是项目名称，不等于首期建设完整自治 Agent。

首期只验证：

1. 标准话术能否成为可治理、可追溯的组织资产；
2. 坐席能否快速找到正确候选；
3. 系统能否在无依据、歧义或敏感场景下拒答或转人工；
4. 内容更新、发布、下架和回滚是否可审计；
5. 真实坐席是否持续使用并获得可核验收益。

自动代回、完整质检、桌面嵌入、外包全量接入和复杂 Agent 闭环都不属于 MVP-A。

## 2. 背景与问题

客服逐步转外包后，乙方无法依赖公司内网、个人经验和“自己人默契”获得标准答法。当前风险包括：

- 话术分散，更新与版本不可追溯；
- 新人和外包学习成本高，答复质量依赖个人；
- 不知道正确答案由谁维护、何时失效；
- 搜索与问答没有稳定内容真源时，会放大错误；
- 既有 `dafuyan-wording` 可能可复用，但所有权、维护、测试、部署与 TCO 尚未审计。

项目机会是先把“正确答案由谁维护、坐席如何找到并确认使用”做成稳定闭环，再依据真实数据决定是否扩到更复杂的 Agent 能力。

## 3. 目标与成功定义

### 3.1 目标

建设一个内部可访问、可治理、可检索的客服 Agent MVP，使标准话术从个人资料变成由业务 Owner 负责的组织资产，并让坐席在人工确认前提下获得可追溯的候选建议。

### 3.2 MVP-A 成功标准

| 维度 | 首期门槛 |
|------|----------|
| 内容资产 | 有效话术 ≥200 条，或 G0 共定 N；每条含稳定 ID、平台 / 场景、状态、Owner、来源、版本与有效期 |
| 检索质量 | 冻结 20 条正例全量盲测，Top3 命中率 ≥70%；不少于 5 条负例，错误直答 = 0 |
| 引用与追溯 | 引用 / 版本正确率 = 100%；每次建议能回到话术 ID、版本与来源 |
| 真实采用 | 3～5 名内部坐席连续两周，每人每周 ≥5 个去重真实任务 |
| 效果指标 | 同时报有用率、采纳率、未命中率、查找时长及分子 / 分母，不以搜索次数单独通过 |
| 人在环 | 自动代发次数 = 0；无可靠依据时拒答或转人工 |
| 内容治理 | 草稿 → 复核 → 发布 / 下架 → 回滚链路可用且有审计记录 |
| 项目结论 | 能形成继续扩面、限时整改或停止的书面决定 |

指标可以在 G0 根据基线调整；一经签发，变更必须进入 CR / DEC 并整集重测。

## 4. 范围

### 4.1 In Scope

| 能力 | MVP-A 最小范围 |
|------|----------------|
| 内容资产 | 单一逻辑真源；稳定 ID、状态、Owner、来源、版本、平台 / 场景和有效期 |
| 管理端 | 起草、复核、发布、下架、回滚与审计 |
| 坐席端 | 关键词与意图检索，返回 Top3 候选 |
| 问答 | 只基于已发布且有效内容回答；显示引用；无依据时拒答 |
| 反馈 | 有用 / 无用、未命中、候选采纳和问题类型 |
| 权限 | 最小 RBAC；管理、复核、坐席和只读角色 |
| 可观测性 | 使用、质量、成本、错误、审计与安全事件 |
| 运行 | 监控、备份、恢复、回退、值班和支持边界 |

### 4.2 Out of Scope

- 自动点击发送、自动接管客服会话或 RPA 代回；
- 全量智能质检、评分、处罚或合规终局判断；
- 客服桌面客户端深度嵌入；
- 外包网络、账号、终端和权限全量开通；
- L3 复杂推送、完整多级审批和大规模版本治理；
- 供应链备案、BOM、对账、预警或相关预算；
- 将已收尾汇报 Web 直接改造成生产产品。

### 4.3 Web 与供应链边界

| 对象 | 现行定位 | 可以复用 | 不可继承 |
|------|----------|----------|----------|
| `web-decision-brief` | 已收尾的汇报 Web / 设计参考 | 品牌素材、信息表达、交互经验、测试方法 | 业务状态、预算、会议草稿、代码架构默认继承 |
| 供应链 | 组合 P1、独立项目、当前暂停 | 未来可复用门禁方法和评测框架 | 客服预算、Owner、WBS、Ddev、指标或资源 |
