### 1.2 名称边界

“客服 Agent”是项目名称，不等于首期建设完整自治 Agent。

若 08-04 客服确认项目侧推荐，一期只验证：

1. 一个真实、高频、损失明确的客服任务能否被软件有效改善；
2. 坐席能否少切换、少查找、少出错，同时保留人工判断；
3. 系统没有可靠依据时，能否明确说“不知道”并回到人工流程；
4. 权威内容变更、下架和恢复是否有人负责、可以追溯；
5. 3～5 名坐席真实使用两周后，证据是否支持扩大、整改或停止。

一期正式灰度前先用冻结的脱敏历史问题做影子回放和业务盲审。首批坐席候选为 2 名新手、2 名老手，但人员对称不等于业务覆盖：必须先按平台 × 意图 × 班次 × 活动期 × 风险检查覆盖，覆盖不足时增补或替换，总体优先控制在 3～5 人。

自动代回、四个方向一起做、所有平台一次接完、外包全量接入和复杂自治 Agent 都不属于一期。

## 2. 背景与问题

目前项目侧归纳的主问题是：商品和活动话术分散在多张在线表格，语义检索困难；坐席找不到可核对依据时不敢确定，需要询问资深客服、话术师或兼任培训师的产品老师。访谈还提到夜间接待可能等待约 15 分钟、活动话术可能过期、外包坐席更换后需要重复培训。以上是需求假设与访谈陈述，真实发生频次、等待时长分布、平台差异和经营影响仍待客服提供基线，不能把“15 分钟”写成已验证平均值。

因此项目侧推荐一期做“证据型客服助理”：坐席用自然语言查询，系统返回带来源、版本、适用平台 / SKU / 活动与有效期的候选话术；信息不足时先澄清，有冲突、过期或无依据时升级人工；坐席始终人工确认并自行发送。灰度前先用历史问题做影子回放，避免把脏内容或错误适用范围直接暴露给真实客户。

08-04 由客服总监、经理、客服 BP、内容 / 话术负责人候选和至少 3 名坐席共同确认、修正或否决上述推荐。主问题仍必须满足：真实发生、有分母和基线、软件能在较短时间形成最小闭环、风险可控、两周灰度可以证伪。若证据不足，会议结论就是 `OPEN + Owner + 日期`，不能把项目侧建议写成客服已经同意。

## 3. 目标与成功定义

### 3.1 目标

在客服确认推荐方案后，建设一个内部可访问、有人负责、能监控、能回退的证据型客服助理，一期只覆盖商品 / 活动话术的一个最小闭环。系统帮助坐席获得可确认的安全答案，但不替坐席发送、不替业务负责人决定正确答案，也不把点击次数包装成业务价值。

### 3.2 一期成功标准

| 维度 | 首期门槛 |
|------|----------|
| 问题适配 | 主任务有真实样本、发生频次、现状耗时 / 错误 / 升级和经营影响；同时保留“不上新软件”的对照办法 |
| 内容资产 | 若主任务涉及知识 / 话术，权威来源、Owner、版本、适用平台 / 场景、有效期与冲突规则全部清楚 |
| 灰度前影子回放 | 用冻结的脱敏历史问题和内容快照做业务盲审；通过质量、安全、过期 / 冲突和升级门槛后才开放真实坐席灰度 |
| 上线前冒烟 | 冻结 20 条正常命中任务全量盲测，Top3 命中率暂定 ≥70%；信息不足、冲突 / 过期、跨平台、错 SKU、越权承诺、敏感信息六类风险各不少于 2 条，全部正确澄清 / 拒答 / 升级，风险错误直答 = 0；该门槛不单独证明业务成功 |
| 证据与追溯 | 每次系统辅助都能回到对应任务证据；若涉及知识 / 话术，引用 / 版本正确率 = 100%，并可追溯到内容 ID、版本与来源 |
| 真实采用 | 3～5 名内部坐席连续两周，每人每周 ≥5 个去重真实任务 |
| 效果指标 | 重点报告获得“可确认安全答案”的时长、平台指标、质量、采用 / 大幅修改 / 拒绝、未命中、升级和稳定性；同时报原始计数与分母，不以搜索次数单独通过 |
| 人在环 | 自动代发次数 = 0；无可靠依据时拒答或转人工 |
| 内容治理 | 草稿 → 复核 → 发布 / 下架 → 回滚链路可用且有审计记录 |
| 项目结论 | 只能形成扩大、一次限时整改后重测、停止三种书面决定 |

指标可以在 G0 根据基线调整；一经签发，变更必须进入 CR / DEC 并整集重测。

## 4. 范围

### 4.1 In Scope

| 能力 | 一期最小范围 |
|------|----------------|
| 主任务 | 项目侧建议只做商品 / 活动话术查询与确认；08-04 客服确认后冻结，有原流程和零新增软件对照 |
| 坐席端 | 自然语言查询、必要上下文、候选话术、权威原文、来源、版本、平台 / SKU / 活动有效期、澄清 / 升级、人工采用 / 编辑 / 拒绝；不自动发送 |
| 内容端 | 若涉及知识 / 话术，支持起草、复核、发布、暂停、下架、回退与记录 |
| 反馈 | 查询上下文、候选结果、采用、大幅修改、拒绝、澄清、升级、未命中、编辑差异和最终任务结果 |
| 权限 | 最小 RBAC；管理、复核、坐席和只读角色 |
| 可观测性 | 使用、质量、成本、错误、审计与安全事件 |
| 运行 | 监控、备份、恢复、回退、值班和支持边界 |

### 4.2 Out of Scope

- 自动点击发送、自动接管客服会话或 RPA 代回；
- 四个业务方向在一期同时开发；
- 自动作出质检处罚、合规终局判断或业务批准；
- 客服桌面客户端深度嵌入；
- 订单、物流、退款与售后系统深度集成；
- 外包网络、账号、终端和权限全量开通；
- L3 复杂推送、完整多级审批和大规模版本治理；
- 供应链备案、BOM、对账、预警或相关预算；
- 将已收尾汇报 Web 直接改造成生产产品。
- 任何早期学习项目的代码、数据、配置、账号、部署或迁移。
