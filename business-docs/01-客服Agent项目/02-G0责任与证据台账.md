## 4A. 九项决定在 60 分钟内怎样处理

| 决策 ID | 本会目标 | 合格输出 |
|---|---|---|
| DEC-REQ-01 · 一期主问题 | 校准项目侧建议 | 有会前任务和损失证据则确认或修正；否则保持 `PRECONFIRM / OPEN` 并补证 |
| DEC-REQ-02 · 主用户与场景 | 条件决定 | 定到哪类坐席、哪个平台、哪个任务；不记录真实姓名 |
| DEC-REQ-03 · 最小闭环 | 决定业务边界 | 校准“证据卡 → 澄清 / 升级 → 人工确认发送 + 灰度前影子回放”；技术实现会后验证 |
| DEC-REQ-04 · 做什么 / 不做什么 | 现场决定 | 校准一期商品 / 活动话术边界；自动代发、订单 / 物流 / 售后深度集成等明确排除 |
| DEC-REQ-05 · 成功 / 停止 | 决定口径，不编目标值 | 定指标名称、来源和 Owner；公式、基线、阈值最迟 08-12 由业务与 QA 共同确认 |
| DEC-REQ-06 · 权威来源 | 会前预填、现场确认 | 定候选真源、内容 Owner 与冲突裁决；详细权限最迟 08-07 补齐 |
| DEC-REQ-07 · 试点人口 | 决定分层原则 | 2 新手 + 2 老手为首批候选；先验平台 × 意图 × 班次 × 活动期 × 风险覆盖，定 3–5 人替补和退出 |
| DEC-REQ-08 · 系统约束 | 只收业务输入 | 定人数、峰值、平台、设备、网络与安全限制；技术方案和容量由工程在 08-06 前验证并书面记录 |
| DEC-REQ-09 · 后续责任 | 现场决定 | 项目、业务、内容、验收和工程各有唯一拍板人 / 执行人、截止日和证据位置 |

会议成功不等于九项全部为 `DEC`；成功标准是九项都被处理，且每个非 `DEC` 项都有明确原因、唯一 Owner、截止日和证据位置。
