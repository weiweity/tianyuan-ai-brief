## B. 证据型客服助理专项评测（项目侧 PRECONFIRM）

本节是项目侧推荐方案的预置协议，只有客服业务 Owner 书面确认后才成为一期验收协议；若客服修正或否决，必须通过 DEC / CR 重写，不能把项目侧建议冒充业务签发。冻结验收集至少 **50 条**：20 条正常正例、至少 12 条安全负例（六类 × 2）和至少 18 条长尾 / 错别字 / 改写 / 上下文鲁棒性样本。它们只构成灰度前影子回放与上线前冒烟门，不单独证明提效、因果或规模收益。

### B.0 灰度前影子回放门

- 使用**独立冻结、来源合规且经批准脱敏**的预检问法与同一权威内容快照，系统结果不展示给正在接待客户的坐席；纯人工 / 合成项必须按来源标注，不得冒充历史真实问题；
- 业务标注人与独立盲审人在看到系统输出前冻结可接受话术 ID、必要澄清和升级条件；
- 同时回放关键词基线与候选方案，逐条检查来源、版本、平台 / SKU / 活动适用性、有效期和风险行为；
- 错误直答、过期 / 跨平台误用、越权泄露或自动代发任一 `>0`，不得开放真实坐席灰度；
- 影子回放通过只证明“可以受控试用”，不证明坐席提效或客户体验改善。
- G1a 固定使用本节 `20 + 12 + 18` 独立预检集；进入真实 Pilot 后前瞻取得的 `REAL-FWD` 只进入 G1b / 扩面账，不得反向补 G1a 或与调参集混用。

### B.1 中国电商分层覆盖规则

- G0 必须先冻结“平台 × 意图 × SKU / 商品 × 活动阶段 / 有效期 × 班次 × 任务复杂度 × 所需上下文 × 升级 / 风险”覆盖矩阵，并为每个正 / 负例标注分层标签；
- 一期业务范围只建议覆盖商品话术与活动话术；订单、物流、退款和售后系统深度集成不进入一期，但相关越界问法必须作为负例；
- 覆盖矩阵以“平台 × 店铺 / 品牌 × 意图 × 活动类型 / 阶段”为行键，以正常命中、信息不足、冲突 / 过期、跨平台、错 SKU、越权承诺、敏感信息为列；每行至少 1 条正常命中，每个适用风险单元至少 1 条任务；不适用单元必须填写 N/A、理由和业务审核人，不能留空；

### B.4 统一计分与防过拟合规则

1. 业务标注人在看到系统输出前冻结可接受话术 ID 集；实现者不得在验收当天补答案。
2. G1a 使用全部冻结样本；正常正例 Top3 仍以 20 条为固定分母，不允许“业务抽样”、删除难题或只报成功案例；安全负例与鲁棒性样本分栏报告，不能混入正例稀释分母。
3. `Top3 命中率 = Top3 命中题数 / 20`；并列结果按系统实际展示顺序取前三。
4. 任何未发布、已过期、平台不适用或引用版本错误的话术，按未命中计。
5. 全部冻结安全负例必须正确澄清、拒答或升级；任一负例错误直答、自动代发、越权泄露均直接不通过。鲁棒性样本中的安全行为同样是硬门。
6. 调参 / 开发集与冻结验收集必须按样本 ID、语义簇和来源去重，互不重叠；若冻结集或内容快照变化，生成新版本并整集重测。
7. 同一冻结集同时测关键词基线和候选方案；语义 / 模型无可解释增益时，默认采用成本更低、风险更小的方案。

**G1a 暂定门槛：** 总体正例 Top3 ≥ **70%**；每个已冻结分层 Top3 ≥ **50%** 且至少命中 1 条；总体及各分层来源 / 版本 / 适用范围正确率 = **100%**；负例错误直答 = **0**。任一分层未达线即失败，不能用总体均值抵扣。阈值可在 G0 依据基线提高；如需降低，必须有真实任务基线、业务 Owner 与 QA 双签及 DEC，且不得取消“每层至少 1 命中”和分层否决。

| 确认可用安全答案时长 | 从客户问题进入到坐席获得可核对、可确认的话术并完成确认的中位数、P90 | 与同平台、同意图、同活动阶段和同难度任务比较；只缩短模型响应不算提效 |
| 专家升级等待时长 | 从坐席发起升级到收到可执行答复的中位数、P90 | 单独报告白天 / 夜间与班次，不用访谈“15 分钟”代替基线 |
| 错误话术率 | 授权抽样人工复核判错的任务 / 被复核任务 | 平台错配、过期、引用错均算错误；不得从复制或自报结果自动推断正确性 |

**暂定门槛：** ≥3 人 × 连续 2 周 × 每人每周 ≥5 个去重真实任务；计划首批 4 人（2 新 + 2 老），允许 3～5 人；业务扩面目标 50～100 人，架构容量仍为 50～150 人；自动代发 = 0。抽样按“坐席层（新/老）×业务场景（平台/意图/活动/风险）×自动事实结果（复制/未命中/放弃/升级/重选）”三维分层：高风险、无命中、放弃、升级和重选全审；成功复制至少抽 20%，两周不足 30 个根问题时全审。该样本只能证明受控可行性，不能单独证明规模收益。G0 必须依据现状基线冻结质量、确认安全答案时长、复制、抽样修改 / 发送 / 适用性、未命中 / 放弃 / 升级、稳定性和成本目标，任一硬指标未达标不得扩面。

### C.1 一期探索性对比规则

1. 首批候选为 2 名新手、2 名老手，但先按平台 × 意图 × 班次 × 活动期 × 风险检查覆盖；覆盖不足时增补或替换，总体优先保持 3～5 人。
2. 一期不称正式 A/B；新手和老手分别报告“辅助条件 - 基线条件”的匹配任务描述性差异，不用“新手对老手”的原始水平差证明软件效果。
3. 匹配任务必须在平台、意图、活动阶段、班次类型、复杂度、风险等级和内容快照上完全一致，但不得重复同一道题；写入 matched_pair_id。无法配对的任务不进入配对差异，但继续进入安全和采用统计。
4. 匹配规则、配对清单、最低有效 pair 数与排除项在 Pilot Ready 前签发，试点中不得事后换对；内容快照或活动阶段变化时该 pair 作废并单列。
5. 同一坐席使用软件后可能产生学习效应，不能假设其完全回到未使用状态；记录暴露顺序和训练影响。
6. 使用者环比只作采用、未命中、编辑、稳定性和趋势观察，不能作为唯一因果证据。
7. 每个任务必须保留平台、意图、SKU / 商品、活动阶段 / 有效期、班次、复杂度、所需上下文、升级 / 风险和内容快照版本。

### C.2 二期正式试验方向

一期 M4 通过且二期另行批准后，优先采用同期、分层随机 A/B，并按新手 / 老手分别报告；无法随机时，预注册对照组、平行趋势检验和差分中的差分方案。任何设计都必须控制平台、活动阶段、班次和任务难度，避免把大促、换班或内容更新误判为软件效果。

### C.4 CR-002 / CR-003 搜索证据、复核与训练边界

1. CR-002 是现有 `search / events / Dashboard` 的增量，不替换架构 SSOT，不新增平行搜索或反馈平台，不影响 CR-001 `work_order_*` 业务工单分析。
2. 自动事实只包括：脱敏搜索问法、绑定发布版本与内容哈希的真实候选、成功复制、无命中、显式放弃与升级；“搜索原句 + 复制话术”不是完整聊天记录。一期不再要求强制八枚举自报，也不实现 `usage_outcome` / `PreviousUsagePrompt`。
3. 人读“已确认平台”映射到 wire/DDL canonical `platform`，Phase 1 必须经用户确认：直接手选/修正写 `platform_source=manual`；接受热键瞬时 `detected_platform` 提示可写 `platform_source=foreground_process`，但提示本身不是自动真源。禁止轮询、读取窗口标题和监听剪贴板历史；未来 `native_integration` 另行授权。
4. telemetry 故障时允许显著标记的 `collection_disabled/stateless` 安全搜索，但整个会话排除运行指标、语料候选和 G1b 分母；DLP、Auth 或内容快照不就绪继续 fail-closed。
5. 数据分层固定为 `0 / 14 / 30` 一期安全基线：raw 原句只在请求内存、脱敏问法正文 14 天、个人级结构化事件 30 天；已由 `EVD-G0-11-SECURITY-BOUNDARY-20260810` 批准。只有经二次 DLP、业务 + 数据安全双审、用途锁定和删除血缘登记的语义资产才可晋级，向量、训练集、教师输出和备份不得绕过源删除。
6. 一期只预埋可审计训练合同、空模板与纯合成 fixture；线上仍为 Unicode bigram，本地开源 embedding 只做隔离离线影子。未来只允许训练检索、意图和重排，问法资产与答案发布版本解耦；行为仅作候选信号，不能直接成为正确标签。
7. 二期仍须另行批准，采用两周一个版本的批训、业务 + 数据安全双审和人工发布；`train / G1a / G1b` 按语义簇隔离。DeepSeek 仅为可替换教师候选而非微调依赖，GLM 无书面授权禁止蒸馏；教师运行不可变、抗注入、隔离执行并受费用 cap 约束。

CR-002 的逐项验收以当前[设计索引](20-设计-进行中/README.md)登记的 `48-CR-002测试计划.md` 为准；公开根文档只链接已跟踪的设计索引，避免未成组提交时形成悬空链接。
