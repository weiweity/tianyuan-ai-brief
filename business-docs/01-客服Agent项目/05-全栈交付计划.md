## 1. 客服一期怎么形成双闭环

```text
坐席输入问题与必要上下文
      ↓
系统用 Unicode bigram 在线检索；隔离环境可跑 embedding 离线影子
      ↓
展示候选话术、权威原文、来源、版本、平台 / SKU / 活动有效期
      ↓
信息不足则澄清；冲突、过期或无依据则升级
      ↓
坐席核对并人工复制、放弃、重新选择或升级
      ↓
系统只记录脱敏查询、绑定版本的候选、成功复制、无命中、放弃与升级
      ↓
业务与数据安全按三维样本离线复核修改、发送和适用性
```

以上是当前话术推荐方向；书面 EVD、G0、Ddev、`DEV-M0` 与 `DEV-M1` 合成产品实施已完成。DEV-M1 W0～W5 已完成合成金标、mock auth / policy、受控 SearchBackend、Search + Events 事务与 50 条 runner；PR #17～#20 已合并，最终 `main@5cf650c`，退出 CI 三路全绿。desktop 仍未接 API，真实内容、飞书 auth、完整九端口与运行激活仍不存在。这些结果仍不等于真实 G1a 或真实试点已放行。系统不能自动替客服做高风险决定或发送消息；来源不可靠、权限不足、信息不足或结果不确定时，必须澄清、升级或回到人工流程。复制成功不等于发送、答对或客户满意；一期取消强制八枚举自报，修改 / 发送 / 适用性只按离线样本复核。

业务工单走另一条独立闭环：批准的 CSV/XLSX 导出文件 → 预检与映射 → 白名单标准化 → 聚合 / 筛选 / 下钻 → 脱敏导出与审计。它统一叫**工单分析**、使用 `work_order_*`，不写回班牛；检索 / 采纳信号形成的内部改进对象统一叫**话术优化待办**、使用 `iteration_task*`，不承载业务工单原始明细。CR-001 已登记前者进入一期方向，真实数据启用仍受字段白名单、安全、保留期、书面 EVD、G0 与 Ddev 门禁。

## 4. 一期软件边界

一期按当前设计做两个分域闭环；G0 / Ddev 已 Pass，合成开发已完成 `DEV-M0` 与 `DEV-M1`，真实运行仍待后续门禁。至少包括：

- 清楚的登录与权限；
- 唯一且可靠的数据 / 文档来源；
- 一条从自然语言查询、必要上下文、证据展示、澄清 / 升级到人工确认的完整流程；
- 来源、版本、适用平台 / SKU / 活动与有效期；
- 自动记录脱敏搜索原句、与 `release_id + script_id + script_version + content_hash` 绑定的候选、成功复制、无命中、显式放弃与升级；重新选择用 `parent_query_id + attempt_kind=original|reselection` 归并根问题，同时保留每次操作；
- 修改、是否发送与话术适用性只做“坐席层 × 业务场景 × 自动事实结果”的离线三维抽样复核，不采最终发送正文，不做强制八枚举自报；
- Dashboard 的业务**工单分析**：批准文件手工导入、字段校验 / 映射、聚合、筛选、明细下钻、脱敏导出与审计；全链路不写回源系统；
- Dashboard 的内部**话术优化待办**：由无命中、跳过 Top1 等信号生成，受控开始 / 关闭，不自动改 Answer；与 `work_order_*` 分表、分 API、分权限；
- 灰度开关、监控、备份与快速退回原流程；
- 3–5 名试点坐席可完成真实任务。

一期客户端为 **Windows Electron**；macOS 后续；iOS / Android 不进一期。Mock 身份只限开发 / 演示，试点和生产必须真实飞书 OAuth + 服务端 RBAC。

一期不做：自动代发、班牛实时 API / 自动建单 / 填单 / 改单 / 写回、订单 / 物流 / 退款 / 售后系统深度集成、所有平台一次接入、供应链需求、对外大规模上线或自治 Agent。

## 5. 技术选择顺序

工程团队按以下顺序做决定：

1. 一期到底解决哪一个真实任务；
2. 用户是谁、在哪个平台工作、预计多少人使用；
3. 正确答案来自哪里、谁能修改、谁能批准；
4. 哪些数据敏感，是否允许进入 AI 模型；
5. 不用 AI 的最简单方案能做到什么程度；
6. AI 能否带来可测的额外价值；
7. 如何记录、监控、备份、恢复和停止；
8. 最后再选择前端、后端、数据和 AI 技术。

技术栈结论由工程负责人提出，由 IT / 安全和项目负责人复核；不会让客服人员在会上对技术框架投票。

现行技术路线已由 37/32 冻结：Route A 全自研，Electron + Node/TS API + PostgreSQL SoR，Unicode bigram 为一期线上检索主路；本地开源 embedding 只做隔离的离线影子。DeepSeek 是可替换推理 / 教师候选，不是微调依赖；GLM 在取得书面授权前禁止蒸馏。实现不得重开 Dify/RAGFlow 主中台或向量主路；精确依赖版本只在 Ddev 通过后的 DEV-M0 锁定。

训练路线只预埋在设计合同中：问法语义资产与答案发布版本解耦，行为信号只产生候选，不直接当正确标签；未来只训练检索、意图、重排，不训练生成回复。任何真实样本晋级须二次 DLP、业务 + 数据安全双审、用途锁定与删除血缘；二期获批后才可按双周版本批训、不可变 teacher-run、预算 cap 与人工发布执行，并保持 `train / G1a / G1b` 语义簇隔离。

## 6. 开发与发布流程

```text
任务可开发
   ↓
设计、接口、数据、测试共同评审
   ↓
小步开发并自动测试
   ↓
测试环境验证
   ↓
客服验收
   ↓
冻结历史问题影子回放与业务盲审
   ↓
3–5 名坐席内部灰度
   ↓
达标继续 / 触线停止并回退
```

### 环境

| 环境 | 使用什么数据 | 用途 |
|------|--------------|------|
| 本地 | 纯生成样本；获批后才可用脱敏样本 | 开发、合同校验和基础测试 |
| 测试 | 冻结的脱敏数据 | 联调、完整测试和安全检查 |
| 影子 | 冻结的脱敏历史问题与内容快照 | 业务盲审，不向真实客户展示 |
| 隔离训练 / 教师 | 一期仅纯合成 fixture；未来仅获批晋级资产 | 离线 embedding 影子、获批批训与教师运行；与测试 / G1a / G1b 分账 |
| 灰度 | 批准的最小真实数据 | 3–5 名内部坐席试用 |
| 正式环境 | 一期默认不扩面 | 灰度验收后另行批准 |

## 9. 什么任务可以进入开发

每项开发任务必须先有：用户与问题、做与不做、验收条件、界面状态、数据与权限影响、测试方法、负责人、依赖和回退办法。关键内容缺失时保持“未准备好”。

## 10. 什么才算完成

只有在代码和文档经过复核、自动测试通过、权限和异常状态完整、数据记录可观察、没有未处理的严重风险、业务验收证据归档、回退可执行时，功能才算完成。

“页面能打开”或“AI 回答了几个问题”都不等于完成。
