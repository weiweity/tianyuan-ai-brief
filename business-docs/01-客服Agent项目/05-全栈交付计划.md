# 客服 Agent · 全栈交付计划

> **用途：** 说明产品、设计、前端、后端、AI、数据、QA、安全和运维如何形成一个可交付闭环
> **生效条件：** G0 阶段用于设计；产品功能开发仅在 Ddev 成立后开始
> **技术状态：** 技术栈尚未冻结；以复用审计和架构 ADR 为准
> **Owner：** 项目负责人 / FDE
> **版本：** v1.0 · 2026-07-31

---

## 1. 产品闭环

```text
话术 Owner 起草
      ↓
业务复核与发布
      ↓
客服 Agent 检索 / 推荐 Top3
      ↓
坐席查看引用与版本
      ↓
坐席确认并人工发送
      ↓
采纳 / 无用 / 未命中反馈
      ↓
质量、内容和检索迭代
```

系统没有自动发送路径。无可靠依据、权限不足、内容失效或场景歧义时，必须拒答或转人工。

## 2. 逻辑架构

| 层 | 责任 | 首期必须有 |
|----|------|------------|
| 坐席工作台 | 搜索、候选、引用、版本、反馈、拒答 | 关键词 / 意图输入、Top3、人工确认 |
| 内容管理端 | 起草、复核、发布、下架、回滚 | 最小状态机与审计 |
| 应用 API | 内容、搜索、反馈、权限、审计 | 版本化契约、输入校验、错误码 |
| 检索 / AI | 关键词基线、混合检索、排序、拒答 | 基线可对比、成本可计量、可降级 |
| 数据层 | 话术、版本、状态、来源、反馈、事件 | 稳定 ID、数据字典、迁移与快照 |
| 身份与安全 | 登录、RBAC、PII、出域、日志 | 最小权限、禁止字段、审计留痕 |
| 运行平台 | 环境、发布、监控、备份、恢复 | 告警、回退、RPO / RTO、值班责任 |

`web-decision-brief` 不默认成为任何一层的实现。可复用内容必须经过 ADR 记录，而不是因为“页面已经存在”直接续做。

## 5. 技术决策顺序

G0 必须按顺序回答：

1. 现有能力能否复用，谁维护；
2. 话术逻辑真源与状态机是什么；
3. 用户身份、角色和访问环境是什么；
4. 客户原文是否进入模型、是否出域；
5. 关键词基线能否满足首期；
6. 需要何种检索 / 模型增益；
7. API、数据、日志和审计如何追溯；
8. 如何监控、备份、恢复和回退；
9. 如何评测、灰度、止损和移交。

技术栈必须在问题和约束之后确定，不先选框架再找场景。

## 6. 开发与发布流程

```text
需求 Ready
   ↓
设计 / API / 数据 / 测试共同评审
   ↓
小分支开发
   ↓
单元 + API + 契约 + E2E + 安全检查
   ↓
PR 评审
   ↓
测试环境
   ↓
业务 UAT
   ↓
Pilot 环境
   ↓
门禁签发后发布
```

### 环境

| 环境 | 数据 | 用途 | 发布条件 |
|------|------|------|----------|
| local | 生成或脱敏样本 | 开发与单元测试 | 不接真实客户数据 |
| test | 冻结脱敏数据 | 集成、契约、E2E、安全测试 | 自动门禁通过 |
| pilot | 批准的最小真实数据 | 内部试点 | Pilot Ready 签发 |
| production | 首期默认不建立 | 未来扩面 | 另立发布门禁 |

### 分支与变更

- 主分支保持可部署；
- 每项工作有需求 ID、验收条件和风险等级；
- 数据 Schema 与 API 变更必须版本化；
- 高风险变更必须带回退方案；
- 不在 PR、日志或测试快照中写入敏感原文；
- 生成物不手改，由构建或发布流程产生。

## 7. 测试门禁

| 测试层 | 覆盖 |
|--------|------|
| 单元 | 状态机、权限、过滤、排序、拒答、费用计算 |
| API / 契约 | Schema、错误码、版本兼容、权限和审计 |
| 数据 | 必填字段、重复、过期、来源、版本和敏感字段 |
| 离线评测 | 正例、负例、关键词基线、Top3、引用和拒答 |
| E2E | 起草 → 复核 → 发布 → 检索 → 反馈 → 回滚 |
| 安全 | 越权、PII、Prompt 注入、依赖、Secrets、日志泄露 |
| 性能 | 搜索响应、并发、数据量和降级 |
| 可访问性 | 键盘、焦点、语义、对比度和屏幕阅读 |
| 运行 | 监控、告警、备份、恢复、回退和事故演练 |

G1a 使用冻结数据全量运行，不删难题、不只报成功案例。

## 8. Definition of Ready

一项开发任务进入 Sprint 前必须有：

- 用户与问题；
- In / Out；
- 验收条件；
- 设计或交互状态；
- API / 数据影响；
- 安全与隐私影响；
- 测试方案；
- 依赖、Owner 和回退；
- 费用与运行影响。

缺任一关键项，任务保持 Not Ready。

## 9. Definition of Done

一项功能完成必须满足：

- 代码与文档已评审；
- 自动测试通过；
- 权限、审计、错误和空态完整；
- 埋点与监控可观测；
- 无未处置 Critical / High；
- 业务验收证据已归档；
- 回退步骤可执行；
- 对应章程、台账、Scope 或运行手册已同步。

“页面能点”或“模型能回答几个问题”不等于 Done。

---

## 10. Web 设计资产复用

已收尾汇报 Web 可以提供：

- 品牌素材与视觉规范参考；
- 信息层级和投屏经验；
- 响应式、可访问性和四视口测试方法；
- 内容 SSOT、发布校验和离线降级经验。

不能直接继承：

- 历史业务文案和会议状态；
- 客服 + 供应链组合预算；
- localStorage 决策草稿；
- 汇报页信息架构；
- “静态页面可运行”等同生产系统可运行的判断。

任何复用必须写入架构 ADR，并说明复用范围、成本和退出方案。
