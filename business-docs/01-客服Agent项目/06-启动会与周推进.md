> **维护人：** 项目负责人

## 2. 启动会操作步骤

1. 打开 [`00-项目章程.md`](00-项目章程.md)，复述项目目标与首期边界。
2. 打开 [`02-G0责任与证据台账.md`](02-G0责任与证据台账.md)，逐项具名唯一 A 和 R。
3. 确认 8 月 4 日是 D0，Ddev 仍为空。
4. 确认 A / B / C 费用路径的负责人和 8 月 5 日截止。
5. 确认话术真源、数据、安全、复用和评测提供人。
6. 确认 8 月 7 日中检、8 月 14 日 G0 决策会。
7. 会后 2 小时内发纪要，行动项必须带 Owner、日期和完成证据。

### 会议结束判定

启动会只有在以下内容齐全时才算完成：

- 项目名和 MVP-A 边界无歧义；
- 核心事项只有一个 A；
- G0 每项有证据要求和截止日；
- 风险、依赖和升级路径已登记；
- 所有人理解 D0 ≠ Ddev；
- 会议纪要有外部可访问链接。

## 3. 日常节奏

### G0 期间

| 节奏 | 时长 | 内容 | 产出 |
|------|------|------|------|
| 每日异步更新 | 5 分钟 | 昨日完成、今日目标、阻塞、证据链接 | 台账状态更新 |
| 阻塞同步 | 15 分钟，按需 | 只处理影响 G0 的红 / 黄项 | Owner、行动、日期 |
| 08-07 中检 | 30 分钟 | 检查事实、Owner、费用、复用和安全缺口 | 中检结论 |
| 08-14 G0 决策 | 60 分钟 | 逐项验真、签发 Pass / Fail | Ddev 或阻塞清单 |

### Ddev 后

| 节奏 | 内容 |
|------|------|
| 周一计划 | 本周目标、Ready 工作、风险和依赖 |
| 每日站会 | 只讲交付、阻塞和风险，不重述背景 |
| 周中设计 / 技术评审 | 设计、API、数据、安全、测试共同评审 |
| 周五 Demo + 质量复盘 | 展示端到端结果、测试、指标和未完成项 |
| 门禁评审 | 只依据冻结证据，不依据演示印象 |

## 4. 每周更新顺序

每次状态变化按以下顺序更新：

1. G0 台账：Owner、动作、证据、风险、决定；
2. Scope 与验收：指标、数据集、阈值或验收结果；
3. 项目章程：范围、目标、里程碑；
4. 总排期：日期、资源和顺延；
5. 项目驾驶舱：组合状态、健康度和下一门禁；
6. 周报：只摘录以上真源。

不要先改周报，再回头猜真源应该写什么。

## 6. 升级规则

| 情况 | 处理 |
|------|------|
| 关键 Owner 逾期 | 当日升级项目负责人和金主 |
| 正式凭证、费用或安全 Fail | G0 直接 Fail，不用其他完成项抵扣 |
| Scope 影响关键路径 | 提 CR，重新评估日期、费用和评测 |
| Critical / High 安全问题 | 停止发布或试点，先处置和复测 |
| 评测集或阈值临场变化 | 拒绝验收，重新冻结并整集重测 |
| 供应链事项进入客服资源 | 移回供应链项目并记录组合决定 |
| 汇报 Web 被当作当前系统 | 指回项目章程并纠正会议纪要 |
