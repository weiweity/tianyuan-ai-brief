# 客服 Agent 一期 · 技术方案设计

> **状态：** DRAFT
> **原则：** 先定边界和验证方法，再选技术栈；Ddev 前只允许小实验和接口草案

## 逻辑边界

```text
坐席端
  → 权限与会话层
  → 查询编排层
  → 关键词 / 语义检索与适用范围过滤
  → 证据、版本、有效期与冲突检查
  → 候选答案 / 澄清 / 升级
  → 反馈、审计与指标事件
```

## 必须产出的设计记录

| ID | 决策 | 必须比较 |
|----|------|----------|
| ADR-01 | 应用形态与访问方式 | 现有入口、独立 Web、嵌入工作台的限制 |
| ADR-02 | 数据存储与版本方式 | 权威源保留、快照、索引与审计的职责分离 |
| ADR-03 | 检索基线 | 关键词 / 规则、语义检索、混合检索的真实样本结果 |
| ADR-04 | 模型与降级 | 是否需要模型，费用、数据边界、超时和失败时如何回退 |
| ADR-05 | 身份与权限 | 坐席、内容维护、审核、管理员的最小权限 |
| ADR-06 | 运行与恢复 | 日志、监控、备份、回滚、RPO / RTO 和事故处理 |

## 非功能设计输入

- 人数：一期 3–5 名内部坐席；全量人数与峰值并发待客服确认；
- 安全：默认最小权限，原始客户数据、密钥和安全细节不进公开仓；
- 稳定性：查询失败不能阻断客服原流程，灰度必须有快速关闭开关；
- 可观测：请求、结果、采用 / 修改 / 拒绝、错误、延迟和费用均能按脱敏 ID 追溯；
- 无障碍与兼容：键盘全流程可用，并覆盖客服实际设备和浏览器。
