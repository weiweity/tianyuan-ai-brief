## 1. 背景与目标

### 1.1 背景

客服在千牛 / 抖音接待时，找话术路径长：快捷语 → 飞书产品在线表 → 群问话术师。话术分散、更新慢。业务侧还需要对班牛等系统导出的工单文件做质量与结构分析。一期同时建立 **话术推荐闭环** 与 **只读工单分析闭环**，为二期回复语料、三期自动回复打底。

### 1.2 三期与一期任务边界

| 阶段 | RAG 素材本质 | 任务重心 | 话术正文 |
|------|---------------|----------|----------|
| **一期** | **标准检索库 + 可审计训练合同预埋** | 话术师治理问法 / 答案；自动事实→人工复核候选；线上 bigram、embedding 离线影子 | **不改字，只选库；不真实训练** |
| **二期** | 经 DLP 与业务 + 数据安全双审晋级的语义资产 | 双周版本批训检索 / 意图 / 重排，人工发布 | **仍不训练生成回复；改字另审** |
| **三期** | 复用已验证语义、评测与删除血缘底座 | 客服 Agent / 生成能力另立项 | **自主程度、场景改写与发送权限重审** |

### 1.3 一期产品目标

建设 **Electron 壳 + 中心 API + PostgreSQL SoR**，双表面：

1. **浮窗（一线）** — TopK 库内原文、人在环、**主路径复制剪贴板**（自动填实验）\
2. **Dashboard** — 概览、检索/复制自动事实流水、离线三维抽样复核、**工单分析**、**话术优化待办**、导入发布与公告；**话术正文零写**（飞书/Excel 经 Publish）\
3. **内容管线** — Import→Publish(release)→Announce→全客户端更新\
4. 检索：一期按 `39 §2.1` 走**中文字符 bigram + normalize + exact/ILIKE 回退**；本地开源 embedding 只做离线影子，DeepSeek 只作可替换推理 / 教师候选（禁改写）\

**内容重心：** 产品+活动。**CR-002/003：** 记录产品内“脱敏问法 → 绑定发布版本的候选 → 成功复制 / 无命中 / 放弃 / 升级”，它不是聊天记录，不证明平台实际发送或回答正确；一期取消旧在线结果回填，修改 / 发送 / 适用性只按离线三维样本复核。训练仅预埋 schema、空模板和纯合成 fixture。**业务工单分析：** 依据 CR-001 进入一期设计范围，书面 EVD 与 G0 签发仍待补；仅接收批准的导出文件，不写回班牛。**Demo：** 仅业务确认附页。

### 1.4 成功怎么看（分栏 · 阈值后补）

| 栏 | 指标 | 数据来源 |
|----|------|----------|
| **工具事实账** | **复制率 = adopted(兼容机器名)/hit**；无命中 / 放弃 / 升级 / 重选率；Top1 复制占比；P95 | 端内 / Dashboard |
| **离线复核账** | 抽样修改分布、发送确认、话术适用性；同时报告样本量、覆盖层、不可核验与证据等级 | 授权三维抽样 EVD |
| **经营侧** | 响应时间 / 满意度 / 转化率 | **平台后台 only** |

**立即停用：** 错活动/错价直推、泄密、严重质检事故等。

### 3.3 人在环与改字策略

- 必须 **点击或按 `1`/`2`/`3`** 后才推送内容\
- 禁止系统自动连发客户消息\
- **准优先**，条数不超过 3\
- **一期不改字：** DeepSeek / RAG 链路 **不得改写** 库内 Answer 正文；只做理解、检索、排序、过滤；输出必须是库内已发布原文\
- 坐席若在接待软件里手动改字，属人的行为；系统默认推送的是 **原文**\
- 二期起才开放「系统侧改字」；三期自动化场景下可按客户脾气与场景改字（均另规）

### 4.2 Q-A 结构

| 字段 | 一期 | 后续 |
|------|------|------|
| **Answer** | 标准话术模板（主资产）；API 返回发布模板原字节 | 持续修订 |
| **Question** | **初期人工编写**且已脱敏的典型问法；稳定随机 ID、独立版本与 hash；不内嵌 Answer 正文 | 只有获批晋级问法可扩充，并保留来源与删除血缘 |
| 元数据 | 显式平台/商品范围、生效期、意图 taxonomy、风险、占位符、版本、维护与审核人 | 冲突裁决与显式迁移 |

```text
客户原话
  → bigram 检索（Question 语义资产 + Answer 发布绑定 + 元数据过滤）
  → 可选 DeepSeek ranker：仅理解问法 / 辅助排序 / 拒答判断（默认关；**一期禁止改写 Answer 正文**）
  → Top3 = 库内已发布 Answer **模板原文**
  → 若有受控占位符，在客户端内存确定性填值并二次确认后复制
  → 自动事实只追加「根问题 / 操作 + 绑定模板版本的候选」
  → 三维抽样复核形成候选 → 业务 + 数据安全双审后才可晋级
```

**内容资产治理（DEC-042）：**

- `platform_scope` 必填且非空，只能包含 `qianniu / douyin`；两者全含表示 both，禁止用 `NULL / []` 偷换成全平台；
- 商品范围必须显式选择 `product_scope_type=storewide|category|sku` 并提供 `product_scope_refs`；`storewide` 的 refs 必须为 `[]`，`category/sku` 必须非空；
- `effective_from`、`review_due_at` 必填，`effective_to` 可空；普通内容建议 90 天复核、高风险建议 30 天复核，均待内容政策批准，不冒充已授权默认值；
- Question 使用上游给定的稳定随机 `question_id`，不得按文件行序生成；同时保存 `question_version>=1`、`question_hash`、`semantic_family_id`、HMAC `origin_fingerprint`、`source_asset_id`，来源统一为 `manual|from_log|import`；
- 每条内容必须绑定版本化 `intent_taxonomy_version + intent_id`；未知意图隔离待审，旧 ID 不删除，变更通过显式迁移映射；
- `risk_level=low|medium|high`；普通内容由 Content Lead 单审，高风险或冲突内容由 Content Lead + `ROLE-CS-MANAGER` 双审，未决冲突隔离；
- 一期只允许 `{订单号}`、`{日期}`，机器键分别为 `order_id/date`。API 返回模板原字节；占位符值只在客户端内存中确定性渲染，缺必填值禁止复制并要求二次确认；值和渲染正文零落库、零日志，事件仍只绑定模板四元组；
- `content_hash = SHA-256(JCS(规范化治理快照))`。Answer、Question 映射、范围、风险、有效期、意图或占位符任一变化，都必须递增 `script_version` 并产生新 hash。

**改字分阶段（DEC-026）：**

| 阶段 | 系统是否改 Answer 正文 | 说明 |
|------|------------------------|------|
| 一期 | **否** | 只选话术，口径完全跟库 |
| 二期 | **默认否；另行 CR 后才可受控** | CR-003 二期训练只覆盖检索 / 意图 / 重排，不含生成回复 |
| 三期 | **是（场景化）** | 贴合客户脾气与场景，服务自动回复 |

### 4.3 一期 vs 二期数据任务

| | 一期 | 二期 |
|--|------|------|
| 主资产 | **发布话术 + 独立问法语义资产 + 训练合同** | 获批的检索 / 意图 / 重排数据集版本 |
| 人 | 话术师写 Q、改 A；系统记自动事实；双审候选 | 数据 / 业务按双周批次复核、训练，人工发布 |
| 目的 | 检索准、事实可审、正确性可抽验；为后续保留血缘 | 提升检索 / 意图 / 重排，不训练生成回复 |

## 5. 核心用例

### UC-01 飞书登录

打开 App/浮窗 → 飞书授权 → 就绪。

### UC-02 粘贴原话 → Top3 → 推送（主路径）

1. 坐席 **粘贴客户原话** 到浮窗（08-12）或桌宠输入\
2. 中文 bigram/FTS 主路径出 **Top3** 话术（编号 1–3）；DeepSeek 仅为默认关闭的可选重排\
3. 可展开简要理由（可选）\
4. **鼠标点选** 或 键 **`1`/`2`/`3`**\
5. **主路径：复制到剪贴板**并提示坐席粘贴发送；模板含受控占位符时，客户端只在内存中收集必填值、确定性渲染并二次确认，缺值禁止复制；自动填=实验适配器（失败不影响验收）\
6. 系统自动记录：按批准规则脱敏后的搜索问法、当时 Top3 与不可拆分的模板 `release_id + script_id + script_version + content_hash`、成功复制的 rank、无命中、显式放弃或升级；占位符值和渲染正文不落库、不进日志；现行机器合同继续使用 `adoption_events` / `push_method`，人读统一称“复制”\
7. 搜索问法与复制话术的配对不是完整聊天记录，系统不读取接待平台最终文本，也不自动判断是否发送或答对\
8. 第一次搜索写 `attempt_kind=original`；同一问题的再次选择生成新 `query_id`，写 `parent_query_id=<首个 query_id>` 与 `attempt_kind=reselection`；根问题账只计一次，操作账逐次追加。

### UC-02B 自动事实与离线三维复核

1. 一期浮窗不出现强制结果回填门，也不因上一笔复制阻断下次唤起；
2. 自动事实包括查询、真实候选、成功复制、无命中、显式放弃、升级与重选；事件确认 timeout 为版本化配置，超时只记未知 / 待重试，不推断未发送或失败；
3. Dashboard 按“坐席层（新/老）×业务场景（平台/意图/活动/风险）×事实结果（复制/无命中/放弃/升级/重选）”生成离线样本：高风险和非正常结果全审，成功复制至少抽 20%，两周不足 30 个根问题时全审；
4. 复核分别判断是否修改、是否发送、话术是否适用；不采最终发送正文时无法证明的字段必须记 `unverifiable`，三项分账；
5. 复核结论只产生语义资产候选，行为信号不能直接当正确标签；晋级须二次 DLP、业务 + 数据安全双审、用途锁定与删除血缘；
6. telemetry 故障时允许显著标记的 `collection_disabled/stateless` 安全搜索，但该会话不进入指标、语料候选或 G1b 分母；DLP、Auth 或内容快照不就绪仍阻断。

### UC-03 话术师维护库

1. 按四类维护 Answer 模板，并显式填写平台/商品范围、生效期、意图、风险与占位符声明\
2. 初期维护/补充已脱敏 Question；稳定随机 ID 与版本不得由行序派生\
3. 普通内容由 Content Lead 单审；高风险或冲突由 Content Lead + `ROLE-CS-MANAGER` 双审，未决冲突隔离\
4. 结构、安全或来源错误整批失败；质量问题只隔离问题行，clean 行按 DEC-042 抽检通过后方可发布；下架即不可推\

### UC-04 一期业务工单分析

1. coach / owner 在 Dashboard 选择批准的班牛或业务工单 CSV/XLSX；
2. 系统先做文件格式、列名、类型、必填项、重复行和敏感字段校验；
3. 用户确认字段映射后创建导入批次，只保存允许字段的标准化结果，不保存未审批原始载荷；
4. Dashboard 提供聚合指标、筛选、排序与明细下钻，并显示数据批次、口径和刷新时间；
5. 用户按权限导出脱敏分析结果；系统记录导入、查询和导出审计；
6. 一期 **不调用班牛写接口、不自动建单 / 填单 / 回写**，也不把原始工单默认发送给第三方模型。

### UC-05 无结果

低置信：不凑满 3 条；明确「暂无可靠推荐」+ 升级路径；写入 `no_hit` 日志供迭代。

### UC-06（二期）自动识别会话与商品

减少粘贴；仍须按键/点击后推送。

一期人读“已确认平台”映射到 wire/DDL canonical `platform`，Phase 1 必须经坐席确认：直接手选/修正写 `platform_source=manual`；接受热键瞬时 `detected_platform` 提示可写 `platform_source=foreground_process`，但提示本身不是自动真源。不轮询、不读窗口标题；未来深度平台接入统一为 `native_integration`，另走 ADR、数据与平台授权。

### UC-07 话术优化待办（话术师）

1. 系统按规则扫描搜索 / 复制兼容日志（无命中聚集、常复制 Top2 而不复制 Top1 等）\
2. 生成 **话术优化待办**，区分疑似 **库缺口** vs **排序/算法**\
3. 提醒话术师（飞书或 App）\
4. 话术师补 Question / 改 Answer / 转工程查算法；**系统不自动改库**\
5. 发布后索引更新，待办关闭\

详见 [`26-话术库与自动事实数据模型.md`](26-话术库与自动事实数据模型.md) §4。

## 9. 验收与 Demo（08-12）

> **2026-08-05 核对（业务确认）：** 四类话术（售前/活动/售后/产品）**均已有、一线在用**；现表**无**生效/失效字段。08-12 **只演示**，导入**部分**话术即可。观众=业务。Ddev 前仍只做原型/演示，不写生产功能。

6. **工单分析原型：** 仅用批准的脱敏样本或合成文件演示“导入预检 → 聚合 → 下钻 → 导出”；不要求 08-12 连接班牛\
7. **飞书登录** 可 Mock，须页面和口头双重标注；试点前必须换真实 OAuth\

### 9.2 演示不做 / 降级

| 项 | 08-12 处理 |
|----|------------|
| 全量灌库 | 不做；部分样本即可 |

### 9.3 Demo 脚本（建议 5 分钟）

1. 打开浮窗 → 贴 1～2 句真实口吻问法 → 出 Top3\

### 9.4 一期验收集（不是 08-12 Demo 通过数）

冻结验收集至少 **50 条且与开发 / 调参集不重叠**：20 条正常正例、至少 12 条安全负例（六类 × 2）和至少 18 条长尾 / 错别字 / 改写 / 上下文鲁棒性样本。正常正例 Top3 分母固定为 20，安全负例必须全部通过；工单分析另按字段白名单、映射、聚合口径、越权、脱敏导出与审计验收，不得混入话术 Top3 总分。
