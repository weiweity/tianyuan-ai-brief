## 1. 背景与目标

### 1.1 背景

客服在千牛 / 抖音接待时，找话术路径长：快捷语 → 飞书产品在线表 → 群问话术师。话术分散、更新慢。工单侧另有导出分析需求。一期核心是 **把话术库训起来、用起来**，为二期回复语料、三期自动回复打底。

### 1.2 三期与一期任务边界

| 阶段 | RAG 素材本质 | 任务重心 | 话术正文 |
|------|---------------|----------|----------|
| **一期** | **最标准 RAG 素材库**：只命中 **固定话术** | 话术师优化话术/问法；采纳日志→迭代提醒 | **不改字，只选库** |
| **二期** | **清洗聊天记录** → 一线数据资产 RAG 库 | 扩库 + 开始训回复资产 | **开始允许改字** |
| **三期** | 在以上库上 **自动训练/迭代** | 自动回复（另立项） | **按脾气/场景改字** |

### 1.3 一期产品目标

建设 **Electron 桌面安装包**，**飞书登录**，提供：

1. **话术库**（话术师迭代；四类：售前 / 活动 / 售后 / 产品）  
2. **RAG + DeepSeek API** 驱动的话术推荐（人在环，Top3）  
3. **导出工单分析**  
4. 一线主交互：**浮窗（08-12 可先）→ 桌宠（目标形态）**；粘贴原话 → Top3 → 点/键推送  

### 1.4 成功怎么看（名称已定，阈值待基线）

| 指标 | 数据来源 |
|------|----------|
| 响应时间 / 满意度 / 转化率 | 平台后台 |
| 话术命中率 / 采纳率（含键位 1–3） | 端内埋点优先 |

**立即停用：** 错活动/错价直推、泄密、严重质检事故等。

## 3. 产品范围

### 3.1 In Scope（一期）

| 模块 | 说明 |
|------|------|
| M1 安装与账号 | Electron 安装包；飞书登录 |
| M2 话术库 | 四类话术；Q-A；话术师迭代；版本/发布/下架 |
| M3 智能推荐 | **RAG + DeepSeek API**；Top**3**；浮窗/桌宠 |
| M4 反馈闭环 | 采纳日志；**迭代提醒话术师**（无命中/常跳过 Top1 等） |
| M4b 数据模型 | 见 [`26-话术库与采纳日志数据模型.md`](26-话术库与采纳日志数据模型.md) |
| M5 导出工单分析 | 导出后分析，不写回班牛自动填 |
| M6 推送 | **优先自动填入接待输入框**；失败则 **剪贴板** |

### 3.2 Out of Scope（一期）

- 无人值守自动代发客户消息  
- 班牛字段自动填写写回  
- 二期级「自动读当前会话/商品」（可做接口预留）  
- 完整自动回复 Agent  

### 3.3 人在环与改字策略

- 必须 **点击或按 `1`/`2`/`3`** 后才推送内容  
- 禁止系统自动连发客户消息  
- **准优先**，条数不超过 3  
- **一期不改字：** DeepSeek / RAG 链路 **不得改写** 库内 Answer 正文；只做理解、检索、排序、过滤；输出必须是库内已发布原文  
- 坐席若在接待软件里手动改字，属人的行为；系统默认推送的是 **原文**  
- 二期起才开放「系统侧改字」；三期自动化场景下可按客户脾气与场景改字（均另规）

## 4. 话术库模型（一期核心）

### 4.1 分类（Answer 域）

| 类型 | 说明 |
|------|------|
| 售前话术 | |
| 活动话术 | |
| 售后话术 | |
| 产品话术 | |

### 4.2 Q-A 结构

| 字段 | 一期 | 后续 |
|------|------|------|
| **Answer** | 标准话术正文（主资产） | 持续修订 |
| **Question** | **初期人工编写** 典型问法 | 由一线真实调用问法扩充 |
| 元数据 | 类型、平台、有效期、版本、维护人 | 冲突裁决 |

```text
客户原话
  → RAG 检索（Question / Answer + 元数据过滤）
  → DeepSeek API：理解问法 / 辅助排序 / 拒答判断（**一期禁止改写 Answer 正文**）
  → Top3 = 库内已发布 Answer **原文**
  → 坐席选用 → 回写「问法 + 选用话术 ID」
  → 话术师审核后迭代库
```

**改字分阶段（DEC-026）：**

| 阶段 | 系统是否改 Answer 正文 | 说明 |
|------|------------------------|------|
| 一期 | **否** | 只选话术，口径完全跟库 |
| 二期 | **是（受控）** | 开始允许改字；范围/审核另定 |
| 三期 | **是（场景化）** | 贴合客户脾气与场景，服务自动回复 |

### 4.3 一期 vs 二期数据任务

| | 一期 | 二期 |
|--|------|------|
| 主资产 | **话术库（Q-A）** | 开始建 **回复语料库** |
| 人 | 话术师写 Q、改 A；一线用 | 一线调用日志规模化 |
| 目的 | 检索准、采纳高 | 为三期自动回复铺数据 |

## 5. 核心用例

### UC-01 飞书登录

打开 App/浮窗 → 飞书授权 → 就绪。

### UC-02 粘贴原话 → Top3 → 推送（主路径）

1. 坐席 **粘贴客户原话** 到浮窗（08-12）或桌宠输入  
2. RAG + DeepSeek 出 **Top3** 话术（编号 1–3）  
3. 可展开简要理由（可选）  
4. **鼠标点选** 或 键 **`1`/`2`/`3`**  
5. **优先尝试自动填入** 千牛/抖音输入框；失败则 **复制剪贴板** 并提示  
6. 坐席在接待软件发送；系统记：原问、选用 ID、是否手动改（若可采集）  

### UC-03 话术师维护库

1. 按四类维护 Answer  
2. 初期维护/补充 Question  
3. 发布后进入 RAG 索引；下架即不可推  

### UC-04 导出工单分析

导入导出文件 → 分析 → 导出结果；不写回班牛。

### UC-05 无结果

低置信：不凑满 3 条；明确「暂无可靠推荐」+ 升级路径；写入 `no_hit` 日志供迭代。

### UC-06（二期）自动识别会话与商品

减少粘贴；仍须按键/点击后推送。

### UC-07 话术迭代提醒（话术师）

1. 系统按规则扫描采纳日志（无命中聚集、常选 Top2 不选 Top1 等）  
2. 生成 **迭代工单**，区分疑似 **库缺口** vs **排序/算法**  
3. 提醒话术师（飞书或 App）  
4. 话术师补 Question / 改 Answer / 转工程查算法；**系统不自动改库**  
5. 发布后索引更新，工单关闭  

详见 [`26-话术库与采纳日志数据模型.md`](26-话术库与采纳日志数据模型.md) §4。

## 6. 信息架构

```text
Electron
 ├─ 浮窗（08-12 MVP 必达）
 │    输入：粘贴原话
 │    输出：Top1–3 + 键 1/2/3
 │    推送：自动填写 → 失败剪贴板
 ├─ 桌宠（目标形态，与浮窗并存；C 方案）
 ├─ 话术库管理台（话术师）
 ├─ 工单分析
 └─ 设置（快捷键、推送方式、置顶）
```

## 8. 软件架构（路线 A · DEC-029）

```text
Electron 客户端（浮窗/桌宠）
    │ 飞书 token
    ▼
自研后端（一体或分服务）
    ├─ 账号权限（飞书）
    ├─ 话术库 CRUD + 索引更新
    ├─ 自研 RAG：embedding + 向量检索 + 过滤
    ├─ DeepSeek 适配（理解/排序/拒答；**禁改写 Answer**）
    ├─ 采纳日志 + 迭代规则
    └─ 工单分析
    ▼
业务 DB + 向量存储（可用开源组件，非套件中台）
```

**ADR 待补：** 语言栈、向量库选型、切块、DeepSeek 职责边界、费用 B 密钥与 cap、自动填写方案。  
**明确不做（一期）：** 部署 Dify/RAGFlow/MaxKB 作为主检索中台。
