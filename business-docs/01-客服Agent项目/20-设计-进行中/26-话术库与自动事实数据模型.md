## 2. 话术库字段表

### 2.1 四域来源版本与 release 绑定（CR-004 静态合同）

一期固定四个内容域：`presale` 售前、`campaign` 活动、`aftersale` 售后、`product` 产品。每个来源版本一经登记即不可改；每个 `content_release` 必须恰好绑定四条不可变来源版本，且每域一条、不可缺失、不可重复。

| 人读实体 | 最小字段 | 冻结语义 |
|----------|----------|----------|
| `authoritative_source_versions` | `source_version_id`、`source_ref`、`domain`、`upstream_version`、`snapshot_sha256`、`use_class=canonical|reference`、`approval_evd`、`approved_by/at`、`review_due_at` | 一个已核验来源的不可变版本；`reference` 仅供引用，不能进入发布/检索；禁止 UPDATE / 覆盖旧版本 |
| `release_source_bindings` | `release_id`、`domain`、`source_version_id`、`created_at` | release 的四域绑定；`UNIQUE(release_id,domain)`，随 release 永久冻结 |
| `authoritative_source_suspensions` | `suspension_id`、`source_version_id`、`reason_code`、`evidence_ref`、`suspended_by/role/at` | 只追加暂停事实；一经暂停永久生效，禁止删除、覆盖、恢复或在来源版本上维护可变布尔值 |

**唯一推导：** `content_current` 指向哪个 release，该 release 绑定的四个 `use_class=canonical` 来源版本才构成运行时 `canonical + current` 来源集合；`reference` 来源不得绑定可用 release。不得另建可变 `current/canonical` 标记，也不得把来源暂停混写为 `content_releases.status=superseded` 或 `scripts.status`。

**全链硬门：** import、publish、rollback、search 任一步发现四域绑定缺失/重复、来源未登记、`use_class=reference`、版本/域/hash/EVD 不匹配或已有暂停记录，都必须整步 fail-closed。被暂停的 `source_version` 永久不得再次 import / publish / rollback / search；恢复业务只能登记一个新的不可变来源版本，并与一次新 release 发布在同一原子事务完成。禁止先改“当前来源”再发布。rollback 必须重新校验目标 release 的四域绑定与暂停记录，任一不合格则整次拒绝，禁止过滤目标快照后伪称回滚成功。

**离线读取硬门：** 客户端只可在服务端签发、绑定 `client_id/user_id/release_id/source_binding_hash` 的短租约有效期内使用完整 current snapshot；静态合同冻结默认 600 秒、允许 60～900 秒，服务端只存 opaque bearer token 的 SHA-256。租约到期立即停止本地 FTS/search。ACK 只确认同步游标，不续租；重新联网核验并取得新租约前，无宽限期或旧 snapshot fallback。

**拒绝审计硬门：** 来源治理或离线租约拒绝的业务事务先回滚，再以独立、幂等短事务/审计端口追加最小记录；不得在随后 `RAISE` 会回滚的同一事务内先写审计。底层 `record_source_denial_audit` 仅作内部存储 writer，不授予应用角色；import/search/current/snapshot 仅调用 `record_runtime_source_denial_audit`，publish/rollback/source suspend 仅调用 `record_admin_source_denial_audit`，禁止 workload 跨界伪造 operation。只允许 `denial_key/operation/reason_code/actor_subject_hash/hash_key_version/actor_role/release_id/source_version_id/source_binding_hash/diagnostic_id/committed_at`；其中 `source_version_id` 是安全 `srcv_*` 标识，禁止 `source_ref`、正文、raw query、上传原文、内部路径或 token。审计无法持久化时管理写动作继续 fail-closed。

### 2.2 话术条目 `script`（Answer 主实体）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `script_id` | 稳定 ID | 是 | 业务主键，日志外键 |
| `category` | 枚举 | 是 | `presale` 售前 / `campaign` 活动 / `aftersale` 售后 / `product` 产品 |
| `title` | 短文本 | 是 | 列表用标题 |
| `answer_text` | 长文本 | 是 | **标准话术模板；API 返回必须原字节** |
| `status` | 枚举 | 是 | `draft` / `in_review` / `published` / `archived` |
| `version` / `script_version` | 整数 | 是 | `>=1`；治理快照任一字段变化即递增 |
| `content_hash` | SHA-256 | 是 | `SHA-256(JCS(规范化治理快照))`，不是只算正文；一期数据库实现只接受合同固定的 ASCII 对象键并以 `C` 排序，不是任意 Unicode 键的通用 JCS 序列化器 |
| `platform_scope` | 非空数组 | 是 | 仅 `qianniu / douyin`；两者全含表示 both；禁止 `NULL / []` 作为全平台 |
| `product_scope_type` | 枚举 | 是 | `storewide / category / sku` |
| `product_scope_refs` | 数组 | 是 | `storewide` 必须 `[]`；`category / sku` 必须非空；不再以空 `sku_scope` 表示全部 |
| `campaign_tag` | 文本 | 否 | 活动标识 |
| `effective_from` | 时间 | 是 | 生效时间；禁止空值放行 |
| `effective_to` | 时间 / 空 | 否 | 空=无预定失效；非空时过期不得进 Top3 |
| `intent_taxonomy_version` / `intent_id` | 版本 / ID | 是 | 必须命中已批准 taxonomy；未知意图隔离待审 |
| `risk_level` | 枚举 | 是 | `low / medium / high` |
| `risk_categories` | 数组 | 是 | `high` 必须非空且只含七类受控高风险枚举；`low / medium` 必须为 `[]`，不能靠空/乱填类别绕过或误触发双审 |
| `has_conflict` | 布尔 | 是 | 同一显式范围是否存在内容冲突；为 true 时强制双审并在未决前隔离 |
| `placeholder_keys` | 数组 | 是 | 仅 `order_id / date`；无占位符时 `[]` |
| `priority` | 数 | 否 | 冲突时参考 |
| `owner_role` | 角色代号 | 是 | 维护责任 |
| `review_mode` | 枚举 | 是 | `single / dual`；`low/medium + 无冲突` 才可 single，`high` 或冲突必须 dual |
| `primary_reviewer_id` / `primary_reviewer_role` / `primary_review_evd` | 受控主体 / 固定角色 / EVD | 是 | 只能由受限审核事实解析；角色固定为 `ROLE-CONTENT-LEAD`，主体是版本化伪名标识，不是真实姓名 |
| `secondary_reviewer_id` / `secondary_reviewer_role` / `secondary_review_evd` | 受控主体 / 固定角色 / EVD / 空 | 条件 | dual 时三者必填，角色固定为 `ROLE-CS-MANAGER`，且主体必须不同于 primary；single 时三者全空 |
| `source_ref` | 文本 | 是 | 发布血缘投影；由服务端从受信 import 上下文与该 release 的 `release_source_bindings` 附加，导入文件行不得自报或覆盖；公开仓无内部 URL / 路径或原文 |
| `review_due_at` | 时间 | 是 | 下次内容复核时间；普通建议 90 天、高风险建议 30 天，均待内容政策批准；到期后复核、下架或隔离 |
| `created_at` / `updated_at` / `published_at` | 时间 | 是 | 审计 |
| `supersedes_script_id` | ID | 否 | 替代旧版 |

**审核信任边界：** 上传文件、普通 normalized row 与普通 import worker payload 不得携带或自报 `review_mode`、审核主体、审核角色、审核 EVD、审核结论或 `quality_gate_passed`。授权审核池只能经 `record_content_review_decision` 向受限 `content_review_decisions` 追加事实；finalizer 按 `script_id + content_hash` 解析固定 `ROLE-CONTENT-LEAD` / `ROLE-CS-MANAGER` 角色，并验证 dual 的两个伪名主体不同后，才把最小审核投影冻结进发布资产。坐席 public wire 只按 OpenAPI 封闭白名单暴露产品行为所需字段，不暴露审核主体 ID、审核 EVD、来源 query、origin HMAC/key version、晋级凭据或内部 locator。\
**规则：** 仅同时满足 `published`、`effective_from <= now < effective_to`（`effective_to` 空=+∞）、显式平台/商品范围、已批准 taxonomy、已完成对应风险审核、属于 `content_current` 的 release、命中该 release 的四域 `use_class=canonical` binding 且来源版本不存在永久暂停记录的条目可被推荐。在线路径只允许调用 SECURITY DEFINER 函数 `search_recommendable_scripts(platform, product_context_type, product_context_ref)`；`app_runtime` 对 `v_scripts_recommendable`、`release_items` 与 `content_current` 均无直接 SELECT。`platform_scope` 与商品范围不得用空值放宽；未知意图、未决冲突和质量隔离行均不可发布。**禁止**关闭或旁路任一过滤。\
**一期不变量：** API 返回的 Answer 模板 **字节级等于** SoR 发布模板（`policy.rewrite=OFF`）。客户端只可按 `placeholder_keys` 将 `{订单号}` / `{日期}` 分别映射为 `order_id` / `date`，在内存中确定性渲染；缺必填值禁止复制并要求二次确认。占位符值与渲染正文零落库、零日志，自动事实仍只绑定模板 `release_id + script_id + script_version + content_hash`。

### 2.3 问法 `script_question`（Question）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `question_id` | 稳定随机 ID | 是 | 由上游给定；禁止按文件行序、数组下标或正文 hash 派生 |
| `script_id` | FK | 是 | 挂到哪条 Answer |
| `question_version` | 整数 | 是 | `>=1`；正文、映射、意图或来源变化时递增，不覆盖旧版本 |
| `question_hash` | SHA-256 | 是 | 已脱敏 Question 规范化内容与映射的版本证据 |
| `semantic_family_id` | ID | 是 | 语义簇；用于去重、切分与 `train/G1a/G1b` 隔离 |
| `origin_fingerprint` | HMAC | 是 | 对获批来源身份做带版本 HMAC；不得保存可逆原始来源标识 |
| `origin_fingerprint_key_version` | 密钥版本 | 是 | 与 HMAC 指纹同存；用于换钥、重放与审计，禁止只存指纹不存版本 |
| `question_text` | 脱敏文本 | 是 | 典型问法；持久化、发布快照和日志前必须脱敏 |
| `source` | 枚举 | 是 | 仅 `manual / from_log / import`；运行日志不能直接写入 active |
| `source_asset_id` | ID | 是 | 非空稳定 ID：`manual` 指向受控人工录入资产，`from_log` 指向已批准脱敏语义来源资产与删除血缘，`import` 指向受信导入资产；不得填原始正文或可逆业务标识 |
| `intent_taxonomy_version` / `intent_id` | 版本 / ID | 是 | 与 Answer 映射的批准 taxonomy 一致 |
| `status` | 枚举 | 是 | `active` / `disabled` |
| `created_by_role` | 角色 | 否 | |
| `created_at` | 时间 | 是 | |

一条 Answer 可挂多条 Question，但两类资产版本与生命周期解耦：Question 负责“这类问题怎么说”，Answer 负责“当前批准回复是什么”。检索时通过发布绑定关联，不把 Answer 正文复制进问法资产；答案下架 / 回滚不删除可合法保留的语义簇，但旧绑定不得继续推荐。Question 的不可变版本键是 `(question_id, question_version)`；同一组合只能对应一份脱敏正文、hash、taxonomy、来源指纹及映射，禁止 UPDATE / DELETE 后复用。导入重排或在中间插入 Question 不得改变已有 `question_id`；相同 ID 的内容变化必须追加新 `question_version/question_hash`，不得原地冒充旧版。

**from_log 删除血缘：** `script_questions` 不直接把永久历史锁死在运行 `query_events` 上，而是绑定一个非 PII 的语义来源资产。该资产在 active 阶段保存受控 `source_query_id` 外键，并同时保存来源 HMAC、HMAC key version 与批准 EVD；源 query 要到期或收到删除请求时，先撤下所有可推荐绑定，再经受限、只可执行一次的 retire 流程写 tombstone / retirement EVD，保留不可逆 HMAC 血缘并释放对运行 query 的直接引用。retired 资产永久不得恢复、发布、搜索或重新绑定；恢复业务只能新建资产与 Question 版本。禁止直接 `SET NULL`、级联删除或覆盖历史来伪造已完成删除。

### 2.4 Intent taxonomy、风险与占位符（DEC-042 必填）

1. taxonomy 以 `intent_taxonomy_version + intent_id` 成对引用；旧 `intent_id` 只可停用，不得删除或改义。改名、合并、拆分必须发布新 taxonomy 版本与显式 `old_id → new_id[]` 迁移映射；未知意图隔离待审，不得以 `unknown` 绕过发布门。
2. `risk_categories` 与 `risk_level` 必须成套：`high` 时非空且只能从七类受控高风险枚举中取值，`low|medium` 时必须为 `[]`；`low|medium` 且无冲突才走 `ROLE-CONTENT-LEAD` 单审，`high` 或同一显式范围内存在相互冲突内容时，必须由固定 `ROLE-CONTENT-LEAD` 与固定 `ROLE-CS-MANAGER` 两个不同伪名主体的独立审核结论共同通过。七类为：退款/赔付、价格/折扣、活动规则、功效/安全宣称、账号/隐私、投诉/升级、法律承诺；命中任一类不得降级为 `low|medium`。未决冲突保持 quarantine。
3. `placeholder_keys` 只允许 `order_id/date`，正文 token 只允许 `{订单号}/{日期}`，声明与正文必须一一对应；未知 token、重复语义键或声明不匹配属于结构错误。
4. `content_hash` 的 JCS 治理快照至少覆盖 Answer、排序无关的稳定 Question 映射、平台与商品范围、风险、有效期、intent taxonomy、placeholder 声明和来源版本。Question 的晋级角色也属于不可变映射，变化时必须形成新 Question 版本/hash。一期 SQL 只实现**固定 ASCII 合同键的 JCS 子集**并使用 `C` 排序；任何新增/Unicode 对象键必须先改用成熟应用层 JCS 并补跨语言固定向量，不能静默扩大 helper 声明。任一治理字段变化均递增 `script_version` 并产生新 hash。

### 2.5 内容质量分层门（DEC-042）

- 结构、安全或来源错误属于批级致命错误：整批失败，不得以 quarantine 规避；
- 文案清晰度、重复、分类建议等质量问题可只将问题行置为 quarantine；只有 clean 行可进入审核与发布候选；
- 每个质量审查批次最多 5,000 条，超过时必须分批；clean 行 `<=500` 时全审，`501–5000` 时抽 10%，且最少 100、最多 300 条；
- 抽样质量问题率 `>2%` 时扩样至 clean 行的 30%；`>5%` 时阻断该质量审查批次；高风险行和冲突行始终 100% 审核，不进入普通抽样分母；
- 抽样策略版本、截止时间、总体/样本量、随机种子或可重放选择证据、缺陷数与扩样/阻断结论必须冻结后再看结果。总体还必须冻结 `population_manifest_hash`：对按稳定键排序的安全元组（至少 `script_id + content_hash + risk_level + has_conflict + quality_status`）求确定性摘要；数量不变但替换任一行也视为总体变化。该内容质量抽检与 CR-002 的 Pilot 三维离线复核分账，不能互相替代。

**机器证据协议：** 普通 import worker 只能经 `freeze_content_quality_review_plan` 冻结 `content_quality_review_plans`（策略版本、cutoff、clean/普通/强制全审分母、初始/扩样目标、`population_manifest_hash`、seed hash、selection manifest hash 与算法），不能在 normalized row 自报通过。授权审核池完成实际检查后，才可经 `record_content_quality_review_evidence` 向 `content_quality_review_evidence` 追加同一 `plan/batch/population_manifest_hash`、样本数、缺陷数、强制全审数、quarantine 数、`passed|blocked` 结论与 EVD；长期人工证据绑定冻结计划，而不是依赖短时 worker lease 维持真实性。finalizer 必须从最终安全行元组重新计算总体 hash，并同时核对 plan、evidence、当前 staging 身份/分母及阈值；缺失、阻断、同数量换行、hash 漂移或过期一律不得转 `staged` / 发布。

## 4. 话术自动识别迭代（话术优化待办）

### 4.1 产品目标

系统根据日志 **自动聚类问题、发现异常**，生成 **话术优化待办** 提醒话术师：

- 可能是 **话术库缺口**（该补 Q 或 A）\
- 也可能是 **排序/算法问题**（库里有，但 Top1 总不对）\

**一期不自动改 Answer**，只 **提醒 + 建议动作**；改库仍由话术师完成。

### 4.2 信号规则（建议默认阈值，可配置）

| 信号 ID | 名称 | 触发条件（示例） | 更像什么问题 | 建议动作 |
|---------|------|------------------|--------------|----------|
| SIG-NO-HIT | 无命中聚集 | 同 `query_text_hash` 或同意图簇，**无命中 ≥ N 次 / 窗口 T**（如 7 天 ≥ 5） | **库缺口** 或缺 Question | 补 Question 或新建 Answer |
| SIG-SKIP-TOP1 | 常跳过 Top1 | 近 7 日：script 在 rank1 曝光 **≥ N=5**，且（chosen_rank∈{2,3} 或 dismissed）占比 **≥ 40%** | **排序/算法** 或 Top1 口径差 | 检查 score；或调整 Question 挂接；或修订 Top1 话术 |
| SIG-ALWAYS-TOP2 | 稳定选 Top2 | 同簇多次选用 **同一 script 且 rank=2** | Top1/Top2 **挂错 Q** 或排序反了 | 对调优先级 / 重挂 Question |
| SIG-LOW-COPY | 低复制 / 多次放弃 | hit 后显式 `dismissed`，或同根问题多次重选仍未复制 | 推荐不准或场景不对 | 只生成候选；人工复核后再判断 Answer、Question 或排序 |
| SIG-CAT-MISMATCH | 类型疑似错 | 检测类型与选用 script.category 不一致多 | 分类/算法 | 纠分类或过滤规则 |

> 阈值 N/T/P/M 在 G0 前与业务拍一版默认值即可，后续可调。

## 5. 隐私与合规要点

- raw 搜索问法只在受控请求内存中处理；日志中的问法必须先 **脱敏**，DLP 不确定时正文 `suppressed`；DDL 静态合同已对齐，但迁移未执行且真实数据门未过前不得接真实数据\
- 数据分层建议固定为 `0/14/30`：raw 原句只在请求内存（0 天）；脱敏问法正文 14 天；个人级结构化事件 30 天；后两者是提交 G0-11 的建议值，不是已授权保留期\
- 聚合优先用 `query_text_hash` + 抽样审核\
- 话术优化待办展示给话术师的样例须权限控制\
- 业务工单文件与本域日志不得混表、不得共用 `task_id`；跨域关联只能使用经过审批的聚合标签或脱敏关联键\
- telemetry 故障允许显著标记的 `collection_disabled/stateless` 安全搜索；该会话不得落问法、候选、复制证据，也不得进入指标、语料或 G1b；DLP、Auth、内容快照不就绪仍 fail-closed\
- 一期角色仍是 `agent / coach / owner`；样本审核、隐私复核等均作为叠加 capability，不建立可绕过既有 RBAC 的平行角色\
- 到期前经二次 DLP、业务 + 数据安全双审、用途锁定后，问法才可从短期日志晋级为 `semantic_asset`；晋级记录必须保存源事件集合 HMAC、key version、审查、保留策略与删除血缘。源删除请求先撤下可推荐绑定，再将非 PII 语义来源资产单向 retire/tombstone 并释放运行 query 外键，同时向向量、数据集、teacher-run 输入索引和备份恢复副本传播；不得用“已脱敏 / 已向量化”规避删除，也不得丢掉 tombstone/EVD 伪造无血缘\

## 6. CR-003 训练预埋与多教师边界

### 6.1 一期只预埋

- `training-artifacts/` 只包含单一 schema、空模板、纯合成 fixture 与说明；不得放真实问法、个人标识、生产导出或教师真实输出；
- 训练目的白名单仅 `retrieval / intent / reranker`，禁止生成回复、个性化脾气模仿或自动发送策略；
- 问法资产和 Answer 发布资产分离，数据项仅保存答案绑定 `release_id + script_id + script_version + content_hash`，不复制最终发送正文；
- 线上继续 Unicode bigram；默认离线 embedding 后端为本地、许可已审的小型开源模型。embedding 只跑影子，不改变线上结果；
- `data_account=real|policy|synthetic` 必须分账。纯合成只能验证管线，policy 数据验证规则，real 数据须真实数据门和双审后方可进入候选。

### 6.2 后续晋级、训练与发布门

1. **晋级：** 行为只产生候选；业务 + 数据安全双审确认语义、用途、许可、DLP 与删除血缘后才成为可训练资产。
2. **隔离：** 按 `semantic_family_id` 去重后切分；`train / G1a / G1b` 禁止同簇、近重复、同源泄漏。G1a/G1b 评测数据不得进入 teacher prompt、训练、阈值调参或 embedding 索引构建。
3. **节奏：** 二期另批后，两周形成一个不可变 `dataset_version` / 训练版本；人工审核、人工发布，禁止在线连续学习和自动晋级。
4. **教师：** DeepSeek 仅为可替换候选，不是微调依赖；GLM 无书面授权禁止蒸馏。教师输入视为不可信数据，必须与系统指令隔离、转义、字段白名单、输出 schema 校验和越权内容拦截。
5. **student：** 只选择经许可审查的小型开源模型，并在隔离环境训练；不得下载来源不明权重，不得把许可证不兼容模型或数据带入交付物。
6. **不可变运行：** `teacher_run` 保存 provider/model/version、prompt/config/input/output hash、参数、数据集版本、时间、操作者、费用与审查结论；只追加，不 UPDATE / 覆盖。
7. **预算：** 教师、embedding 与训练分别设单次 / 日 / 批次 / 月 cap；超 cap fail-closed。费用路径 B 和 Ddev 未成立期间外部教师实付调用必须为 0。

### 6.3 删除血缘最小字段

`asset_id`、`source_event_ids_hash`、`source_expiry_max`、`promotion_review_ids`、`purpose_lock`、`dataset_versions[]`、`embedding_index_versions[]`、`teacher_run_ids[]`、`deletion_requested_at`、`deletion_completed_at`、`backup_redelete_due_at`。任何一环缺失都不得标记“可训练”。
