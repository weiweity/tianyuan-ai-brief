## 0. 大厂是怎么展示技术栈的？

大厂**不会**只写一句「React + Node + Postgres」。标准做法通常是下面几种**同时**出现：

| 展示形态 | 给谁看 | 长什么样 |
|----------|--------|----------|
| **分层清单（Layer Inventory）** | 全员/评审 | 前端→网关→服务→数据→中间件→可观测… 表格穷举 |
| **C4 容器/部署拓扑图** | 架构/运维 | 跑在哪台机器、进程边界、同步/异步边 |
| **Must / Optional / Deferred 矩阵** | 部署 | 一期必装 / 可 Mock / 二期后置 |
| **Tech Radar（Adopt/Trial/Assess/Hold）** | 技术委员会 | 哪些技术主路径、试验、评估、禁止 |
| **版本锁定表 + 环境变量表** | 运维/SRE | 精确版本、ENV 名、默认值、生产红线 |
| **依赖与红线** | 安全/合规 | 外部 SaaS、出域、密钥、禁止项 |

**核心原则：**

1. **按「运行时职责」分层**，不是按公司部门分层。\
2. **每一层写清：选型 · 版本 · 职责 · 一期是否必须 · 挂了怎么办**。\
3. **SoR（权威数据源）单独标红**，避免「本地库冒充全公司库」。\
4. **实线主路径 vs 虚线可选路径**（与架构图一致）。\
5. **禁止清单**与选型清单同级展示（大厂很常见）。

下面 **L0～L16** 是行业穷尽分层；每层先写「行业一般有什么」，再写 **本项目（CS-AI-C11 一期）落什么**。

图例：

- ✅ **一期必须（Must）**
- 🔶 **一期可选 / 可 Mock（Optional）**
- ⏸ **二期及以后（Deferred）**
- ⛔ **明确禁止（Hold / Ban）**

## L4 · 应用服务 / 领域能力（Application Services）

按**能力**穷举（大厂叫 capability / domain service）：

| 能力 | 职责 | 一期 |
|------|------|------|

| **workorders** | 批准 CSV/XLSX → 校验 / 映射 → 聚合 / 下钻 / 脱敏导出 | ✅ Must；只读分析，不写回班牛 |

| **announce** | 版本公告、快照分页、ack | ✅ Must |

## L10 · 异步消息 · 任务 · Outbox（Async / Jobs）

| 项 | 行业常见 | 本项目一期 |
|----|----------|------------|
| 消息队列 | Kafka / RabbitMQ / SQS / RocketMQ | ⏸ 非必须 |
| Outbox 模式 | 表 + worker | ✅ **一期 Must**；`import_batches + outbox_jobs` 同 DB 事务后才 202 |
| 定时任务 | cron / k8s CronJob | 🔶 清理/备份脚本 |
| import Worker | 独立进程 | ✅ **TypeScript / Node 24 LTS**；claim/heartbeat/lease_version/fenced finalize |
| work-order Worker | 独立 capability | ✅ 可同一部署进程但使用 `app_work_order_worker`；job/table/claim/heartbeat/retry/reconciler/finalizer 与内容导入隔离；耗尽时原子关闭 job + batch |
| 清洗 Worker | 独立进程 | ⏸ **Python 清洗 Worker 二期**，不得取代一期 import worker |
| 流处理 | Flink 等 | ⏸ |

**原则：** import 的异步执行是 Must，不等于 search/publish 受进程内队列绑架。Worker 挂掉时已受理 job 留在持久 outbox 中可重抢；积压超门槛要告警并对新 import 背压，不手工改终态。

### 最小部署拓扑

```
[坐席 Windows] Electron 安装包
       │ HTTPS /v1（全程）
       ▼
[入口/LB 或直连 TLS API]
       │ HTTPS
       ▼
[Node 24 API 1或N] ──单事务──> [PostgreSQL 15+] SoR + outbox
       │                              ▲ claim/heartbeat/fenced finalize
       └──先持久原文──> [Object / RWX 持久存储] <── [TS Import Worker 1或N]

single_host: API + worker 同主机/同持久卷；multi_instance: object 或跨节点 RWX
✅ 飞书 OAuth（production Must）   🔶 DeepSeek（可选）
```

### 一期 SLI / 告警与恢复目标

| SLI / 恢复项 | 一期目标 | 告警 / 门禁 |
|-----------------|----------|-------------|
| search 成功率（非 5xx） | **≥ 99.5% / 5min** | 连续 5min &lt; 99% |
| search p95 | **≤ 800ms**（无 LLM）/ **≤ 1200ms**（开 ranker） | 超阈 10min |
| publish 成功率 | **≥ 99%** | 失败 ≥3 次/15min |
| 429 占比 | 正常峰 &lt; 5% | &gt; 15% 持续 5min |
| PG 连接池等待 | p95 &lt; 50ms | 持续升高 |
| 备份年龄 | 成功备份 &lt; 24h | 超过 26h |
| outbox 积压 | oldest pending <120s；dead 增量=0 | >120s warn，>600s critical；dead >0 |
| outbox fencing | lease lost <3/5min；worker heartbeat <2×lease | 超阈调查超时/重抢，不手改终态 |
| 客户端同步 | 在线客户端 p95 落后 ≤1 release | >1 release 持续 15min |
| import 存储 | 可写且按 key/hash 可重读 | 失败则 readiness=false，不受理 202 |
| 工单数据治理 | 未批准列 / 敏感列入库=0；外部写回调用=0 | 任一违规立即停用工单分析并保全审计 |
| 限流分片 | row-lock wait p95 ≤10ms，拒绝分布可接受 | >10ms 持续 5min/倾斜不可接受 → DEC-CAP-01 |
| **RPO / RTO** | **RPO ≤ 24h / RTO ≤ 4h（目标）** | 真备份 + outbox 重放 + 客户端重同步演练前不认证 |

结构化日志至少包含 `request_id, port, user_id_hash, release_id, latency_ms, error_code`，并按路径增加 `query_id | import_batch_id | job_id | client_id_hash`；原 query、token、原文路径禁入日志。

### 恢复清单（上线前实演）

1. 备份清单覆盖 PostgreSQL/PITR、import 对象版本或 RWX 卷快照、迁移/锁定版本/配置 schema、签名 Electron 安装包与更新元数据；secret 只记录恢复引用。
2. 停 import/publish 受理，恢复 PG 与 import 存储到一致点，按 `source_sha256` 校验待重放原文。
3. 只经受控管理函数递增 `lease_version` 并回收可重放 running job；禁止手改 outbox complete 或 batch staged。
4. 启动 TypeScript worker 清积压，验证 `content_current`/release/announcement，再让客户端以固定 release_id 重建快照并 ACK。

### 环境变量（核心）

| 变量 | 含义 | 一期要求 |
|------|------|----------|
| `DATABASE_URL` | Postgres 连接串 | ✅ 必须 |
| `API_PUBLIC_URL` | 客户端访问的 API 根 | ✅ 必须 |
| `APP_ENV` | `development` \| `test` \| `production` | ✅ 必须；生产唯一判定值为 `production` |
| `AUTH_MODE` | `mock` \| `feishu` | dev/test 可 mock；**production 必须 feishu** |
| `DEPLOYMENT_PROFILE` | `single_host` \| `multi_instance` | ✅ 必须；决定存储与实例拒启规则 |
| `API_INSTANCE_COUNT` | API 实例数 | ✅ 必须是正整数，与 profile 一致 |
| `UPLOAD_BACKEND` | `object` \| `filesystem` | ✅ 必须 |
| `UPLOAD_DIR` | filesystem 持久共享卷路径 | 仅 `single_host + filesystem`必填；API/worker 必须挂载同一卷 |
| `UPLOAD_SHARED_VOLUME_ID` | 卷唯一标识/挂载声明 | filesystem 必填，用于防止 API/worker 指向不同卷 |
| `OBJECT_ENDPOINT` | S3 兼容 endpoint | object 必填（云厂商默认 endpoint 可由受控配置生成） |
| `OBJECT_BUCKET` / `OBJECT_REGION` | 对象桶与区域 | object 必填 |
| `OBJECT_CREDENTIALS_REF` | workload identity/密钥引用 | object 必填；不将明文凭证写入业务配置 |
| `WORK_ORDER_UPLOAD_PREFIX` | 工单原稿独立对象前缀 | ✅ 必须；不得与内容导入前缀混用 |
| `WORK_ORDER_MAPPING_VERSION` | 已批准字段映射版本 | ✅ 必须；未知版本拒绝导入 |
| `WORK_ORDER_RETENTION_DAYS` | 原稿 / 标准化数据保留期 | ✅ 安全批准后填写；未批准不得接真数 |
| `RATE_LIMIT_FAIL_CLOSED` | 限流后端失败时拒绝 | **生产必须 `true`**；否则拒启 |
| `RANKING_ADAPTER` | `disabled|deepseek`，默认 disabled | 🔶；未过出域/预算门不得改 |
| `DEEPSEEK_API_KEY` | 可选排序 | 仅 adapter=deepseek 时必填 |
| `CLIENT_ACTION_TIMEOUT_MS` | 客户端操作生命周期阈值 | ✅ 可配置；到期才写 terminal timeout |
| `QUERY_TEXT_RETENTION_DAYS` / `QUERY_EVENT_RETENTION_DAYS` | `0|14|30`，无默认 | ✅ G0-11 签发前不得接真实数据 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 真登录 | 🔶 生产 |
| `LOG_LEVEL` | 日志级别 | 建议 info |
| `PORT` | API 监听端口 | 如 8765 |

> 生产启动必须同时验证 `APP_ENV=production`、`AUTH_MODE=feishu`，并确认 `/v1/auth/mock-login` 未注册；任一条件不满足，进程必须在监听端口前退出。

### 配置拒启矩阵

| 条件 | 行为 |
|------|------|
| production 的 `API_PUBLIC_URL` 或 API→入口跳为 `http://` | 监听前拒启；内网不豁免 |
| `multi_instance + filesystem` 且非已验证跨节点 RWX | 拒启 |
| `multi_instance` 使用节点本地 `UPLOAD_DIR`、临时盘或无共享卷证明 | 拒启 |
| `single_host + filesystem`，但 API/worker 的 `UPLOAD_SHARED_VOLUME_ID` 不同或目录不可持久重读 | 拒启 |
| `UPLOAD_BACKEND=object` 但 endpoint/bucket/region/credentials ref 缺失，或启动读写探测失败 | readiness=false 且不受理 import；生产进程拒启 |
| TypeScript import worker 未配置，outbox 函数/ACL 未通过自检 | 不注册 import 路由；不得降级为进程内队列 |

## 最小可运行清单（ops checklist）

1. 先选且记录 `DEPLOYMENT_PROFILE`：`single_host` 准备 API+worker 同主机共卷；`multi_instance` 准备 2+ API + 1+ worker + object/跨节点 RWX；两者均需 Postgres。\
2. 安装并锁定 Node 24 LTS 精确 patch 与 pnpm；生产设置全程 HTTPS。\
3. 注入 `DATABASE_URL`：全新空库用 33 作 clean-install 对照；生产/存量库只执行 46 §6 的不可变 `expand→backfill→validate→contract` migrations，禁止把 33 当升级器。\
4. 配置 `UPLOAD_BACKEND` 与对应 OBJECT_*/共卷参数，验证 API 与 TypeScript worker 按 key/hash 读写同一原文；通过 outbox claim/heartbeat/fenced finalize 自检。\
5. 启动 API，配置 `API_PUBLIC_URL`、`APP_ENV`、`AUTH_MODE`；生产校验 `RATE_LIMIT_FAIL_CLOSED=true`、`AUTH_MODE=feishu` 且不注册 `/v1/auth/mock-login`，否则监听前拒启。\
6. 首发前确认业务 `/ready=false`，search/current 为 `CONTENT_NOT_READY`；导入种子话术 → Owner **Publish 一次** → readiness 转绿。\
7. 打包并验证 Electron CSP/IPC/allowlist/permission/fuses，签名安装包与更新元数据，再发给坐席。\
8. 用 41 的 30 天数据包络跑 EXPLAIN/容量门，并完成 PG+存储+outbox+客户端重同步恢复演练；未通过不认证 QPS/RPO/RTO。\
9. **试点前**完成真飞书 OAuth 配置、回调与 agent/coach/owner 越权测试；仅 DeepSeek 排序是可选。\
10. 工单真实数据启用前补齐字段白名单、映射版本、保留期、脱敏、安全 EVD；用合成 / 批准脱敏样例验证导入、聚合、下钻、导出和“无写回”。
