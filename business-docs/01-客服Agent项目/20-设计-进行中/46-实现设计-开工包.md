## 2. 技术栈冻结

| 层 | 一期唯一选择 | 禁止双轨 |
|----|--------------|----------|
| 工作区 | **pnpm workspace** | 不并存 npm/yarn lockfile |
| API 宿主 | **Node.js 24 LTS + TypeScript strict + Fastify** | 不并存 Nest/Express 第二宿主；禁止已 EOL Node |
| 运行时校验 | **OpenAPI JSON Schema → Fastify validator** | 不手写第二套 Zod/TypeBox DTO 真源 |
| 机器合同 | **OpenAPI 3.1 为源** | 不从手写 TS 反向覆盖 OpenAPI |
| TS 类型 | 从 OpenAPI **单向生成**到 packages/contracts/src/generated | generated 文件禁止手改 |
| 数据访问 | **pg + Pool + 参数化 SQL** | 关键路径不交给 ORM 隐式生成 |
| 数据库 | **PostgreSQL 15+** | SQLite 仅可选只读客户端缓存 |
| 单元/集成测试 | **Vitest** | 不并存 Jest |
| Electron/E2E | **Playwright Electron** | 不引入第二套 E2E runner |
| import 执行 | **持久 outbox + TypeScript / Node worker** | Python 清洗仅 Deferred；禁止进程内队列返 202 |
| import 存储 | **object 或跨节点 RWX；filesystem 仅 single_host 共卷** | 禁止多实例节点本地路径 |
| 桌面端 | Electron + React + TypeScript | renderer 禁 Node 权限；安全基线见 §10.5 |

本包选择 **OpenAPI JSON Schema**，不选择 TypeBox。原因是 OpenAPI 已被指定为机器合同源；再用 TypeBox 手写同一组 DTO 会形成第二真源。依赖的精确 patch 版本在 DEV-M0 初始化时写入 package.json 与 pnpm-lock.yaml，禁止 floating latest。

Node 未来升级只可选官方仍受支持的 LTS；DEV-M0 在 `engines`、版本管理文件、`packageManager`、lockfile 与 CI image 同时锁定精确 patch，禁止 floating latest。

目录纪律：

- API 唯一路径是 **apps/api**；禁止再建 services/api。
- `openapi.v1.yaml` 是 machine source；packages/contracts/openapi 仅容纳生成 bundle，禁止再建可手改的 `cs-agent.v1.yaml` 第二真源。
- packages/contracts 不含业务逻辑；packages/config 不依赖 apps。
- domain 是纯函数与类型，零网络、零文件、零数据库 I/O。
- ports 负责协议编排，可依赖 domain、adapter 接口与 infra repository。
- adapters 不依赖 port 内部实现，不得直写 scripts/release_items。
- infra/postgres 是服务端唯一 SQL 出口。
- 内容与工单 import worker 可共用 apps/api 包和部署进程，但必须使用不同 entrypoint capability / DB role / job type / object prefix / finalizer；Web 进程不得用无持久化的内存任务冒充 202 异步队列，Python 不在一期必经路径。
- Electron renderer 只经 preload 白名单 IPC；renderer 不直连网络密钥或数据库。
- Electron main 只管窗口、剪贴板、热键与受控 IPC，不写业务 SQL。

health/ready 属于 platform endpoint，不增加第十业务端口；`/ready` 必须分别报告 database/schema/auth/storage/content，其中 storage 覆盖配置后端的写入与按 key/hash/size 重读完整性探测；响应 schema、鉴权边界、首发内容 readiness 与 503 规则以 39 §0.6 / OpenAPI 为准。

## 5. 依赖与事务调用顺序

### 5.1 所有请求的公共顺序

1. 生产只接受客户端→入口→API 全程 HTTPS；内网明文跳、错误证书或非 allowlist origin 在业务逻辑前拒绝。
2. 生成或接收 request_id。
3. 解析服务端可信身份；忽略客户端声明的角色。
4. 用 `openapi.v1.yaml` 的 JSON Schema 校验 path/query/header/body。
5. 对有副作用端点处理幂等；**已完成终态 replay 必须发生在限流扣费之前**。
6. 以固定顺序扣用户桶，再扣全局桶；search 全局桶为 16 分片近似保护，分片函数只能用 39 冻结的 SHA-256/UTF-8/big-endian uint32 算法与金标向量，禁止语言内置 hash；生产限流存储失败即 503。
7. 开启最小数据库事务；禁止在事务内等待 LLM 或文件网络上传。
8. 调 repository 或冻结的 SECURITY DEFINER 函数。
9. 同事务完成幂等记录；提交后生成结构化日志和指标。
10. DB 错误只按 39 冻结的 SQLSTATE 映射稳定 HTTP/`error.code`；`DETAIL` 仅作经 allowlist/schema 验证的 `error.details.reason`；**禁止解析 DB `MESSAGE` 文案/前缀**，不泄漏 SQL、路径、token 或原始 PII。

### 5.2 幂等矩阵

| 操作 | 幂等身份 | request_hash |
|------|----------|--------------|
| search | query_id 作为业务幂等键 | 原始 canonical body 的带版本 HMAC（禁无密钥 SHA） |
| adoption | **必填** Idempotency-Key；另受 query_id 唯一约束 | canonical JSON body |
| escalate | **必填** Idempotency-Key；另受 `(query_id,action)` 唯一约束，同 query 可多 action | canonical JSON body |
| import JSON | Idempotency-Key | canonical JSON body |
| import multipart | Idempotency-Key | canonical metadata + file_sha256 + file_size；multipart boundary/临时路径不入 hash |
| publish/rollback/cancel | Idempotency-Key | canonical JSON body |
| announce ack | **可选** Idempotency-Key；DB user-bound 单调 release_seq 是业务幂等真源 | 提供 header 时用 canonical JSON body |
| policy flag / iteration-task mutation | Idempotency-Key | canonical JSON body |

同步写：claim → 业务 → complete 必须同一事务。\
异步 job：使用 lease_version fencing token；heartbeat 只能续自己持有的 lease；旧 worker 的 complete 必须被 DB 拒绝。

canonical JSON 参考向量（适用于无 PII 端口的 SHA 分支；search 对该 canonical 字节做 HMAC）：

~~~text
input:  {"b":1,"a":2}
canon:  {"a":2,"b":1}
sha256: d3626ac30a87e6f7a6428233b3c68299976865fa5508e4267c5415c76af7a772
~~~

### 5.3 search

1. 校验 query_id、parent_query_id、interaction_reason、query_text、platform、`product_context_type`、`product_context_ref`、兼容输入 sku_hint 与 top_k；original 必须 parent=null，reselection 必须引用同用户已终态父 query。按已锁 DEC-042 机器合同，platform 必须是明确上下文；`product_context_type=category|sku` 与 `product_context_ref` 必须成对，缺商品上下文只允许命中显式 `storewide`。旧 sku_hint 不得代替 category/sku 成对语义，也不得以空值进入“全平台/全商品”路径。
2. 生产身份/RBAC；在不记录 raw body 的受控内存中，先按已存 `request_hash_key_version`（无记录则当前版本）计算 HMAC 并查终态 replay；只有 miss 才扣 user:search 后 global:search。过期 pending lease 须进 claim 重抢，不得卡到 TTL。
3. redaction port 内部先把 NFKC 作为模式匹配预处理，再执行手机号/身份证替换，生成 query_text_redacted；从端口编排看，redaction 仍先于日志、持久化与 LLM。这样全角数字也不能绕过规则。
4. 原始 query_text 不落库、不进结构化日志；SearchBackend 与事件只消费 normalized + redacted 文本，query_text_hash 使用 39 冻结的带版本 HMAC。
5. 在一次请求上下文读取 current_release_id；首次 owner publish 前不存在 current，返 503 `OVERLOADED` + `details.reason=CONTENT_NOT_READY`，不写 query/impression、不 complete 幂等终态。后续全部读取固定 release_id。
6. CR-004 运行实现中，同一快照必须证明该 release 恰好绑定 `presale/campaign/aftersale/product` 四个 immutable、`use_class=canonical` source versions、条目来源匹配且无任何永久暂停记录；未登记/reference 来源同样拒绝；canonical/current 只从这组 binding 推导。任一失败整次 fail-closed，不能作为 no-hit，也不能走 stateless。
7. API / `app_runtime` 只调用 `search_recommendable_scripts(platform, product_context_type, product_context_ref)`；该受控函数在同一 statement snapshot 依次执行 source binding、permanent suspension、effective window、显式 scope、taxonomy、风险审核与非 quarantine/未决冲突门。`app_runtime` 对 backing view、`release_items`、`content_current` 无直接 SELECT；路由不得自行拼 `WHERE`。
8. SearchBackend 对上述受控函数返回的固定 snapshot 以字符 bigram + normalize + exact/escaped ILIKE 回退召回；不得读任意 scripts、backing view、可变 current-source 标记或过期本地 snapshot 旁路。EmbeddingProvider 只能接离线影子 runner，不能注册到在线 port。
9. 可选 RankingStage 在事务外执行，400ms 超时；失败回退规则序。
10. 用 release_items 填充 Answer **模板原字节**与获批 `placeholder_keys`；ranker 无权返回或修改 Answer。每个候选强制携带 release_id/script_id/script_version/content_hash，其中 content_hash 必须对应该版本固定 ASCII 键集的治理快照，不得只算正文。返回 public wire 前必须经显式最小投影 mapper，禁止 `row spread` 把 reviewer/EVD、上游定位符、origin HMAC 或语义来源查询透出 API。
11. 单事务写 query_events 与 0～3 条 candidate_impressions；候选四元组必须 FK 命中同 query release 的不可变 release_items。事件只绑定模板四元组，不接收占位符值或客户端渲染正文。
12. 返回与已写 impressions 同一组 candidates；禁止补假卡。
13. CR-004 **来源/租约**拒绝时主事务保持 query/impression/正常幂等终态零写入；回滚后以独立、幂等短事务追加最小 source denial audit。底层 writer 只给 definer，`app_runtime` 只能调用 runtime wrapper，`app_content_admin` 只能调用 admin wrapper，两边 operation 白名单不交叉。DEC-042 内容、审核、质量或 hash 拒绝记入标准发布/安全审计，禁止塞入 source denial 原因集。任一所需审计失败继续 fail-closed，不得改返普通 no-hit。

DEV-M1 尚未交付 content HTTP 时，测试 fixture 必须创建 staged batch 并调用 publish_content_release 生成 current release。禁止为提前跑 search 而直插“第二真源”、自动发布空 release 或绕过 snapshot。

### 5.4 adoption / escalate

adoption：

1. agent 只能操作自己的 query_id；coach/owner 代操作能力一期不开。
2. adopted 必须同时满足 chosen_rank、chosen_script_id 非空，且精确匹配 candidate_impressions。
3. adopted 仅允许 clipboard/autofill 成功；failed/pending/null 一律 POLICY_DENIED。
   若模板声明 `placeholder_keys`，必须先在客户端受控内存中对 `{订单号}` / `{日期}` 做确定性渲染，展示二次确认后才执行剪贴板 CTA；缺必填值、未知 token 或声明/正文不匹配时禁止复制。值、渲染正文与二次确认内容零落库/日志/事件/缓存/截图；adoption 仍只绑定模板四元组。
4. dismissed/timeout/no_hit_exit 的 chosen 字段必须符合 OpenAPI 条件矩阵。
5. timeout 只由客户端窗口关闭/切后台/idle 达到 `CLIENT_ACTION_TIMEOUT_MS` 后上报，服务端不得凭 HTTP 延迟猜测。
6. 首次终态 wins；不同 payload 的重复请求 409；同 payload 回放首次结果。

> **兼容口径：** `adoption` / `adoption_events` / `push_method` 是既有机器合同名，CR-002 不做破坏式改名；对用户和指标统一解释为“成功复制”，不得据此推断已发送、已采纳或回答正确。自动事实只包括脱敏问法、不可变候选、唯一操作终态与升级辅助动作。

escalate：

- user_id 从 claims 派生；
- query_id 必须存在并属于当前 agent；
- action 只能是合同枚举；
- `(query_id,action)` 幂等，同 query 可记录多个不同 action；动作不结束 query，也不证明外部人工已接单/解决；
- 成功写入后返回 escalate_id/query_id/action。

### 5.5 import

1. 上传流只能写入 `UPLOAD_BACKEND`。`object` 写受控 quarantine key；`filesystem` 只在 `single_host` 中写 API+worker 同一持久卷。流式 hash，不把整文件读入内存。
2. 在受理前完成大小、扩展名、MIME、magic、压缩炸弹、宏/外链、路径安全检查；完成写入后按不透明 storage key 重读/校验 `source_sha256 + source_size_bytes`。存储不可用就失败，不写 batch。
3. multipart 先写 quarantine 并流式求 hash。对象存储不依赖 atomic rename：以 conditional create/server-side copy 提交到稳定内容寻址 key `imports/{tenant_id}/{source_sha256}`；最终 key 已存在时必须 HEAD/重读并校验 hash + size，不符即 fail-closed。最终 key 存在且校验相符才视为 commit，quarantine 安全窗后延迟清理。filesystem 仅限同持久卷，按临时文件 fsync → atomic rename → parent directory fsync 提交；目录同步成功才算 durable commit。这里的 `import_batches.source_ref` 只存不透明最终 key，不存主机路径，也不代表内容权威来源；原文件名只作经清洗审计字段。
4. multipart 幂等 hash 只用稳定 `{source_type,file_sha256,file_size_bytes}`，不含服务端随机 `source_ref`、boundary、文件名或临时 path；Feishu JSON 才把客户端稳定 source_ref 纳入 hash。终态 replay 时可安全去重 quarantine；DB claim 失败留下的对象由安全窗后扫描器清理。
5. 原文已持久后，以**同一 DB 事务**创建 `import_batches(status=validating)` 与 `outbox_jobs(job_type=import_validate,status=pending)`；只有二者 commit 成功才返回 202。只入内存队列、只写 batch 或只写 job 都不得 202。
6. **一期 TypeScript worker Must：** 独立进程只调 `claim_content_import_validation(instance_id, lease_seconds)`，保存 `lease_version`；续租/重试只调 `heartbeat_content_import_validation` / `retry_content_import_validation`。claim 与每次 heartbeat 必须各用独立短事务并立即 `COMMIT`；claim `COMMIT` 后才可文件 I/O；retry/finalize 各开新事务，禁止 claim→文件 I/O→retry/finalize 共用显式事务。通用 outbox API 对该 role 必须 permission denied。
7. **耗尽闭环：** 专用 retry 与 claim 前 reconciler 都必须以 batch→outbox 锁顺序在同一事务将耗尽任务收口为 `job=dead + batch=failed + error_report(code=MAX_ATTEMPTS_EXHAUSTED)`，并递增 fencing token；禁止永久卡在 validating。
   claim 前置 reconciler 每次最多 1 条；调度清理只能独立短事务调用 `p_limit<=10` 并逐批 COMMIT，禁止大批清理与 claim/文件 I/O 组成长事务。
8. worker 按 storage key 读取原文，重验 hash/size，按 script_id 聚合 questions 并校验。文件表头/行出现内容 `source_ref/source_version` 必须整批拒绝，不能忽略；内容 domain/source version 只从服务端已冻结的受信 import 上下文取得，worker/file 均无权覆盖。按已锁 DEC-042 合同，worker 验证上游稳定随机 `question_id`、不可变 `(question_id,question_version)`、包含 `promoted_by_role` 的 question hash、origin HMAC + key version、显式 scope、taxonomy、risk/categories、placeholder 声明与固定 ASCII 键集治理快照；normalized row 不得携带审核主体/角色/EVD/结论或 `quality_gate_passed`。普通 worker 只可调用 `freeze_content_quality_review_plan` 冻结抽样计划与 `population_manifest_hash`；审核池另经 `record_content_review_decision` / `record_content_quality_review_evidence` 写受限事实。finalizer 以安全行身份元组重算总体 manifest，必须与 plan/evidence 绑定值相同，即使行数不变也不允许替换总体。upsert 须分别产出 questions/title/answer 的 NFKC+2gram token 串与 fallback；finalizer 从受限事实解析固定角色、双审异人和质量结论，并在单事务完成 staging + batch 终态 + job complete。
9. complete 必须匹配 running/owner/version/未过期 lease；失租或 cancel 时 DB 以 SQLSTATE `ZA006` + `DETAIL=OUTBOX_LEASE_LOST` 拒绝，API 返 409 `CONFLICT` + `error.details.reason=OUTBOX_LEASE_LOST`。当前事务的 staging/batch/complete 整体回滚，旧 worker 停止副作用。
10. `app_import_worker` 只有 import 专用 claim/heartbeat/retry、freeze quality plan/finalizer EXECUTE，无 review decision/quality evidence、通用 `outbox_complete` 权限，也无 staging/batch/outbox/审核或质量证据表直接 DML。审核池 capability 只可调用对应 record 函数，不得 claim/finalize import。校验失败的公开 `error_report` 仅允许枚举 code、DB 随机 UUID 生成的 opaque diagnostic_id、安全行列/计数与有限枚举 issue_codes，`additionalProperties:false`；worker 不得提供 diagnostic_id，SQL 必须拒绝并重建未知 worker JSON。原始异常只进脱敏、限长、最小权限运维日志，通过受限 diagnostic_id→job_id 审计映射关联，不写正式 scripts/release_items。
11. cancel 只调 `cancel_content_import(...)`，原子争抢 `validating|staged → failed`并递增 lease_version；publish 原子争抢 `staged → publishing`。两者都检查受影响行数，禁止 API 先 SELECT 后 UPDATE；竞态仅一方成功。
12. 文件、孤儿上传、失败 batch 按已批准留存策略清理；当 DB 事务失败时允许留下可识别孤儿对象，由受控扫描器按 key/hash/安全窗清理，不在请求失败路径冒险误删。
13. CR-004 的来源上下文缺失/不匹配、文件自报来源或命中永久暂停时，import 整批 fail-closed；业务事务回滚后以独立、幂等短事务追加最小 source denial audit。DEC-042 内容/质量/hash 拒绝另记标准发布/安全审计。不得在随后 `RAISE` 会回滚的同一事务内写拒绝证据。

### 5.6 publish

1. 仅 owner；一期 coach 不发布。
2. 先做终态幂等 replay，再扣 owner 桶与全局桶。
3. 开事务并调用 publish_content_release；API 不复制 SQL。
4. 函数使用 pg_try_advisory_xact_lock；失败立即 409。
5. 用单条原子条件更新争抢 `staged → publishing`，受影响行数必须为 1；0 行按存在性/状态返 NOT_FOUND/CONFLICT。禁止先 SELECT 后 UPDATE；invalid/空批拒绝，事务失败时状态迁移同步回滚。
6. operation=upsert 覆盖同 script_id；operation=withdraw 从新 snapshot 排除，并归档 scripts。
7. 新 snapshot = previous snapshot ∪ upsert − withdraw。
8. 对完整 MERGE 候选 snapshot 校验 CR-004：恰好具备 `presale/campaign/aftersale/product` 四域 immutable source bindings，全部条目来源匹配且无 source version 存在永久暂停记录；不得只校验本批行。同时校验 DEC-042：只允许 clean 行、非未决冲突、taxonomy 已批准、scope/placeholder 形状合法且审核完整的条目；`high`或冲突项必须 Content Lead + `ROLE-CS-MANAGER` 两个独立结论。
9. 发布前必须验证质量审查快照：clean `<=500` 全审；`501–5000` 抽 10%（最少 100、最多 300）；问题率 `>2%` 扩至 30%，`>5%` 阻断；high/冲突 100% 审且不进普通抽样分母。规则版本、截止点、总体安全行身份的 `population_manifest_hash`、随机种子/选样 hash、总体/样本/缺陷数与扩样/阻断结论必须先冻结。finalizer 再从当前 staging 重算 manifest 并与 plan/evidence 绑定值比较；同计数替换行也必须拒绝。结构/安全/来源错误仍整批失败，不得借 quarantine 降级。
10. 为每个 release_item 以 **DEC-042 固定 ASCII 对象键集 + `COLLATE "C"` 键序**的规范化治理快照重算 content_hash；这是受限治理子集，不得对外声称通用 Unicode RFC 8785 serializer。Answer、排序无关的稳定 Question 映射（含 `promoted_by_role`）、scope、risk、effective、taxonomy、placeholder 或来源版本任一变化均必须递增 script_version 并产生新 hash，不得沿用旧快照。
11. 来源切换只能随本次 publish 生效。同事务写 release、release_items、四域 bindings、content_current、announcement、change_audits，batch 变 published；禁止先改可变 current-source 再发布。
12. complete 幂等记录并提交；任何失败不得移动 content_current 或部分写入新 bindings。
13. 来源/租约拒绝在主事务回滚后独立、幂等提交最小 source denial audit；内容合同、质量、审核或 governance hash 拒绝记入标准发布/安全审计。所需审计提交失败继续 fail-closed。

### 5.7 rollback

1. 仅 owner；必须 Idempotency-Key。
2. 调 rollback_content_release，禁止 API 手拼第二套发布事务。
3. 先重新校验目标 release 的四域 immutable bindings、条目来源与永久暂停记录；任一 source version 已暂停或绑定不完整即整次拒绝，禁止过滤目标 snapshot。
4. 目标 release 的完整 snapshot 与四域 bindings 重放成新的 release_seq。
5. 历史 release 不就地修改；新 release 记录 rollback_of_release_id。被暂停旧 source version 永久不能借 rollback 复活。
6. 同事务更新 current、announcement、change_audits；来源/租约拒绝走独立 source denial audit，其他内容治理拒绝走标准发布/安全审计。

### 5.8 announce / ack

- current 可 ETag/304，release_seq 为游标。首次 owner publish 前返 503 `CONTENT_NOT_READY`，业务 readiness=false；不返虚构 seq=0。
- snapshot 的 release_id 首次确定后整次分页固定；cursor 只按 script_id。服务端返回该 release 的完整不可变集合，不按当前时间删项；客户端每次使用时按 `effective_from <= now < effective_to` 半开区间过滤，`now == effective_to` 必须排除。
- 客户端必须完整拉完并成功替换本地只读 snapshot 后再 ACK。
- ACK 校验 release_id 与 release_seq 对应，不接受未来游标。
- ACK 只表示客户端内容已同步，不表示用户已读公告。
- ACK 唯一写路径为 `ack_client_release(...)`；`app_runtime` 不得直接写 `client_sync_state`，由函数在行锁下绑定 user/client 并拒绝游标回退。
- CR-004 机器 changeset 已静态冻结：current 签发绑定 `client_id + user_id + release_id + source_binding_hash` 的 opaque 短租约，默认 600 秒、允许 60～900 秒，DB 只存 token SHA-256；snapshot 每页和 ACK 均验租，ACK 只记同步游标/token hash 且不续租。current/snapshot/ack 的来源/租约拒绝必须先回滚主事务，再独立幂等提交 source denial audit，最后返回 HTTP denial；ACK 的其他内容错误只走标准错误审计。离线客户端只在租约有效期内使用本地 FTS；到期立即停检索并提示联网，取得新租约前无宽限或旧 snapshot fallback。时钟偏差动态负例仍待实现取证。

### 5.9 policy

- GET 返回未知 flag 时按 OFF。
- POST 仅 owner，必须调用 set_policy_flag。
- “未知 flag → OFF”只适用于 GET 读取缺失键；POST 提交未在允许枚举内的 flag_key 必须返回 400 VALIDATION，不得自动创建任意键。
- 一期 rewrite=true 与 auto_send=true 无条件 POLICY_DENIED；Owner 和 ADR 也不能越过期别。
- AUTH_MODE 是鉴权模式唯一真源；APP_ENV=production 时 AUTH_MODE 必须 feishu，且 mock-login 路由不得注册，否则进程在监听端口前退出。policy_flags 不存在 mock_auth；POST 提交该键按未知键返回 400 VALIDATION。

### 5.10 CR-002 搜索—复制自动事实与离线语义增量

### 5.11 CR-004 来源治理静态实现合同

1. source version 不可变；每个 release 恰好有售前、活动、售后、产品四条 immutable、`use_class=canonical` bindings，未登记/reference 来源拒绝。canonical/current 是 `content_current` + bindings 的投影，不建可变 current 来源字段。
2. suspension 仅追加永久事实，不提供更新、删除或恢复旧版本的动作。旧 source version 一经暂停永久不得 import/publish/rollback/search；恢复业务只能登记新版本并发布新 release。
3. 文件行不得自报内容来源。`import_batches.source_ref` 仅为存储/上游对象定位符；`scripts/release_items.source_ref` 只能由服务端受信 import 上下文和 release binding 附加。
4. import/publish/rollback/search 共享同一来源治理 fail-closed policy evaluator；来源未登记或仅供 reference、缺域、重复、hash/EVD 不匹配、条目来源不匹配或永久暂停均不得被转成 no-hit 或部分成功。离线租约只约束客户端本地 search，不参与 import/publish/rollback。
5. source switch + publish 使用全站单飞和单一事务；完整 MERGE 校验、release、四域 bindings、current、announcement、change audit 同成同败。
6. denial audit 是失败路径的独立持久副作用：主业务事务先回滚，再用 request/decision 去重键在独立短事务追加最小记录；不得与会 `RAISE` 的事务同写。审计失败时管理写动作继续拒绝。
7. desktop 只缓存完整 current snapshot + bindings 摘要 + 短租约；静态租约包络为默认 600 秒、60～900 秒，绑定 `client_id/user_id/release_id/source_binding_hash`；租约到期停止本地检索，联网重新核验并取得新租约后才恢复，ACK 不续租。

**状态纪律：** 本节与 39/33/OpenAPI 是同批 `STATIC DESIGN/MACHINE CONTRACT`；迁移、生成类型、服务端/客户端代码与动态测试仍为 `NOT IMPLEMENTED`。在 Ddev 后对应里程碑取证前不得注册运行路由、执行生产迁移或把静态条款记为运行 EVD。

### 5.12 DEC-042 内容资产治理静态实现合同

1. **稳定 Question 身份：** `question_id` 由上游给定稳定随机 ID，禁止以文件行序、数组下标或正文 hash 派生；`(question_id,question_version)` 是不可变版本键。正文、Answer 映射、intent、来源或 `promoted_by_role` 变化时必须追加新 `question_version>=1` 与 `question_hash`，且 hash 必须覆盖该晋级角色。保留 `semantic_family_id`、HMAC `origin_fingerprint` + `origin_fingerprint_key_version`、`source_asset_id` 和 `manual|from_log|import`。Question 持久化前先脱敏，旧版本禁止覆盖/删除后复用。`from_log` 的语义资产须先退役/墓碑并撤下引用 release，才能删除源 query；不得破坏历史血缘或原地复活旧资产。
2. **显式范围：** `platform_scope` 必填非空，只允许 `qianniu|douyin`；全平台必须显式同时列出两者。商品范围使用 `product_scope_type=storewide|category|sku` + 受控 refs；只有 `storewide` 的 refs 可为 `[]`，`category/sku` 必须非空并匹配请求上下文。
3. **taxonomy 与风险审核：** `intent_taxonomy_version + intent_id` 成对必填；旧 ID 不删除/改义，变更只能发布新版本和显式迁移映射。未知 intent 隔离待审。risk categories 使用受控枚举；`low|medium + 无冲突` 由固定 `ROLE-CONTENT-LEAD` 单审，`high` 或冲突内容必须固定 `ROLE-CONTENT-LEAD` + 固定 `ROLE-CS-MANAGER` 两个不同伪名主体独立双审，未决冲突继续 quarantine。normalized row 不接审核主体、角色、EVD 或结论；授权审核池仅经 `record_content_review_decision` 写受限事实，finalizer 才解析冻结。
4. **受控 placeholder：** 一期机器键只允许 `order_id|date`，正文 token 只允许 `{订单号}|{日期}`，声明与正文必须一一对应。API 返回模板原字节；desktop 只在内存渲染并二次确认，缺值即禁止复制，值/渲染正文/确认内容零落库、零日志、零事件。
5. **治理快照：** `content_hash=SHA-256(JCS-subset(规范化治理快照))`；本合同只允许 SQL 明确构造且校验过的固定 ASCII 对象键，键序固定 `COLLATE "C"`，不冒充通用 Unicode JCS serializer。快照至少覆盖 Answer、排序无关稳定 Question 映射（含晋级角色）、平台/商品 scope、risk、effective/review due、taxonomy、placeholder 声明和来源版本。任一变化都递增 `script_version` 并产生新 hash。
6. **分层质量门：** 结构/安全/来源错误整批失败；文案清晰度、重复或分类建议等质量问题可只 quarantine 问题行。每批最多 5,000 条；clean `<=500` 全审，`501–5000` 抽 10%（min 100/max 300），问题率 `>2%` 扩至 30%、`>5%` 阻断，high/冲突 100% 审且不进普通分母。普通 worker 仅经 `freeze_content_quality_review_plan` 冻结 `content_quality_review_plans` 与基于安全行身份的 `population_manifest_hash`；授权审核池再经 `record_content_quality_review_evidence` 写 `content_quality_review_evidence` 并绑定同一 manifest。finalizer 重算总体 manifest 并重验 plan/evidence、分母、阈值和 EVD，拒绝同计数换行、短 worker lease 冒充审核身份或 row 自报 `quality_gate_passed`。
7. **公开投影与快照：** Search/Snapshot 只经显式白名单 mapper 返回封闭 public schema，Question 只返回客户端必需字段；内部 reviewer/EVD、origin HMAC、source query/上游定位符不出 public wire。snapshot 分页返回完整不可变 release，客户端使用时再按 `[effective_from,effective_to)` 过滤。

- 质量 plan 未先冻结、evidence 缺失/blocked/异体重放、`population_manifest_hash` 与 staging 安全行身份不等、同计数替换行，或 row 自报 `quality_gate_passed` 必须失败。
- 未知 placeholder、声明/模板不一致、缺值仍复制，或占位符值/渲染正文进入 DB、event、log、trace、cache 必须失败。
- 治理快照任一字段变更却沿用 `script_version/content_hash`、Question `promoted_by_role` 变更不改 hash、固定 ASCII 键未以 `COLLATE "C"` 排序、只对 Answer 正文求 hash，或质量抽样不可重放必须失败。非 ASCII/任意 Unicode 对象键不得经该受限 serializer 冒充通用 JCS。
- 结构/安全/来源错误被降级 quarantine、clean `<=500` 未全审、`501–5000` 未满足 10%/100–300、问题率 `>2%` 未扩 30%、`>5%` 仍发布，或 high/冲突进普通抽样分母必须失败。
- `from_log` 语义资产未先退役/墓碑与撤下 release 引用就删源 query，或旧 source_asset 原地复活必须失败。
- snapshot 在服务端按当前时间删除 release item、客户端在 `now == effective_to` 仍使用，或 public mapper 透出 reviewer/EVD、origin HMAC、source query/上游定位符必须失败。

## 8. 中文检索实现合同

### 8.1 normalize

固定顺序：

1. Unicode NFKC。
2. 英文按 locale-independent lowercase。
3. 标点映射：
   - ，→ ,
   - 。→ .
   - ！→ !
   - ？→ ?
   - ：→ :
   - ；→ ;
   - （）→ ()
   - 【】→ []
   - “ ”→ "
   - ‘ ’→ '
   - 、→ ,
4. 所有 Unicode 空白折叠为一个 ASCII 空格。
5. trim。

固定向量：

| 输入 | 输出 |
|------|------|
| ＡＢＣ　客服，退款 | abc 客服,退款 |
|  活动  什么时候结束？ | 活动 什么时候结束? |
| 【售后】　换货 | [售后] 换货 |
| Ｔ恤　XL | t恤 xl |

normalize 必须在查询与入库检索文档两侧使用同一 packages 内纯函数；禁止客户端和服务端各写一份。

### 8.2 Unicode code point bigram

- 用 Array.from(normalizedText) 或等价 code point 迭代；不得按 UTF-16 code unit 切分。
- 检索 token 只在字母、数字、汉字组成的连续片段内生成，不跨空白或标点边界。
- 每个片段长度 0：无 token；长度 1：交给 exact/ILIKE；长度 ≥2：生成重叠二元组。
- 示例：退款进度 → 退款、款进、进度。
- emoji 或扩展字符按一个 code point 处理；不生成代理项半字符。
- questions、title、answer 分开生成，再以 tsvector 权重 A/B/C 合并。
- pg_trgm 只允许加速 ILIKE/相似度回退，不得作为 bigram 主路径。

### 8.3 过滤、召回与排序

1. 固定 current_release_id。
2. effective window 强制过滤。
3. `platform_scope` 必填非空，只允许 `qianniu/douyin`；两者全含才表示 both。请求 `platform` 必须明确且被 scope 包含；禁止用 `NULL/[]` 或请求空值放宽为全平台。
4. 商品资产范围必须是 `product_scope_type=storewide|category|sku` + `product_scope_refs`；`storewide` 必须 refs=`[]`，`category/sku` 必须 refs 非空。搜索请求的 `product_context_type=category|sku` 与 `product_context_ref` 必须成对；成对时只命中对应 refs 或显式 `storewide`，两者均缺时只命中 `storewide`。旧 `sku_hint` 仅保留兼容语义，不得代替新成对字段，更不得表达 category scope。
5. exact equality/phrase candidate 与 bigram candidate 合并、按 script_id 去重。exact equality 只比较 normalized question/title；phrase 比较 normalized questions/title/answer。
6. bigram 查询用参数化 tsquery；ILIKE 对反斜杠、百分号、下划线转义，并显式 ESCAPE。
7. 0 code point 返回 VALIDATION。
8. 1 code point 跳过 bigram，走 exact/escaped ILIKE。
9. bigram 无候选或分词失败才走 escaped ILIKE 回退。
10. 默认稳定排序使用元组，不让实现者自定数字：exact question、exact title、phrase question、phrase title 依次降序，再按 PostgreSQL tsvector 默认 A/B/C 权重的 ts_rank_cd 降序，最后 script_id 升序。
11. 最低置信阈值、hit@3 目标属于 §13 的产品决策门；未批准前不得宣称达到业务准确率。若后续调整排序元组或权重，必须有金标前后对比与 Tech Owner ADR。
12. LLM ranker 只在本地候选产生后可选运行，只改顺序/score，不得改 Answer。

## 9. 上传与活动价安全

### 9.1 上传

- 只接收 csv/xlsx；拒绝 xlsm、可执行文件、宏与外部链接。
- 扩展名、Content-Type、magic 三者不一致即拒绝。
- object backend 用最小权限 bucket/prefix、服务端生成 key、默认私有且禁止直接公网读；filesystem 目录权限 0700、文件 0600，文件名只用服务端 ID。
- `UPLOAD_DIR` 仅 single_host 可用，必须是 API+worker 同卷的持久绝对路径，且不在静态服务根、源码仓、临时盘或用户可控路径。
- CSV 仅接受 UTF-8/UTF-8 BOM；编码失败给逐行错误，不猜编码。
- XLSX 必须限制 entry 数、解压总字节和单 entry 字节；超限即失败。
- 不透明 storage key、文件 SHA-256、大小、清洗后原名与 batch 关联审计；worker 读取时复验 key/hash/size。
- 文件内容、路径、hash 不进入普通 INFO 日志。
- 失败和取消不允许半发布；孤儿文件由受控清理 job 按批准留存期处理。

### 9.2 活动价/价格承诺

安全默认：

- 在 DEC-CONTENT-01 尚未签字前，所有 category=campaign 行都必须同时有 effective_from 与 effective_to；不能靠关键词猜哪些行含价格承诺后再选择性放行。
- 日期时间以 UTC 存储；若导入仅给 YYYY-MM-DD，则按 Asia/Shanghai 将 from 映射为当日 00:00:00、to 映射为当日 23:59:59.999，再转 UTC。
- 检索边界统一为半开区间 `[from, to)`：`effective_from <= now()` 且 `now() < effective_to`。`now == effective_to` 必须排除，不得因旧客户端或 snapshot 缓存多放行一个端点。
- 缺任一边界时整批 `failed` 并写结构化 error_report，不写 staging；仅整批合法时 staging 全部 `validation_ok=true`。publish 仍保留 invalid-row 防御门。
- 不允许靠文本关键词自动决定是否“价格敏感”并静默放行。

DEC-CONTENT-01 必须由 Content Owner/Product Owner 决定：

1. 是否所有 campaign 都强制双边有效期，或增加明确的 price_sensitive 字段；
2. 谁维护有效期；
3. 允许的最长活动窗口；
4. 永久有效例外由谁批准。

在该门通过前，validator 对所有 category=campaign 且缺任一边界的行 fail-closed。

## 10. 指标口径

存储时间统一 UTC；API from/to 使用 ISO-8601 UTC，区间为 [from, to)；Dashboard 展示为 Asia/Shanghai。

| 指标 | 一期计算 |
|------|----------|
| root_question_count | `interaction_reason=original` 的 query 数 |
| search_operation_count / reselection_count | 全部 query 数 / `interaction_reason=reselection` 的 query 数 |
| root_adopted_count / root_adoption_rate | 链内任一 operation 成功复制的去重 root 数 / root_question_count |
| operation_adopted_count / operation_adoption_rate | outcome=adopted 的 operation 数 / search_operation_count；不表示发送或正确 |
| operation_no_hit_count / operation_no_hit_rate | no_hit operation 数 / search_operation_count |
| top1_copy_share | adopted 且 chosen_rank=1 / operation_adopted_count |
| root_escalated_count / root_escalation_rate | 链内任一 auxiliary action 的去重 root 数 / root_question_count |
| escalate_action_count | 按 `(query_id,action)` 去重的动作数；同 query 可有多个不同 action |
| p95_latency_ms | 录制查询延迟 P95；空窗口返回 `null`，不用 0 冒充未知 |

约束：

- 时间窗归属以 root/operation 各自 query_events.created_at 为准，不以 adoption 写入时间漂移；两套分母必须同屏返回。
- agent 只能看自己；coach/owner 的全站与分用户权限需 G0 RBAC 签字。
- 经营指标响应时间、满意度、转化率不进入本 API。
- `metrics/tool` 必须满足 `to > from` 且 `to-from ≤ 7 天`；越界返回 400 `VALIDATION`，不得静默截断。更长报表另走离线任务/ADR。
- 指标目标值、业务告警阈值与是否进入绩效考核属于 DEC-METRICS-01，不在实现者处自行决定。
- CR-002 自动事实只用于产品改进和语义候选治理，不得默认用于个人绩效；修改/发送/正确性必须来自批准抽样的离线人工复核并单独统计。

### 10.1 数据增长包络与 EXPLAIN 门

以下只是工程造数/容量演算，不是用户行为预测或已实测事实：

| 项 | 演算基线 |
|----|----------|
| 日均 query | 150 在线坐席 × 0.05 QPS/座席 × 12 活跃小时 ≈ **324,000/day** |
| 日 impression 上界 | 每 query 最多 3 条，约 **972,000 rows/day** |
| 30 天热数据 | **9.72M query_events + 29.16M candidate_impressions**，同时造 idempotency/outbox/client_sync 长尾 |
| 短突发 | **300 QPS × 60s = 18,000 queries**；500/s 只是限流保护上限，不是性能认证 |

- 在不小于该 30 天包络（或等价分布统计）上，对 search、metrics、snapshot 分页、outbox claim 归档 `EXPLAIN (ANALYZE, BUFFERS)`。关键查询 actual total time ≥3s、不受约束的全历史扫描、临时盘 spill 或超出 pool/WAL 预算，任一成立即失败，修复并重跑。
- **DEC-DATA-01：** Owner/Tech/Security 须在生产开 metrics 前签 hot retention、分区/预聚合、归档/删除策略。30 天只是演算基线，不是隐私留存授权。
- search 的 PostgreSQL 近似全局桶用 16 分片，每分片 capacity=32/refill=31.25/s。**DEC-CAP-01：** 坐席 >150、目标突发 >300 QPS、行锁等待 p95 >10ms 持续 5min 或倾斜不可接受，必须升级公司网关/Redis 等原子限流并重跑压测。

### 10.2 首次未发布行为

- 新库无 `content_current` 是合法技术启动态，但业务 readiness 必须 false。
- `POST /v1/search` 与 `GET /v1/announce/current` 返 503 `OVERLOADED` + `details.reason=CONTENT_NOT_READY` + `Retry-After`；不写 query/impression/幂等终态。
- 禁止空 release、seed 直改 current、直扫 scripts 或返虚构 release_seq=0。只有 Owner 对已校验 staged batch 完成首次发布，business readiness 才转绿。

### 10.3 outbox / client-sync 可观测

| 信号 | 告警/恢复动作 |
|------|---------------|
| outbox oldest pending | >120s warn，>600s critical；按 job_type 分类 |
| outbox dead / lease lost | dead 增量>0；lease lost ≥3/5min 调查 worker 超时/重抢 |
| worker heartbeat age | >2×lease 告警；不允许手改 terminal status 消警 |
| client release lag / ACK age | 在线客户端 p95 落后 >1 release 持续 15min 告警 |
| import storage | 按 key/hash 不可写或重读时 readiness=false，不受理 202 |
| content current | 首发前 readiness=false；首发后从 present 变 absent 立即 critical |

结构化日志以 `request_id` 为主链，再连接 `query_id | import_batch_id | job_id | release_id | client_id_hash`；不记原 query、token、原文路径或未脱敏 outbox error。

### 10.4 恢复清单（待真实演练）

1. 备份对象包括 PG/PITR（release/current、idempotency、outbox、client_sync）、import 对象版本/RWX 卷快照、迁移/锁定版本/配置 schema、签名 Electron 安装包与更新元数据。secret 只保留安全恢复引用。
2. 恢复顺序：停 import/publish → 恢复 PG+存储一致点 → 按 source_sha256 验证 → 受控函数递增 lease_version 并回收可重放 job → 启 TypeScript worker 清积压 → 校验 current/release/announcement → 客户端固定 release 重同步/ACK。
3. 禁止直改 outbox complete/batch staged “做绿”。RPO ≤24h / RTO ≤4h 仅是待验证目标；在真备份、outbox 重放和 client resync 演练成功前不声称达标。

### 10.5 Electron 安全实现合同

- BrowserWindow 必须 `contextIsolation=true`、`sandbox=true`、`nodeIntegration=false`；preload 只用 `contextBridge` 暴露单职责方法，禁止通用 channel 转发。
- 每个 IPC handler 先校验 `event.senderFrame` origin/URL + 预期 WebContents，再做 payload schema/RBAC；不接受 renderer 传入任意 path/shell/role。
- CSP 禁止任意远程 script/eval；will-navigate、window open、`shell.openExternal` 精确限制到预期 HTTPS host/scheme。
- permission request/check 默认 deny；页面以受控 custom protocol 加载，不直接依赖 `file://`。
- CI 验证 Electron fuses，固定受支持 Electron patch；Windows 安装包/更新元数据签名、防降级、保留上一已签名可回滚版本。验签失败即中止更新。

### 12.3 必须保留的不变量

- INV-NR：Answer 字节等于当前 release_items。
- INV-EFF：过期内容永不出现。
- INV-ADOPT：伪造“复制成功”的 adopted 兼容事件被 API 与 DB 双拒绝。
- INV-PAD：不凑满 3。
- INV-REL：current、snapshot、announcement、audit 同事务。
- INV-FB：ranker 失败仍返回规则结果并记 query。
- INV-RL：超限 429，过载 503。
- INV-PUB-LOCK：并发 publish 仅一成功。
- INV-BYPASS：旁路改 published 内容失败。
- INV-CTA：主按钮 data-testid=cta-clipboard，文案含复制/剪贴板。
- INV-IDEM：终态 replay 不重复业务、不重复扣限流。
- INV-FENCE：旧 worker lease 不得完成新 lease 的 job。
- INV-IMPORT-DURABLE：原文可重读 + batch/outbox 同事务前不返 202；多实例节点本地路径拒启。
- INV-OUTBOX-FENCE：失租旧 worker 的 staging/batch/complete 整事务回滚。
- INV-FIRST-REL：无 current 时 search/current 503 `CONTENT_NOT_READY`，readiness=false。
- INV-DB-ERROR：HTTP 只依赖 SQLSTATE + allowlisted detail，DB `MESSAGE` 文案改变不影响映射。
- INV-ELECTRON-BOUNDARY：非 allowlist sender/navigation/window/openExternal/permission 全拒绝，fuses 与签名更新门可验证。
- INV-TASK-DOMAIN：话术优化待办只访问 `iteration_tasks` / audits，不连接业务工单明细。
- INV-TASK-CAS：start/close 匹配 `expected_version` 与合法迁移；并发旧版本 409。
- INV-WO-DOMAIN：`/work-orders/*` 只访问 `work_order_*`，不生成内部待办、不混入检索指标。
- INV-WO-ALLOWLIST：未知列、原始客户 / 订单 / 工单编号与 raw row JSON 不进入标准化表、公开错误、日志或默认模型出域。
- INV-WO-IDEM：同 scope + source hash + mapping version 重试不重复记录；总数=接受+拒绝。
- INV-WO-RO：代码、配置、凭据、OpenAPI 和 E2E 均证明无班牛建单 / 填单 / 改单 / 写回路径。
- INV-WO-RBAC：agent 全拒绝；coach / owner 仍受业务范围过滤；导出只追加审计。
- INV-AUTH-PROD：试点 / production 非 Feishu、缺验签配置或注册 mock-login 时监听前拒启。
- INV-COPY-SEMANTICS：`adoption_events` / `push_method` 仅作为机器兼容名；UI、指标与审计把成功动作称为复制，且不推断已发送、已采纳或正确。
- INV-RESELECT：original parent=null；reselection 指向同用户已终态父 query；lineage append-only 且无环。
- INV-CANDIDATE-PROVENANCE：每条候选四元组外键绑定同 query release 的不可变 release_items。
- INV-CONTENT-ID：`question_id` 是上游给定的稳定随机 ID；Question 变更必须递增 `question_version` 并生成新 `question_hash`，hash 覆盖 `promoted_by_role`；保留 semantic family、带版本 HMAC origin 与 source asset 血缘，禁止行序/正文 hash 派生身份。
- INV-CONTENT-SCOPE：`platform_scope` 非空且显式；`product_scope_type/refs` 形状合法。请求 `product_context_type=category|sku` 与 `product_context_ref` 成对，缺上下文仅命中 `storewide`，旧 sku_hint 不代替 category scope。
- INV-INTENT-TAXONOMY：`intent_taxonomy_version + intent_id` 必填且已批准；旧 ID 不删除/改义，只能经新版本和显式迁移映射变更，未知 intent 隔离。
- INV-CONTENT-RISK：`risk_level=low|medium|high`；low/medium 需 Content Lead 审核，high 或冲突需 Content Lead + `ROLE-CS-MANAGER` 独立双审，未决冲突不得发布/检索。
- INV-PLACEHOLDER：仅 `order_id/date` ↔ `{订单号}/{日期}`；API 返模板原字节，客户端内存渲染+二次确认，缺值禁复制，值与渲染正文零持久，事件只绑模板四元组。
- INV-CONTENT-HASH：`content_hash=SHA-256(JCS-subset(规范化治理快照))`；只接受固定 ASCII 对象键并以 `COLLATE "C"` 排序。Answer、稳定 Question 映射/晋级角色、scope、risk、effective、taxonomy、placeholder 或来源版本任一变更都必须递增 `script_version/hash`。
- INV-CONTENT-QUALITY：结构/安全/来源错误整批失败；质量问题行 quarantine；clean `<=500` 全审、`501–5000` 抽 10%（100–300），问题率 `>2%` 扩 30%、`>5%` 阻断，high/冲突全审。plan/evidence/finalizer 绑定同一 `population_manifest_hash`，同计数换行也失败。
- INV-TERMINAL：每 query 仅一条 adoption terminal；timeout 只由 CLIENT_ACTION_TIMEOUT_MS 客户端生命周期触发。
- INV-ESCALATE-AUX：`(query_id,action)` 幂等，同 query 可多 action；辅助动作不终结 query、不证明外部解决。
- INV-METRICS-DUAL：root question 与 search operation 两套分母同屏返回且不混算。
- INV-SEMANTIC-LINEAGE：from_log 语义问法必须带 source query + 审核 EVD；删源前先退役/墓碑资产并撤下 release 引用，历史血缘不原地复活；一期无在线复核/训练 API。
- INV-PUBLIC-PROJECTION：Search/Snapshot 只返封闭最小 public schema，禁止 DB row/internal object spread 与 reviewer/EVD、origin HMAC、source query/上游定位符外泄。
- INV-SNAPSHOT-EFFECTIVE：snapshot 保留完整不可变 release；客户端使用时按 `[effective_from,effective_to)` 过滤，`now == effective_to` 不可用。
- INV-STATELESS：仅采集链路故障时允许明确 `collection_disabled/stateless` 安全搜索，并排除语料候选与指标；DLP/Auth/content readiness 故障不得降级绕过。
- INV-SOURCE-BINDING：每 release 恰好绑定售前/活动/售后/产品四域 immutable source versions；canonical/current 只从 current release 推导。
- INV-SOURCE-SUSPEND：暂停只追加且永久；旧 source version 一经暂停永久不得 import/publish/rollback/search，恢复只能新版本 + 新 release。
- INV-SOURCE-IMPORT：文件表头/行自报内容来源整批拒绝；`import_batches.source_ref` 仅是对象定位符，内容来源由服务端受信上下文附加。
- INV-SOURCE-ATOMIC：完整 MERGE 校验、source switch、release、四域 bindings、current、announcement、change audit 同一事务。
- INV-SOURCE-ROLLBACK：目标任一 source version 已暂停或 binding 不完整时 rollback 整次拒绝，禁止过滤 snapshot 或复活旧来源。
- INV-SOURCE-DENIAL-AUDIT：仅来源/租约拒绝在主业务事务回滚后独立幂等提交 source denial audit；内容/质量/hash 走标准审计，同事务 INSERT+RAISE 不合格，所需审计失败继续 fail-closed。
- INV-OFFLINE-LEASE：客户端短租约到期立即停止本地检索；ACK 不续租，联网取得新租约前不得使用旧 snapshot。

### 14.1 话术优化待办（内部 `iteration_task`）

- 读：`GET /v1/metrics/iteration-tasks`。
- 写：`POST /v1/events/iteration-tasks/{task_id}/start`。
- 写：`POST /v1/events/iteration-tasks/{task_id}/close`。

数据库四态与 UI 三态映射：

| UI 三态 | DB 状态 | 含义 |
|---------|---------|------|
| 待处理 | open | 新生成、未领取 |
| 处理中 | in_progress | 已领取、待处置 |
| 已关闭 | resolved 或 wont_fix | 必须带 resolution 与 resolution_note |

冻结迁移：

~~~text
open → in_progress
in_progress → resolved | wont_fix
resolved / wont_fix → 终态，一期不 reopen
~~~

权限：

- agent 不可读全站话术优化待办、不可改状态。
- coach 可领取和关闭授权范围内待办。
- owner 可读全站并关闭；不得改历史 signal。
- 每次状态变更必须匹配 `expected_version`，写 actor、时间、before/after、version 与审计；旧版本返回 409。

自动生成：

- “跳过 Top1”沿用 31 已冻结的 N=5、40%、7 日规则。
- no_hit 聚类阈值、分派规则和 SLA 不由实现者猜，进入 DEC-ITERATION-TASK-01。

### 14.2 工单分析（业务 `work_order`）

```text
批准 CSV/XLSX
  → 安全上传 / 校验 / 映射版本

  → app_work_order_worker 专用 claim / heartbeat / retry / fenced finalize
```
