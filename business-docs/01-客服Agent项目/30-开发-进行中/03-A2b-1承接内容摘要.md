## Architecture review

选择独立、版本标记的 owner_acceptance_content_hash(snapshot, script_version, record_sha256)。拒绝修改旧 content_governance_hash：那会改变历史摘要语义并影响已发布内容。新函数为 invoker/immutable，拒绝 NULL、未知或缺失键、不合法版本/锚点、非承接模式、缺失负责人或证据、非空第二审核人、未决冲突。只提供确定性内容标识；不查询登记表，不推断真实批准，不授予应用执行权。实际来源、业务字段验证、登记状态和整批精确 scope 由后续消费边界拥有。

## Code quality review

封装一个稳定摘要前像，不把新字段散落到所有调用方。复用已有闭合键检查。SQL NULL 与 JSON null 显式处理，固定错误码不回显数据。旧 registry SQL 和冻结 v1.14 SQL 不修改；新文件只追加一个函数及 ACL。

## Test review

Node 内置 node:test + 隔离 PG15，沿用现有生命周期及中断清理，不新建测试集群管理器。

```text
actual normalized snapshot + version + approval record SHA
  +-- NULL/shape/version/anchor bad -> fixed error [PG15 negative]
  +-- wrong review metadata/conflict -> fixed error [PG15 negative]
  +-- valid -> canonical final digest [SQL vs Node]
         +-- business field/version/owner/EVD/record changes -> different digest
         +-- old single/dual hash -> unchanged
         +-- runtime/admin/registrar direct invocation -> permission denied
```

上述新增路径已在本轮 PG15 合成测试执行；未运行真实内容。后续 consumer 才证明“实际候选绑定有效批准”，本次纯函数不构成该证明。

## Performance review

每条内容一次确定性序列化和 SHA-256，无数据库读取、N+1、网络或缓存；受上游实际内容大小合同限制。复用默认 parallel unsafe，不声称未验证的并行安全。参考 PostgreSQL 15 CREATE FUNCTION 对 IMMUTABLE/INVOKER/NULL 语义的官方说明：https://www.postgresql.org/docs/15/sql-createfunction.html 。
