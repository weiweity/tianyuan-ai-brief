## 边界选择

比较两种方案：调用方自行拼装 observed_scope，会要求每个装载/发布消费者重复来源查询、条目映射和审核元数据约束；单一内部断言从实际内容派生 scope，则由数据库边界统一拥有这些知识。选择后者，复用登记断言的有效期、撤销、来源就绪和事务锁，不复制其状态判定。

接口只接收 tenant、批准记录 SHA、可信负责人 hash、独立选择的四域来源 ID 和实际候选数组。每项含 `script_version`、规范化 `snapshot` 与 `content_hash`。调用方必须先完成业务验证，再用 `content_governance_snapshot` 从实际条目构造快照；不得从批准 scope 伪造快照，也不得把本断言当成业务字段 validator。此责任将在后续消费者接线处验证。

数据库一次读取所选四域不可变来源，检查候选 domain/source_ref/source_version_id；逐条计算最终摘要和审核前摘要，对条目按 ID 排序并与登记范围精确比较。负责人和 EVD 被审核前摘要排除，因此另行绑定到可信负责人及登记表中的批准证据。重复、缺失、新增或业务修改的条目均不等于批准范围；允许输入顺序变化。

## 失败与权限

拒绝非法形状、NULL、越界版本、摘要不符、未登记/撤销/过期、来源不匹配/暂停、范围变化以及不可信审核元数据。错误不回显业务内容。函数固定 search_path、由 cs_ai_definer 持有、无应用角色执行权限。必须在实际消费的 READ COMMITTED 事务内调用；复用断言的来源共享锁与记录共享锁持续到事务结束。只验证后结束事务再另行写入不满足接口合同。

## 验证与设计复核

沿用隔离 PG15 runner、Node canonical hash 对照与中断清理；测试仅含合成数据。负例修改内容后重新计算有效摘要，证明内容标识本身不能替代批准范围；另覆盖条目数量/身份/版本/风险、来源、负责人/EVD、撤销/暂停、租户、隔离级别与 ACL。原有并发撤销/暂停测试继续验证被复用的底层锁策略。

实现只增加一个内聚校验边界，不新增服务、状态存储、应用授权或 pass-through wrapper。来源事实只查一次，条目聚合一次，避免每条查询或逐条 JSON 数组拼接。5000 条上限复用批准范围合同。
