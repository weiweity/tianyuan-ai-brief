# A2b-4 承接导入终结

状态：IMPLEMENTED CANDIDATE · SYNTHETIC VERIFIED。已完成合成导入终结接线与 PostgreSQL 15 验证；尚未获得本候选的公开批准，不表示发布或正式运行放行。

## 目标与前置

前置为 PR #64 的三表存储门。本候选在既有 finalize_content_import_validation 中完成“受控 worker 输入 → 数据库可信审核元数据 → 实际暂存内容 → 完整承接范围 → 批次/任务原子终结”的可运行切片。最终发布/回滚/current 与产品快照交接仍为后续任务。

## 本次修复的原链路缺口

- worker 当前被明确禁止提交 review_mode、审核人、EVD 与 quality_gate_passed；这些字段由数据库审核决定表产生。承接扩展必须保留该禁令，不能把审核字段重新交给 worker 自报。
- 当前审核模式按 high/冲突派生 dual，其他派生 single；必须让数据库从已登记的承接记录派生 owner_acceptance、真实负责人及 EVD，不伪造第二审核人。
- 暂存 INSERT 尚未传递 script_version 与 owner_acceptance_record_sha256；尾部仍按旧 content_governance_hash 重验全部 upsert。
- 冻结质量计划/证据按实际内容摘要与风险计数绑定，不能由负责人承接代替；high 的 mandatory review 分母不能减少。
- 原函数先锁 batch，再锁 outbox lease。承接读取还涉及来源与记录锁；新路径应在 batch/outbox 前取得来源共享锁，与发布的来源锁在前保持一致。

## 方案选择

采用扩展现有终结函数，保留原签名、lease 校验、质量门与失败原子性。独立新终结入口会复制 worker 完成协议，并要求调用方自行选择两条链，故不采用。版本化增量可完整重定义该函数，避免运行时对 pg_proc 源码做字符串替换；文件行数增加不作为隐藏迁移逻辑的理由。

新增 worker 字段仅作为不可信引用：记录摘要及条目版本，必须同时出现、严格校验类型/范围，仅用于 upsert；legacy 与 withdraw 不得夹带。记录必须已由窄登记角色登记，导入 worker 不获得登记或表写权限。

数据库按当前 batch 租户关联记录，并从记录取负责人和 EVD。未知记录不回退到 legacy。owner 暂存版本必须与当前 authoring 后继版本一致；发布时仍需再验版本，避免阶段间变化。旧模式继续走原审核决定及摘要算法。

暂存完成后，按承接记录分组，从实际 persisted 行生成规范快照；四域来源 ID 从 import_batch_source_bindings 独立取得，调用 A2b-2 全量断言。漏项、增项、跨记录混用或不同来源集合须回滚整批。通过后才完成 batch 与 outbox，保留尾部 lease 再验。

## 最小验证闭环

- 合成 high 内容，仅有已登记承接及独立质量证据，实际调用 finalizer 成功，暂存行来源/版本/摘要/负责人均核对，任务和批次原子终结。
- 缺登记、撤销/过期/来源暂停、错租户、条目或版本变化、完整集合删项/增项全部失败且不留部分暂存或终结状态。
- worker 自报审核元数据仍拒绝；缺失/错误质量计划、质量证据或 stale lease 不因承接放宽。
- legacy single/dual、失败报告和 withdraw 保持原协议；不得只用直接 INSERT 的存储测试冒充 finalizer 验收。
- 新函数语法/静态检查、隔离 PG15、并发锁顺序、完整 release 和独立差异审查；新候选公开前另按 DEC-PUBLISH-01 精确批准。
