## 1. 为什么要做（问题 · 给非业务也能懂）

原始客服沟通已明确的短期诉求是 **智能质检、评价分析报告、聊天分析**；话术库属于能力侧补充，不是业务当场确认的落地方案。外包、无内网和个人文档依赖均作为 08-04 待验证假设，不作既成事实。

待验证的问题假设：

- 若真实任务证明答复依赖经验或个人资料，可能存在**口径难统一、更新不及时**的问题
- 若真实任务证明话术查找与版本治理优先，个人经验依赖可能带来质量风险
- 若只上「自动回复机器人」，风险高、也解决不了「标准谁维护」的问题

**条件式目标：** 仅当话术库 / 检索推荐在统一评分中证据充分且明确第一，才把标准答法做成可管理的 **快捷语资产**，用检索 / 意图推荐帮坐席选对话并支持统一更新；桌面嵌入仍属后续范围。
**BI 继续看服务结果；本项目改「应答这一步怎么干」。**

**验证边界：** 08-04 先对“话术库 / 检索推荐、智能质检、评价分析报告、聊天分析”强制排序；仅当话术库 / 检索推荐第一且统一评分卡证据完整时，MVP-A 才进入后续 Scope 冻结。内部坐席验证不证明外包网络、账号、授权或终端接入已解决。

## 2. 做什么 · 做成什么样（四层能力）

按顺序建设，不一次承诺全做完：

| 层 | 能力 | 业务白话 | 首期是否申请 |
|----|------|----------|--------------|
| **L1** | 知识库 + 问答 + **草稿 / 复核 / 发布 / 回滚** | 标准答法集中管、问得到；改一条坐席能搜到且可追溯 | **是 · MVP-A** |
| **L2** | 话术算法 + 意图检索 | 按客户意图推荐合适快捷语 | **是 · MVP-A** |
| **L3** | **推送 / 过期提醒 / 版本·审批** | 广播同步与治理（≠「能改库」） | 二期 |
| **L4** | 桌面端嵌入聊天 | 工作台内一键用，少切屏 | 二期/三期 |

**使用形态（始终）：** 推荐 → **坐席确认** → 发出（人在环）。
**不是：** 全自动代客回复、RPA 接管会话。

## 3. 首期申请什么（MVP-A · 建议写入费用）

| 项 | 内容 |
|----|------|
| **范围** | L1 + L2 初版：统一库、管理端改库生效、可问答、可意图 / 检索推荐、**客服 Agent 内部工作台（形态待 G0 确认）**；不做桌面嵌入 / 代回 |
| **技术底座** | **优先复用**既有话术能力（如 `dafuyan-wording`）；在 G0 内、**Ddev 前**完成复用盘点（能/部分/不能 + 缺口）。未盘点前“约 8 周”只作时间盒，不是锁死合同 |
| **用户** | 内部试点坐席 + 话术师/管理者改库（名单在 **Scope 冻结** 后确定） |
| **周期** | Ddev 后两段：**约 4 可用工作周内部可演示（G1a）** → 再 **约 4 周内部小试用（G1b）**（合计约 8 周量级；阻塞 / 旁线占用另计） |
| **成功标准（首期·可测，数可依基线在 G0 共改）** | ① 有效话术 ≥200 条（或共定 N），含平台 / 场景、Owner、来源、版本 ② 冻结 20 条正例全量盲测 Top3 ≥70%，≥5 条负例错误直答 = 0，引用版本正确 ③ ≥3 名内部坐席连续 2 周、每人每周 ≥5 个去重真实任务，并同时报告有用率 / 采纳率 / 未命中率 / 查找时长 ④ 自动代发 = 0 ⑤ 草稿→复核→发布 / 回滚可审计，同日可检索 |
| **主 R** | AI 组 FDE（天元） |
| **需业务配合** | 正式批准凭证；客服业务 / 话术 / 预算 / IT 安全 Owner **具名**；经理 + 话术 Owner + ≥3 坐席需求再验证 —— 均是进入 Scope 的前置 |
| **非本项 KPI** | 供应链/备案/上海会等布局线；不计入本卡成功标准 |

### 3.1 AI 费用申请要点（科目级 · 可再填数）

> 金额与供应商待你方财务/采购口径补齐；本卡先定 **要什么、为何、不批怎么办**。

| 科目方向 | 用途 | 不批则 |
|----------|------|--------|
| 模型 / API 调用 | 问答、意图理解、检索增强；**须设月度 cap**；量级占位：试用期 **数百～数千元/月**（精确数在 G0 由预算责任人回填） | 先测关键词基线；智能方案无增益则不增加模型费 |
| 应用部署 / 算力或托管 | 内部可访问环境 | 仅本地 Demo，难试点 |
| 如需向量库/检索组件 | 语义匹配 | 退回规则检索 |
| （可选）桌面嵌入相关 | L4，**建议二期再申请** | 首期不做桌面 |

**申请原则：** 首期费用只覆盖 **MVP-A**；L3/L4 另立里程碑再申请，避免一次报大包。

## 4. 明确不做（立项必带 · 挡需求）

| 不做 | 原因 |
|------|------|
| 全自动代客回复 / RPA 代回 | 风险与口径责任；与「人在环」冲突 |
| 首期承诺外包全量开通 | 网络、账号、权限与终端条件尚未验证；内部验证后再谈 |
| 首期上全量质检、自治执行或复杂 Agent 闭环 | 依赖会话、权限与规则，另阶段评估 |
| 设计 AI 出图主 R | 业务已自驱；不占本项带宽 |
| 仓储/供应链智能大系统 | 与 BI 边界冲突；另线查重/布局 |
| 无 Owner 的泛需求池 | 避免 FDE 变成全公司接单调研岗 |
