## 2. `ERR_FILE_NOT_FOUND` 根因与最终协议

根因不是单纯的文件名写错，而是把“相邻文件存在”当成单文件交付的前提。旧的 Blob 顶层导航又产生了一个假绿：首次点击成功，但刷新后 Blob URL 失效，仍会进入 Chrome 错误页。

最终实现分成两条明确路径：

- HTTP(S)：使用相邻 07 / 08 HTML 的 canonical URL，刷新和浏览器历史保留真实 pathname；
- 孤立 `file://`：使用同一物理 HTML 的 `?portable=prd|hub` 持久路由，从内嵌数据还原另一界面；刷新重新读取原物理文件，不依赖 Blob URL；
- PRD 及 Hub 主跳转、真源阅读入口使用 button + `data-canonical-href`，不再保留可被中键 / 新标签绕过的缺失相对 `href`；
- 便携路由只在 `file://` 启用，HTTP 不会被 `portable` 查询参数劫持。

1. 角色待具名从错误的 0 还原为真源的 **13**；

状态结论继续保持：客服 Agent P0 已登记，2026-08-04 只启动立项；公司批准未归档，外部责任包 **0/14**、Scope **0/15**、总计 **0/29**，G0 未签发，Ddev 未成立，产品开发未开始。

同时补齐了工具链的失败关闭：checker 先在内存中完成全量契约校验，再用同目录临时文件 + `fsync` + 原子 `rename` 事务更新 PRD 与 manifest，提交失败时回滚；Hub 以单文件原子替换。三段式 sync 不冒充跨进程总事务：中途失败会保留可检测、可重跑的中间态，只有最后 PRD / Hub 双 `--check` 通过才报告稳定点。所有项目输入都执行 no-follow 与 `realpath` 根边界检查；内容不变时不改 bytes / mtime；私有路径按 POSIX 字面量生成，`$()`、反引号、`$HOME` 都不会被 zsh / bash 误执行。
