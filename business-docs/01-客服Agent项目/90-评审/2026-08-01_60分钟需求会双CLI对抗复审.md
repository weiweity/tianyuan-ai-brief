## 3. 现行 60 分钟唯一议程

| 分钟 | 环节 | 到点必须留下什么 |
|---:|---|---|
| 0～5 | 边界与分工 | 项目已批准；本会不选技术栈、不宣布开工 |
| 5～15 | 看真实任务 | 至少 2 个脱敏任务及耗时、错误或升级证据 |
| 15～23 | 选一期主问题 | 一个主问题；证据不足则 `OPEN` |
| 23～30 | 定一期边界 | 主用户、主场景、最小闭环、人工确认、做 / 不做 |
| 30～38 | 定成功与停止 | 指标名称、来源、负责人；无基线不编目标值 |
| 38～45 | 定真源与责任 | 权威来源、权限、维护人、冲突裁决 |
| 45～52 | 定试点与规模 | 3–5 人分层原则、预计人数 / 峰值、业务限制 |
| 52～60 | 回读决定与未决 | 九项逐一标状态、负责人、截止日、证据位置 |

算术为 `5+10+8+7+8+7+7+8=60`。生成守卫会拒绝空档、重叠、不是 8 段、不是从 0 开始或不是在 60 结束的议程。

## 4. 九项决定不允许“假冻结”

九项依次为：一期主问题、主用户与场景、最小闭环、做什么 / 不做什么、成功 / 停止、权威来源、试点人口、系统约束、后续责任。

现场只允许四种记录：

- `DEC`：证据足，现场已经决定；
- `PRECONFIRM`：会前已填，现场待确认；
- `OPEN`：缺证据，必须写唯一负责人和日期；
- `PARKING`：不在本会决定，会后书面处理。

会议成功的定义是九项都被处理，不是九项都被强行写成 `DEC`。主持台里的“已回读”也明确不等于“已决定”。

## 6. 最新现场化改造

- 移动端 DOM 顺序改为“主持台 → 议程 → 会前准备”，读屏和键盘顺序与视觉一致；
- 主持台显示当前环节、本段剩余、全场预计剩余、上一段 / 下一段和到点硬切提示；
- 九项决定提供 `0/9` 回读进度，但不代替正式状态记录；
- 投影主持模式隐藏无关内容，主持标题、计时和议程字号单独放大；
- 打印按钮生成 1–2 页主持兜底卡，自动化实测为 2 页；
- 客服总监标为最终业务拍板，客服 BP 标为协同与记录，不再含糊合并职责；
- 本段与全场倒计时各有独立可访问名称，避免读屏语义混淆。
- 手机端九项回读使用双列短卡，减少主持台纵向长度；现场页面采用“中文在前、代号在后”，正式台账仍保留可追溯代号。
