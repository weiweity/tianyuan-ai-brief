## 1. 决定

客服 Agent 当前采用 `L1 · SINGLE_OWNER` 治理：项目 Owner、Content Lead 与飞书文档管理员可由同一名公司内部负责人承担，不再要求另一名独立管理员完成父级继承、传递角色组、组织外邀请、限时例外和权限审计五类签收。

`DEC-057` 取代 `DEC-056` 的当前效力，并收窄 `DEC-041` 中“独立受控管理员”的适用范围。G0-09 从 `BLOCKED_BY_TENANT_ADMIN` 恢复为 `进行中`；[`2026-08-30_G0-09单人Owner权限基线.md`](2026-08-30_G0-09单人Owner权限基线.md) 的 `EVD-G0-09-ACL-OWNER-BASELINE-20260830` 可作为同一企业工作簿四个子表共用的当前 `acl_evd`。

这项决定只关闭“必须由另一名管理员签收”的流程负担，不自动关闭整个 G0-09。四域的 `SRC-* / srcv_*`、受控快照、逐域质量 EVD 与同一整体批准 EVD 仍须补齐，因此 G0-09 / Scope #9 继续未通过，外部责任包与 Scope 计数继续为 11/14、11/15，G0 未签，Ddev 为空。

## 2. 当前 L1 最小权限基线

当前阶段只要求 Owner 对同一企业工作簿确认以下四项：

1. 工作簿由公司账号控制，不以个人账号或外部账号作为运行主源；
2. 组织外访问与链接分享关闭；
3. 仅 Owner 保留管理权限，指定应用 / 机器人保持只读；
4. 没有额外外部成员、公开链接或未登记的高权限主体。

四项可由同一 Owner 使用官方界面或接口一次回读并自签，不再要求独立人员、五类截图、管理员日志导出或职责分离声明。新建副本、所有权变化、成员变化、分享范围变化或应用权限变化会使该基线失效，必须重新回读。

## 3. 生产权限门 `PROD-ACL-01`

以下任一事件发生前，必须先通过 `PROD-ACL-01`，但仍允许由当前 Owner 一人完成：

- 导入真实客服话术、客户数据或工单文件；
- 增加第二名人类协作者、高权限应用或外部组织；
- 将飞书作为产品运行时身份或内容来源；
- 接入 RAGFlow 等真实知识索引；
- 部署、真实 Pilot 或生产使用。

`PROD-ACL-01` 验证的是已经实现的控制，不要求在代码开发前先证明未来能力。最低包含：公司身份与资源 allowlist、应用只读 scope、外部分享关闭、成员快照、权限变更审计、紧急撤权 / 停用和失败时 fail-closed。只有组织未来明确指定第二名受控管理员或公司制度要求职责分离时，才升级为双人复核。

## 4. 开发边界

- `PILOT-S0 · SYNTHETIC` 按既有批准继续；
- 管理员设置页、权限预检、审计与停用能力可以使用合成数据进行开发，不再被独立管理员证据反向阻塞；
- 正式 Ddev 仍须等待其余 G0 / Scope 缺口和 G0-09 非 ACL 证据收口；
- 在 `PROD-ACL-01` 通过前，不得把真实数据、真实飞书运行链、真实 RAGFlow 索引、部署或 Pilot 写成已授权。
