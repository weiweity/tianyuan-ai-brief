# 单人开发开工门最小化决定

> **决定编号：** `DEC-058`
>
> **决定日期：** 2026-08-30
>
> **状态：** `CURRENT · L1_SINGLE_OWNER · MINIMUM_G0`
>
> **权威状态入口：** [`../02-G0责任与证据台账.md`](../02-G0责任与证据台账.md)

## 1. 决定

客服 Agent 采用“只把不可逆风险放在开发前”的最小门禁。当前为单人 Owner、0 新增付费、纯合成开发准备，G0 前只冻结问题假设、合成测试合同和唯一内容工作簿，不再要求真实坐席、独立盲审或逐域重复证据先于代码开发完成。

本决定调整 `DEC-055` 中 G0-03 / G0-13 的当前关闭条件，并收窄 `DEC-049` 对 G0-09 的重复取证要求；历史文件不改写，原条件转入后置真实验证门。

## 2. 三项精简

### 2.1 G0-03：问题假设可由 Owner 单次冻结

- 开发前只需要明确一期要解决的候选问题、现状流程候选、已知覆盖面和未测指标；
- 发生频次、确认安全答案耗时、错误 / 冲突和经营影响没有可靠实测时，必须写 `NOT_MEASURED`，不得编数字；
- “至少 3 名坐席用真实任务确认”后移到 G1a / Pilot Ready，不再阻塞单人 `DEV-M0`；
- 当前证据为 `EVD-G0-03-MENOKIN-APPLICABILITY-20260830`。

### 2.2 G0-13：先冻结可执行合成测试合同

- 开发前冻结 `20 + 12 + 18 = 50` 条纯合成用例，覆盖正常命中、安全负例与鲁棒性；
- 当前只证明本地确定性检索合同可重复执行，不证明真实准确率、提效或业务接受；
- 独立盲审、真实内容快照、关键词 / 语义对照和真实分层结果后移到 G1a；
- 当前证据为 `EVD-G0-13-MENOKIN-EVALUATION-FREEZE-20260830`。

### 2.3 G0-09：一个工作簿、一个收口包

- 四个逻辑内容域仍分别保留 `presale / campaign / aftersale / product`，防止运行合同丢域；
- 四域位于同一企业工作簿时，允许共用一个 `SRC-*`、一个物理 `WBV-*`、一个内容摘要快照 EVD、一个质量 EVD、一个 ACL EVD 和一个最终批准 EVD；四个逻辑域分别使用独立 `srcv_*`，不得复用同一运行版本身份；
- 不再要求 5 份独立快照、逐域重复签字或另一名管理员；
- 当前收口包为 [`2026-08-30_G0-09单工作簿收口包.md`](2026-08-30_G0-09单工作簿收口包.md)，公开安全投影为 [`2026-08-30_G0-09单工作簿脱敏快照.json`](2026-08-30_G0-09单工作簿脱敏快照.json)。

### 2.4 G0 / Ddev：同一 Owner、两次独立记录

- 当前 `L1 · SINGLE_OWNER` 模式不再要求业务、安全、预算、项目四名人员重复签字；既有责任包与 RACI 只作为冻结输入；
- 项目 Owner 可先签 G0，再单独签 `DEC-DDEV-01`；“独立”指两个不同动作、时间、结论和证据 ID，不要求两个不同自然人；
- G0 签发只确认 14/14 + 15/15 证据包，Ddev 签发只授权已冻结的 `DEV-M0` 边界；任一记录缺失都不得开正式开发；
- 进入真实数据、多人高权限协作、飞书运行接入、RAGFlow 真实索引、部署或真实 Pilot 前，再按对应后置门恢复职责分离与专项批准。

## 3. 后移而非删除的真实验证

以下条件仍然存在，但不再阻塞代码开发：

| 条件 | 新门禁 |
|---|---|
| ≥3 名目标坐席真实任务适用性 | G1a / Pilot Ready |
| 独立盲审与真实影子回放 | G1a |
| 真实频次、耗时、错误与经营影响基线 | G1b 前瞻证据 |
| 真实飞书运行接入、多人协作、RAGFlow 真实索引 | `PROD-ACL-01` + 对应数据 / 安全门 |
| 部署、真实 Pilot、生产使用 | Pilot Ready / 发布门 |

任一后置门失败都必须整改、降级或停止，不能以本次精简为豁免。

## 4. 状态影响

本决定及其证据包完成后：

- G0-03、G0-09、G0-13 可标记 `Pass`；
- Scope #5、#6、#9、#14 可同步勾选；
- 外部责任包为 `14/14`，Scope 为 `15/15`；
- **G0 仍未签发，Ddev 仍未成立，正式 `DEV-M0` 仍未授权。**

此后只剩两个组织动作：由同一项目 Owner 先单独签发 G0，再单独签发 `DEC-DDEV-01`。二者必须使用不同的记录与证据 ID，不得由本决定、代码测试、Git 提交或工作簿收口自动代签。

## 5. 不变边界

- 产品仓继续只用编译期合成 fixture；
- 不读取或提交真实客户原文、手机号、订单、凭证、飞书 URL 或 token；
- 不启用正式 OAuth、API、worker、migration、PostgreSQL、遥测、付费模型、自动发送、部署或真实 Pilot；
- commit、push、PR、merge、deploy 仍分别需要明确授权。
