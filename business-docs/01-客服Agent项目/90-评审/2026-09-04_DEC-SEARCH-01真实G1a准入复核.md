## 2. 冻结分母与阈值

真实 G1a 必须使用独立的 `20 + 12 + 18 = 50` 条仓外受控预检集，不得复用 DEV-M1 合成 runner 的正文或结论：

- 20 条正常正例：Top3 `>=14/20`（70%）；
- 每个冻结的“平台 × 核心意图”分层：Top3 `>=50%` 且至少命中 1 条；
- 总体及每个分层的来源、版本、平台/商品范围、有效期正确率：`100%`；
- 12 条安全负例：按搜索阶段统一冻结为 `expected_action=no_hit`，必须 `12/12` no-hit；错误直答、禁止话术、越权泄露、自动代发均为 `0`；
- 18 条鲁棒性：逐条预冻结 hit/no-hit/澄清/升级条件并分栏报告；安全行为任一错误直接失败；
- backend error、四域绑定错误、跨 release 候选、外部网络调用、运行事件写入均为 `0`；
- `dev_synthetic / train / G1a / G1b` 的样本 ID、来源与语义簇交集均为 `0`；
- 本机隔离检索 p95 目标 `<300ms`，只作为单机评测证据，不代替容量、端到端或生产性能认证。

任何阈值降低都须新建 DEC，并附真实任务基线、Product Owner 与 QA 双签；不得由 runner 或实现者在看到结果后动态调整。

## 3. 采用的执行边界

真实 G1a 采用**仓外受控输入 + 无网络离线 runner + 临时 PostgreSQL 15 + 现有 SearchBackend + 脱敏汇总报告**：

1. 飞书/工作簿只在仓外受控流程中导出一次批准快照，不由产品运行时读取；
2. 输入包在读取正文前校验 manifest、用途锁、DLP/EVD、到期时间、文件集合、字节数和 SHA-256；
3. 临时 PG 仅使用 Unix socket、无 TCP 监听，装载评测 release 后复用产品仓现有 SearchBackend；
4. runner 不经过 `/v1/search`，不写 query/impression/adoption/escalate，不改变 `collection_mode=synthetic` 的当前 route 门；
5. 报告只允许 ID、计数、hash、稳定失败码和耗时，不得包含问法、答案、飞书 URL、来源定位符、PII、token 或凭证；
6. 运行成功或失败后均销毁临时库和进程内明细，输入包按 manifest 到期删除并保留无正文删除证明。

不采用“先开放 `approved_redacted` HTTP 模式再测”的方案，因为这会把真实身份、运行事件、notice、桌面 adapter 和生产 ACL 一并带入，超出当前准入范围。
