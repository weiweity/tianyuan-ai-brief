> **状态：** **ARCHIVED · SUPERSEDED**（旧 RAG/向量主路选型输入）· 2026-08-05\
> **目标（/goal）：** 一期把「固定话术 RAG 素材库」训准、用起来；二期用聊天清洗扩库；三期自动训练/回复铺路；**不重复造轮子**，Electron 浮窗 + 飞书登录 + Top3 只选不改字 + 迭代提醒话术师\
> **配套：** [`25-PRD草案`](../../20-设计-进行中/25-PRD草案-客服Agent一期.md) · [现行 `26-数据模型`](../../20-设计-进行中/26-话术库与自动事实数据模型.md)

## 1. 话术库本质 = 分阶 RAG 素材库（你的畅想，产品化表述）

| 阶段 | 素材从哪来 | RAG 在干什么 | 人在干什么 | 改字 |
|------|------------|--------------|------------|------|
| **一期** | **固定话术**（话术师维护的标准 Q-A） | 标准 **RAG 素材库**：检索命中库内 Answer，**只选不改字** | 话术师根据无命中/跳过 Top1 等 **迭代优化话术与问法** | 否 |
| **二期** | **清洗一线聊天记录** → 更贴近一线的 RAG 素材 | 扩充/蒸馏语料库；开始允许受控改字 | 清洗规则、质检、审核入库 | 开始允许 |
| **三期** | 在以上库上 **自动训练/迭代** | 服务自动回复；按客户脾气与场景改字 | 治理与门禁 | 场景化 |

```text
一期：标准话术库 ──RAG──► Top3 原文 ──采纳日志──► 提醒话术师改库
二期：聊天清洗 ──► 一线素材库 ──RAG/回复库──► 受控改写
三期：自动训练闭环 ──► 自动化回复（另立项）
```

这与业界常见路径一致：**先管好知识库（content ops）→ 再日志闭环（feedback）→ 再自动扩库/Agent**，而不是一上来端到端自动回复。

## 2. 目标拆解：我们要「造」什么、「接」什么

| 能力块 | 目标 | 建议策略 |
|--------|------|----------|
| 向量检索 / 分块 / 知识库管理 | 标准 RAG | **复用** 开源引擎，不自写向量管线 |
| DeepSeek 接入 | 理解/排序/拒答（一期不生成替代正文） | **复用** 平台模型适配层或官方 API |
| 话术师后台 | 四类话术 CRUD、发布 | 可复用知识库 UI 或薄自研 |
| 采纳日志 + 无命中/跳过 Top1 | 迭代提醒 | **自研轻量**（业务特定）+ 参考 RAG 评估指标 |
| Electron 浮窗 / 桌宠 / 1–3 推送 | 一线体验 | **自研**（差异化）；自动填写可参考 RPA 思路 |
| 飞书登录 | 统一账号 | **复用** 飞书开放平台 OAuth |
| 二期聊天清洗 | 生成一线素材 | **复用** 文档解析/清洗流水线（RAGFlow 类）+ 人工审核 |
| 三期自动训练 | 远期 | 不在一期范围；预留日志与版本 |

## 3. 业界可参考方案（GitHub / 产品，不重复造轮子）

### 3.1 开源 RAG / 知识库平台（候选「引擎层」）

| 方案 | 大致定位 | 对你们的匹配点 | 注意 |
|------|----------|----------------|------|
| **[Dify](https://github.com/langgenius/dify)** | 开源 LLM 应用平台：知识库 + 工作流 + 多模型 | 知识库、工作流编排、可接 DeepSeek 类模型、适合快速试点 | 桌宠/浮窗/只选不改字/1–3 推送需外挂；要控制「生成改写」 |
| **[RAGFlow](https://github.com/infiniflow/ragflow)** | 强文档解析 + RAG；有客服/电商类模板 | **二期聊天/文档清洗** 强；知识库问答 | 一线浮窗体验仍要自研壳 |
| **[MaxKB](https://github.com/1Panel-dev/MaxKB)** | 企业级智能体/知识库，强调客服与嵌入 | 智能客服叙事、权限、可嵌系统 | 与 Electron 定制交互需 API 对接 |
| **FastGPT** | 知识库问答开箱 | 国内常见、上手快 | 定制交互同样外挂 |
| **LlamaIndex / LangChain** | 框架而非产品 | 若自研 BFF，作 RAG 编排库 | 比「装一个 Dify」重，但控制度高 |

对比文章与社区普遍结论：\
- **要整站编排 + 知识库** → Dify 类\
- **要脏文档/聊天清洗质量** → RAGFlow 类\
- **要嵌进自有客户端** → 任选其一作 **RAG 中台 API**，Electron 只做壳\

### 3.2 反馈闭环 / 评估（对应「跳过 Top1、无命中」）

| 参考 | 用途 |
|------|------|
| [NirDiamant/RAG_Techniques · retrieval_with_feedback_loop](https://github.com/NirDiamant/RAG_Techniques) | 反馈如何回写检索侧的教学示例 |
| **RAGAS** 等检索评估（Context Precision/Recall、Hit@K、NDCG） | 离线评测「检索是否把正确答案排前面」 |
| 业界 IR 指标 **MRR / Precision@K / 选用 rank 分布** | 直接对应你们「常选 Top2 不选 Top1」→ 排序问题 |
| Reddit/工程实践：客服内部助手靠 **query log + 人工补文档** | 与「提醒话术师」同构，不是自动改库 |

**结论：**\
- **闭环逻辑**（日志 → 聚类 → 工单）业界有方法论文与 notebook，但 **「提醒话术师改四类话术」** 几乎都要 **自研薄业务层**，没有完美开箱等于你们 PRD 的产品。\
- 不要自研向量库和分块器；**要自研的是：采纳事件模型 + 迭代工单 + 话术师工作台规则**。

### 3.3 飞书 / 国内生态

| 参考 | 用途 |
|------|------|
| 飞书开放平台登录 / 机器人 | 账号与迭代提醒推送 |
| 飞书 Aily 等知识问答 | 思路参考「连接知识→问答→调优」；是否采购另评，**不阻塞** 自建 RAG 中台 |
| ChatWiki 等垂直客服知识库 | 参考工作流，不一定整仓 fork |

### 3.4 客户端

| 能力 | 复用 | 自研 |
|------|------|------|
| Electron 壳、安装包 | electron-builder 等 | 浮窗布局、1–3 热键 |
| 自动填入接待框 | 可调研辅助功能/模拟键鼠库 | 失败降级剪贴板（已定） |
| 桌宠 | 可后期套开源桌宠骨架 | 一期浮窗优先 |

## 4. 现行架构（路线 A · 全自研）

```text
┌─────────────────────────────────────┐
│  Electron 浮窗/桌宠（自研）            │
│  飞书登录 · 粘贴原话 · Top3 · 1/2/3   │
│  自动填写→剪贴板 · 库内原文            │
└──────────────┬──────────────────────┘
               │ API
┌──────────────▼──────────────────────┐
│  自研后端（API + 检索 + 日志）         │
│  · script/question CRUD              │
│  · embedding + 向量检索 + 可选重排   │
│  · DeepSeek 适配（禁改写 Answer）    │
│  · 采纳日志 / 迭代工单规则            │
│  · 飞书 OAuth / 提醒（可后置）        │
└──────────────┬──────────────────────┘
               │
     ┌─────────┴──────────┐
     ▼                    ▼
  向量库/SDK（开源库）   业务 DB（话术+日志）
```

### 一期落地步骤（路线 A）

| 步骤 | 做什么 |
|------|--------|
| 1 | 落库表：script / question / query 日志（见 26） |
| 2 | 检索服务：切分/embedding/Top3，**返回必须等于 answer_text** |
| 3 | DeepSeek：理解/排序/拒答，Prompt+校验双禁改写 |
| 4 | Electron 浮窗主路径 |
| 5 | 无命中/选用 rank 可查；迭代提醒可先列表后飞书 |
| 6 | 08-12 假数据彩排 |

### 明确不要一期做的「轮子」

- 自研向量数据库内核\
- 自研通用 Agent 编排引擎\
- 自研「自动改话术正文」\
- 自研完整 ChatGPT 式对话产品（你们要的是 **坐席辅助 + 训库**）\

## 5. 风险与门禁（和现有项目对齐）

| 风险 | 处理 |
|------|------|
| 费用路径 B | DeepSeek/云向量未批前用 mock 或公司已有额度；cap 另批 |
| 出域 | 客户原话进 API 须脱敏与安全批 |
| 开源平台许可 | 上线前看法务（Dify 等许可证） |
| 「平台会改写答案」 | BFF 层校验：返回文本必须等于 `answer_text` |
| 自动填写不稳定 | 已定剪贴板兜底 |
