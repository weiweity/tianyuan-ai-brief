## 3. 路线 B · 中台 + 自研壳 · WBS 示意

### 3.1 模块拆分

```text
[复用] Dify 或 RAGFlow：知识库+检索（+可选工作流）
[自研] BFF：鉴权、强制原文、写日志、迭代规则
[自研] Electron 浮窗/安装包/飞书登录/推送
[薄]   话术师：用中台知识库 UI 或薄管理页
```

### 3.2 到 08-12 的示意排期（单人全栈体感）

| 段 | 天数（示意） | 交付 |
|----|--------------|------|
| B1 部署中台 + 导入四类假话术 | 1–2 | 知识库可检索 |
| B2 工作流/API：Top3 只出库内片段 | 1–2 | 禁改写校验 |
| B3 BFF + 日志表 | 1–2 | 调用中台 + 落 adoption |
| B4 Electron 浮窗 | 2–3 | 与路线 A 同体验 |
| B5 飞书登录 | 1–2 | 可先 mock |
| B6 迭代：无命中/跳过 Top1 列表 | 1 | 可先后台表，飞书后补 |
| B7 联调彩排 | 1 | |
| **合计** | **约 8–13 人天** | 同体验下通常更稳 |

### 3.3 中台怎么选（展示用）

| 中台 | 更适合 |
|------|--------|
| **Dify** | 一期快、工作流、接模型方便 |
| **RAGFlow** | 更看重二期文档/聊天清洗质量 |

一期 **只部署一个**，不要两个都上。

### 3.4 路线 B 的主要问题

- 要学一点平台配置\
- 许可证/升级需留意\
- 深度定制检索时要会「绕」平台限制（靠 BFF）\

### 3.5 路线 B 的好处

- 检索底座少踩坑\
- 更快验证「训话术库 + 浮窗」\
- 二期清洗可接同一生态\
