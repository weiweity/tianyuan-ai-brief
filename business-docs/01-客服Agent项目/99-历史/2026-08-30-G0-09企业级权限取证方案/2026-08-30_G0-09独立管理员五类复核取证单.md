## 3. 五类复核执行表

### 3.1 父级位置、企业策略与继承

**管理员操作**

1. 进入“管理后台 → 安全 → 成员权限 → 文档权限默认值管理”，分别检查工作簿创建者 / 所有者对应的成员、用户组、子部门、上级部门和企业全局规则，并打开“规则配置详情”确认应用对象。
2. 在管理后台确认本租户云文档 / 云空间的组织级外部访问、分享、协作者与根目录策略；记录页面实际名称、观察时间和生效范围。
3. 按受控证据包内的对象引用，核对“当前企业用户根目录 → 四域工作簿”和“当前企业用户根目录 → 受控证据包 → 待签文档及 5 个快照”两条链路。
4. 确认是否存在 API 直接成员列表未展开的上级空间授权、文件夹子项继承、默认共享、伙伴组织访问或管理员旁路。
5. 将默认规则与当前对象 ACL 分开记录：官方规则优先级为“成员 → 用户组 → 子部门 → 上级部门 → 企业全局”，同级多个部门 / 用户组冲突时分享设置从严；管理员后来修改默认值不会追溯修改历史文档，不能用当前全局默认值单独证明现有工作簿。

**必须留存**

- 组织级策略页、规则配置详情及应用对象截图或受控导出；
- 两条父级链的层级截图 / 导出；
- 现有工作簿当前对象 ACL，以及创建时适用规则或等价审计关联；
- 每项隐藏策略、继承访问或旁路的“无 / 有”结论及受控引用。

**判定**

- `PASS`：父级链与机器基线一致，且无未登记继承访问、默认共享或管理员旁路。
- `PASS-WITH-EXCEPTIONS`：存在经批准、范围明确且有到期时间的例外，并已进入 §3.4。
- `FAIL / NOT_PROVEN`：存在未批准继承访问，或无法查看组织级策略 / 上级访问。

### 3.2 角色组、群、部门与传递成员

**管理员操作**

1. 复核 9 个链路节点没有直接群、部门、用户组、知识空间角色或其他集合主体。
2. 在“文档权限默认值管理”的规则配置详情中检查当前所有者命中的用户组 / 部门规则，再检查企业角色、文档安全角色、伙伴组织、群组与部门授权是否可传递到上述对象。
3. 发现任何集合主体时，在同一观察时间展开其成员；记录主体类型、权限、传递来源、成员数量和受控导出引用。

**必须留存**

- 直接主体与传递主体的查询结果；
- 若存在集合主体，保存完整成员展开导出；
- “零传递主体”也必须由管理员具名、定时签收，不能只引用应用读取结果。

**判定**

- `PASS`：不存在未登记集合主体或传递授权。
- `PASS-WITH-EXCEPTIONS`：所有集合主体均已展开，成员、用途和到期均获批准。
- `FAIL / NOT_PROVEN`：主体无法展开、成员不可见、来源不明或存在未批准成员。

### 3.3 组织外访问与外部邀请

**管理员操作**

1. 复核工作簿和受控证据包对象的组织外访问与链接分享均为关闭。
2. 在“文档权限默认值管理 → 分享设置”和租户级“云文档设置 → 对外分享设置”分别确认：当前所有者是否允许分享到组织外，以及企业是否禁止成员向外部用户分享文件 / 文件夹；页面名称以实际租户 UI 为准。
3. 独立确认“邀请组织外用户 / 伙伴组织”的控制值；当前公开读取接口不回显该独立字段，因此不得仅凭应用读取判定。
4. 在行为审计中查询 `space_update_share_setting_doc`、`space_share` 和 `space_update_spaceshare_status`；关注 `ShareExternalEntityType`、`ShareEntitySameTenant`、`ShareEntityFullAccess`、`ManageCollaboratorEntityFullAccess`、`ExternalAccessOff`、`DisableLinkShare` 的前后值。

**必须留存**

- 独立外邀控制页面截图或对应审计事件导出；
- 当前设置、变更前值、变更后值、执行主体类型、时间和结果；
- 若无审计产品或字段不可见，明确记录产品 / 权限缺口。

**判定**

- `PASS`：组织外访问、链接分享和组织外邀请均关闭，且审计 / 管理后台证据与当前读取一致。
- `FAIL`：任一开关允许未受控组织外访问或邀请。
- `NOT_PROVEN`：只能看到当前文档设置，无法独立回读外邀控制或相应审计。

### 3.4 限时例外、代理授权与到期治理

**管理员操作**

1. 查询与上述对象相关的临时授权、代理授权、例外登记、伙伴组织访问和条件访问记录。
2. 若为零项，由管理员明确签署“截至观察时间，受控范围内限时例外 / 代理授权为 0”。
3. 若存在例外，逐项记录主体类型、对象范围、权限、原因、批准人、开始时间、结束时间、自动撤销状态和受控证据引用。

**必须留存**

- 零项查询截图 / 导出与管理员签收；或
- 完整例外清单及其批准、到期和撤销证明。

**判定**

- `PASS`：受控范围内例外为 0，且有独立管理员的具名、定时证据。
- `PASS-WITH-EXCEPTIONS`：例外均获批准、未过期、最小权限且具有自动撤销和复核责任人。
- `FAIL / NOT_PROVEN`：存在无批准 / 无到期例外，或只能从不含有效期字段的协作者接口推断“无例外”。

### 3.5 权限历史与审计

**管理员操作**

1. 在行为审计中以受控对象引用和观察窗口查询：
   - `space_update_collaborator_doc`；
   - `space_update_share_setting_doc`；
   - `space_update_collaborator_auth`；
   - `space_share`；
   - `space_update_spaceshare_status`。
2. 记录每种事件的结果数、成功 / 失败数、执行主体类型、最新设置后值和受控导出引用。
3. 将开发者日志中的权限读取轨迹作为补充：只登记“权限设置 / 成员 GET 存在、权限设置 PATCH 查询为 0”，不得将其写成权限变更历史通过。
4. 若租户不具备行为审计产品，记录产品与授权缺口；后续增补审计 scope、发布应用版本和租户授权必须分别申请，不得在本取证单中自动执行。

**必须留存**

- 覆盖完整观察窗口的审计查询条件与结果；
- 原始导出或连续截图；
- 事件数量、关键前后值与受控引用；
- 若结果为 0，仍须证明查询能力已开通、对象和窗口正确，不能只保存空页面。

**判定**

- `PASS`：审计覆盖完整窗口，关键分享 / 协作者事件可追溯，且最终状态与当前读取一致。
- `FAIL`：存在未授权变更、失败后未恢复、主体不明或最终状态不一致。
- `NOT_PROVEN`：产品未开通、权限不足、窗口不完整、对象不匹配或只有应用读取日志。
