## 真源分工

| 信息类型 | 唯一真源 | 更新触发 |
|----------|----------|----------|
| 项目目标、范围、里程碑 | 项目章程 | 范围、目标、阶段、里程碑改变 |
| 日期、门禁、资源基线 | 总排期 | 门禁或资源变化 |
| Owner、动作、证据、RAID、DEC / CR | G0 台账 | 事实、责任、风险或决定变化 |
| Scope、评测、验收 | Scope 与验收 | G0 冻结或正式评测 |
| 费用、cap、停止规则 | 费用与成本控制 | 预算或采购路径变化 |
| 技术工作流 | 全栈交付计划 | 架构 ADR、团队或发布方式变化 |
| 立项会快速呈现 | 客服 Agent 立项 PRD（衍生视图） | 真源变化后重新核对，不独立维护状态 |
| 日常推进与会议执行 | 客服 Agent 立项执行中心（00–06 的只读生成视图） | 真源变化后运行生成脚本并通过 `--check` |
| 组合优先级 | [`../00-项目驾驶舱.md`](../00-项目驾驶舱.md) | 项目顺序或健康度变化 |

README、周报、汇报 Web 和历史材料都不能自行发明项目状态。

## 文档规则

- 现行文件用稳定名称，不把日期写进文件名；
- 评审、会议、快照才带日期；
- 现行文档必须写 Owner、更新时间、状态和真源范围；
- 历史文件首屏必须写“历史 / 不得按现行执行”；
- 跨目录引用必须可点击，不只写编号；
- 原始纪要、飞书资源标识和内部人员材料继续按受限资料管理；
- 生成的 PDF、HTML、截图不作为业务真源。
- 执行中心只能由 00–06 真源生成；禁止直接编辑生成后的 `08-客服Agent立项执行中心.html`。
