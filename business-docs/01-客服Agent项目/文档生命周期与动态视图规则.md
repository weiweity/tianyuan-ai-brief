# 客服 Agent 文档生命周期与动态视图规则

> 本文是客服 Agent 项目的文档生命周期 SSOT。它只约束文档、生成物和外部记录的读写方式，不改变项目阶段、授权门或任何业务结论。
>
> 生效日期：2026-08-26 · 当前复核：2026-09-03 · 项目：CS-AI-C11

## 先记住这五句话

1. 项目状态会推进，但已经确认的历史结论不回写。
2. `00–06` 是当前项目状态和批准范围的真源；`07 / 08` 是可重生成的当前视图。
3. `09` 在 D0 需求会生命周期关闭后是历史快照，只做完整性校验，不用新状态重写。
4. HTML 和 PlantUML 图板是“源文件变更后显式重生成”的动态视图，不是实时订阅页，也没有后台 watcher。
5. Menokin 是当前唯一试点；`PILOT-S0`、正式 `DEV-M0` 与后续真实 Pilot 是同一项目的不同证据阶段，不建立平行 Demo 项目。

## 2. 当前状态如何推进

### 2.1 项目状态和业务视图

状态、阶段门、批准范围、证据 ID 只更新 `00–06`。变更后运行：

```bash
node business-docs/08-工具/sync_customer_agent_surfaces.mjs
node business-docs/08-工具/sync_customer_agent_surfaces.mjs --check
```

该流程会重新生成当前 PRD / 执行中心视图，并根据会议生命周期决定是否生成会议视图。它不是实时同步；修改真源后必须重新生成，打开已有浏览器页时还需要刷新。

当前经 `DEC-058` 收口的开发前门禁为 G0 `14/14`、Scope `15/15`；旧 G0-03 数量口径、旧 DAFUYAN G1a 包和此前 ACL 方案均保留历史，不回写旧文件。当前数字必须由 `00–06` 和状态解析器推导，不得手改生成 HTML；G0 与 Ddev 的签发状态继续单独维护。

`37-架构SSOT-v1.md` 与 `46-实现设计-开工包.md` 是 Ddev 签发时冻结的设计输入。后续 WBS / 切片进度只写入 `00–06` 当前真源和新的带日期证据，不为追进度回写这两份签发输入；确需修改其规范内容时，必须按 CR / DEC 评估并重新核对授权投影。

### 2.2 需求会历史快照

当 D0 需求会生命周期关闭后，`09` 只代表当时会前/会中的历史状态。后续项目推进不得把新的 G0、Ddev、费用或 Scope 数字回填到这份快照中。若需要表达后续变化：

- 在 `00–06` 更新当前状态；
- 在 `90-评审/` 或对应生命周期目录新增带日期的证据、决定或修订；
- 必要时在 `99-历史/` 更新索引，但不覆盖原始快照。

历史证据链接失效时只记录“链接失效/证据待恢复”及影响范围，不重建不存在的证据，不把测试文件存在写成历史 PASS。

### 2.3 架构图板

架构图的可编辑源是 `20-设计-进行中/diagrams/` 下 `01～08` 的 `.puml` 文件，源文件索引与说明见 `20-设计-进行中/diagrams/README.md`。任一源文件变化后运行：

```bash
npm --prefix sites run sync:arch-diagrams
npm --prefix sites run check:arch-diagrams
```

当前同步器读取现有 HTML 作为 canonical 手写壳，再更新受控状态区、内嵌 SVG 与溯源块；它不是从独立模板完整重建整页。因此，`00–06` 状态推进时可以同步修改壳层中的读图说明、证据卡与页脚，但不得手改 SVG 或溯源 hash，并必须同时运行 `test:architecture-contract`、`check:arch-diagrams` 与架构图板 UI 回归。若后续引入独立 HTML 模板，再将壳层所有权迁移到模板并同步调整本规则和测试。

HTML 中的 `#diagram-p1` 只是页面锚点。它能在重新生成并刷新后显示新内容，但不会主动感知本地 `.puml` 变化。

## 3. 两仓边界

| 内容 | 项目记录仓 `ai-赋能立项` | 产品实施仓 `customer-agent-prototype` |
| --- | --- | --- |
| 项目状态、G0 / Ddev、批准范围、证据索引 | 主责、唯一当前状态真源 | 只读了解，不复制成第二份状态 |
| 产品 UI、客户端、API、worker、migration、测试和打包实现 | 不承载 | 主责；当前 `DEV-M0 · IN_PROGRESS`，`W0`～`W4` 已完成，W5 runtime adapter / service readiness 待单独开工授权；仍只允许合成数据 |
| 设计合同与架构治理 | 保存项目正式合同和门禁输入 | 保存产品视觉/交互/工程实现 SSOT |
| 真实数据、OAuth、线上 API、部署 | 当前均未授权 | 只有在批准计划、G0、Ddev 和安全条件齐备后，才进入独立实现 |

两个仓库保持独立 Git 历史、工作区和运行时；代码存在、测试通过或 Demo 可运行，都不能反向签发 G0 / Ddev。

## 4. 飞书同步规则

飞书同步采用“精选文档包”而不是整仓复制。当前候选清单由：

```bash
node business-docs/08-工具/prepare_customer_agent_publish_manifest.mjs --check
```

约束，通常只包含脱敏的项目章程、排期、台账、Scope、费用、交付计划、周推进，以及当前 PRD / 执行中心和已批准的架构/实现设计文档。以下内容不得上传：

- `local-private/`、临时 `output/`、测试截图、二维码、缓存和依赖目录；
- 真实姓名、客户原文、PII、凭证、token、内部批准原话和未脱敏链接；
- 产品仓源码、`node_modules`、Demo 运行产物和任何可被误解为上线证据的文件。

外部写入前必须先确认目标飞书知识库/文件夹、文档所有者、当前登录身份、权限和当前 revision。没有明确目标时只做本地 manifest 与只读核对，不创建新文档、不覆盖旧文档。飞书文档是正式留存和协作入口，不是项目运行时读取源，也不与本地文件实时双向同步。
