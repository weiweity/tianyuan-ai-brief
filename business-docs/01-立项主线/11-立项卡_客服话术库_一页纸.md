## 1. 为什么要做（问题 · 给非业务也能懂）

客服正逐步 **转外包**。外包同学 **进不了公司内网**，标准答法不能继续靠「自己人默契」和个人文档。

今天的现状：

- 答复依赖经验与个人资料，**口径难统一、难实时更新**
- 新人/外包上手成本高，质量难治理
- 若只上「自动回复机器人」，风险高、也解决不了「标准谁维护」的问题

**一句话目标：**  
把标准答法做成可管理的 **快捷语资产**，用检索/意图推荐帮坐席选对话，支持统一更新，长期嵌入桌面聊天工作台。  
**BI 继续看服务结果；本项目改「应答这一步怎么干」。**

---

## 2. 做什么 · 做成什么样（四层能力）

按顺序建设，不一次承诺全做完：

| 层 | 能力 | 业务白话 | 首期是否申请 |
|----|------|----------|--------------|
| **L1** | 知识库 + 知识库问答 + **管理端改库生效** | 标准答法集中管、问得到；改一条坐席能搜到 | **是 · MVP-A** |
| **L2** | 话术算法 + 意图检索 | 按客户意图推荐合适快捷语 | **是 · MVP-A** |
| **L3** | **推送 / 过期提醒 / 版本·审批** | 广播同步与治理（≠「能改库」） | 二期 |
| **L4** | 桌面端嵌入聊天 | 工作台内一键用，少切屏 | 二期/三期 |

**使用形态（始终）：** 推荐 → **坐席确认** → 发出（人在环）。  
**不是：** 全自动代客回复、RPA 接管会话。

## 3. 首期申请什么（MVP-A · 建议写入费用）

| 项 | 内容 |
|----|------|
| **范围** | L1 + L2 初版：统一库、管理端改库生效、可问答、可意图/检索推荐、**内网 Web 入口**（**不**做桌面嵌入/代回） |
| **技术底座** | **优先复用**既有话术能力（如 `dafuyan-wording`）；立项后 **D0 前**完成复用盘点（能/部分/不能 + 缺口）。未盘点前 6–8 周为默认估计，非锁死合同 |
| **用户** | 内部试点坐席 + 话术师/管理者改库（名单在 **Scope 冻结** 后确定） |
| **周期** | 批后两段：**约 4 可用工作周内部可演示（G1a）** → 再 **约 4 周内部小试用（G1b）**（合计约 8 周量级；出差/旁线周另计） |
| **成功标准（首期·可测，数可 G0 共改）** | ① 有效话术 ≥200 条（或共定 N）且含分类+Owner ② 20 条黄金问法 Top3 命中 ≥70% ③ ≥3 名内部坐席连续 2 周、每人每周真实检索 ≥5 次 ④ 抽检 0 次自动代发 ⑤ 管理者改一条 → **同日**坐席可检索到 |
| **主 R** | AI 组 FDE（天元） |
| **需业务配合** | 话术真源 Owner **具名**、客服原则同意 —— **进入 Scope 的前置**（见 `10`/`16`），非开发中途再补 |
| **非本项 KPI** | 供应链/备案/上海会等布局线；不计入本卡成功标准 |

### 3.1 AI 费用申请要点（科目级 · 可再填数）

> 金额与供应商待你方财务/采购口径补齐；本卡先定 **要什么、为何、不批怎么办**。

| 科目方向 | 用途 | 不批则 |
|----------|------|--------|
| 模型 / API 调用 | 问答、意图理解、检索增强；**须设月度 cap**；量级占位：试用期 **数百～数千元/月**（精确数 48h 财务回填） | 仅关键词检索，体验上限明显 |
| 应用部署 / 算力或托管 | 内部可访问环境 | 仅本地 Demo，难试点 |
| 如需向量库/检索组件 | 语义匹配 | 退回规则检索 |
| （可选）桌面嵌入相关 | L4，**建议二期再申请** | 首期不做桌面 |

**申请原则：** 首期费用只覆盖 **MVP-A**；L3/L4 另立里程碑再申请，避免一次报大包。

## 4. 明确不做（立项必带 · 挡需求）

| 不做 | 原因 |
|------|------|
| 全自动代客回复 / RPA 代回 | 风险与口径责任；与「人在环」冲突 |
| 首期承诺外包全量开通 | 无内网与权限更复杂；内部验证后再谈 |
| 首期上质检/Agent 大闭环 | 依赖会话与规则，另项评估 |
| 设计 AI 出图主 R | 业务已自驱；不占本项带宽 |
| 仓储/供应链智能大系统 | 与 BI 边界冲突；另线查重/布局 |
| 无 Owner 的泛需求池 | 避免 FDE 变成全公司接单调研岗 |
