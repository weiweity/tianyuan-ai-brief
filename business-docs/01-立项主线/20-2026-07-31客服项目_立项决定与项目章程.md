## 2. 项目背景与机会

客服逐步转外包，乙方无法依赖公司内网、个人经验和“自己人默契”获得标准答法。现状导致：

- 标准话术分散，口径难统一、难追溯、难及时更新；
- 新人和外包学习成本高，答复质量依赖个人；
- 没有稳定标准时，质检和自动回复只会放大噪声与风险；
- 既有 `dafuyan-wording` 能力可能可复用，但尚未形成正式盘点结论。

**项目机会：** 先把“正确答案由谁维护、坐席如何找到并使用”做成稳定能力，再决定是否扩到质检、桌面嵌入和外包。

**证据边界：** 已有访谈能证明客服存在外包、口径与质检类痛点，但“话术库 MVP-A”也包含现有能力可承接的产品判断。G0 必须用真实用户与现状基线再次验证，不能把“技术上能做”当成“业务一定会用”。

## 3. 项目目标与成功定义

### 3.1 项目目标

建设一个内部可访问、可治理、可检索的客服话术库 MVP-A，使标准话术从个人资料变成由业务 Owner 负责的组织资产，并由坐席确认后使用。

内部试点只验证“内容治理 + 检索推荐 + 人在环”是否成立，**不证明外包网络、身份、授权和终端接入已经解决**；外包可访问性只能在 M4 单独评估后进入下一阶段。

### 3.2 首期成功标准

| 维度 | MVP-A 验收门槛 |
|------|----------------|
| 内容资产 | 有效话术 ≥200 条，或 G0 共定 N；每条至少含稳定 ID、适用平台 / 场景、状态、Owner、来源与版本 |
| 检索质量 | G1a 对冻结的 20 条正例全量盲测，Top3 命中率 ≥70%；另有不少于 5 条无答案 / 歧义 / 敏感负例，错误直答 = 0 |
| 基线与增益 | 同一数据集记录人工现状与关键词检索基线；语义 / 模型方案若无可解释增益，则降级到更便宜方案，不以“用了 AI”作为通过条件 |
| 真实采用 | ≥3 名内部坐席连续 2 周、每人每周 ≥5 个去重任务；检索次数不能单独通过，必须同时报告有用率、未命中率、采纳率与查找时长的分子 / 分母 |
| 人在环与可追溯 | 自动代发次数 = 0；每次推荐可追溯到有效话术 ID、内容版本与来源；无可靠依据时明确拒答 / 转人工 |
| 内容治理 | 草稿 → 复核 → 发布 / 下架 → 回滚最小链路可用，留审计记录；已发布内容同日可被坐席检索到 |
| 项目结论 | 能明确给出继续扩面、整改后重测或止损停止的书面结论 |

> 数字可以在 G0 由业务 Owner 与项目组依据基线共同调整；评测集、公式、阈值与内容快照一经冻结，变更必须进入决策日志并整集重测，不能在验收时抽掉难题或临时改口径。

## 4. 范围基线

### 4.1 In Scope · MVP-A

| 能力 | 最小范围 |
|------|----------|
| L1 话术资产 | 单一逻辑真源；稳定 ID、适用平台 / 品牌 / 场景、状态、Owner、来源、版本与有效期字段由样本验证后冻结 |
| L1 管理端 | 有权限的业务角色可起草、复核、发布、下架与回滚；改库同日生效并有审计记录 |
| L1 问答 | 只基于已发布且在有效期内的话术回答或定位内容；展示话术 ID / 版本 / 来源，无依据时拒答 |
| L2 检索推荐 | 支持关键词与意图检索，返回候选快捷语 |
| 坐席入口 | 内部 Web 入口；登录与最小角色权限 |
| 反馈闭环 | 坐席可标记“没搜到 / 不准确 / 需补充” |
| 评测 | 黄金问法、改库冒烟、人在环与采用记录 |
| 复用策略 | 优先盘点并复用 `dafuyan-wording`；形成能复用 / 部分复用 / 不可复用及缺口清单 |

### 4.2 Out of Scope · 首期明确不做

- 全自动代客回复、RPA 接管会话；
- 桌面聊天客户端嵌入（L4）；
- 外包全量开通与外部专网；
- 智能质检、评价分析、聊天 VOC 大闭环；
- L3 全员推送、过期提醒、复杂多级审批与完整版本治理（MVP-A 仍包含最小复核、发布、回滚与审计）；
- 供应链备案、BOM、对账或预警能力；
- 新建通用知识库平台或重复建设 BI 看板。

### 4.3 与供应链的边界

供应链方案已进入下一优先项目序列，但它：

1. 不计入客服项目的范围、工期或成功指标；
2. 使用独立 Owner、预算、样本、里程碑和验收；
3. 客服 G0 期间只保留必要协同窗口，默认不挤占客服主线；
4. 供应链正式启动时另发项目章程，不把两条线混成一个大项目。
5. 两项目数据、权限、评测集和调用计量按 `project_id` 隔离，避免供应链试用消耗客服预算；
6. 只复用通用的人在环审计、证据定位、反馈和评测框架，不共用业务指标；
7. 客服 Top3 命中率不能替代供应链差异召回 / 漏标等指标；
8. 客服 MVP-A 不依赖 PIM、PLM、SRM、金蝶、OCR 或供应链 RPA。
9. 供应链在客服 G0 / G1 期间最多占用项目可用带宽的 20%；客服关键门禁变黄或变红时，供应链准备工作自动暂停。

### 5.2 RACI

| 事项 | A 最终负责 | R 直接执行 | C 协商 | I 知会 |
|------|------------|------------|--------|--------|
| 项目方向与止损 | HR 人事总经理（待正式凭证核验） | 项目负责人 | 客服负责人、财务 / IT | 相关业务 |
| 产品范围与排期 | 项目负责人 | AI 组 FDE（天元） | 客服业务 Owner、话术 Owner | 金主 |
| 话术内容正确性 | **客服业务 Owner（待具名）** | **话术真源 Owner（待具名）** | 质培 / 坐席代表 | 项目组 |
| 技术方案与复用 | 项目负责人 | AI 组 FDE | IT / 安全 / 既有资产维护人 | 金主、客服 |
| 数据安全与出域 | **IT / 安全责任人（待具名）** | AI 组 FDE | 客服业务 Owner、法务 / 合规（如适用） | 项目负责人 |
| 费用与采购 | **预算责任人（待具名）** | 财务 / 采购接口人 | 项目负责人、FDE、IT | 金主、客服 |
| MVP-A 业务验收 | **客服业务 Owner（待具名）** | 项目负责人、业务验收人、FDE | 试点坐席、话术 Owner | 金主 |

**RACI 规则：** 每一事项只允许一个 A；多人可以共同执行 R，但不能用“共同 A”掩盖最终拍板人。

**硬门禁：** 业务 Owner、话术真源 Owner、预算责任人、IT / 安全责任人未具名，不冻结范围、不锁开发日历。

## 8. 关键风险与应对

| 风险 | 触发信号 | 应对 / Owner |
|------|----------|--------------|
| 话术无真源或 Owner 漂移 | 多版本互相冲突、无人签字 | Owner 具名后才冻结；业务 Owner 最终裁决 |

| 费用失控 | 无 cap、无调用台账 | 月 cap + 预警 + 超线停扩 |
| 内部无人采用 | 只有 Demo，无连续使用 | 客服经理点名试点；小规模真实场景跟跑 |
| 检索不准 | 黄金问法 Top3 低于门槛 | 修内容与检索；未达标不扩面 |
| 范围膨胀 | 追加代回、质检、桌面嵌入 | 使用本章程 Out of Scope；变更走决策日志 |
| 双主线抢带宽 | 供应链任务挤占客服 G0 / 交付 | 客服 P0；供应链另立项、另排期 |
| 能做但业务不用 | 真实坐席不认同问题或不愿切换 | G0 完成经理 + 话术 Owner + ≥3 名目标坐席验证，并记录现状基线 |
| 指标被刷高 | 重复搜索、挑题、验收前换题 | 任务去重、冻结评测集、盲测、全量计分，保留原始事件分母 |
| 过期 / 跨平台话术误推 | 话术缺适用范围、版本或有效期 | G0 用样本验证字段；发布态、有效期、平台 / 场景共同过滤 |
