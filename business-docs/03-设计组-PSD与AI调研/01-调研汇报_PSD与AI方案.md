# 01 · 调研汇报 · PSD 与 AI 方案（设计组）

> **版本：** v1.0 · 2026-08-07\
> **调研方：** 内部检索（Grok）+ 独立交叉（Codex CLI）+ 关键事实复核\
> **对应访谈：** 2026-07-22 电商设计提效；2026-07-22 品牌设计工作流\
> **一页摘要：** [00-一页纸](00-一页纸_给设计负责人.md)\
> **打分与证据：** [02-交叉验证与打分](02-交叉验证与打分.md)

---

## 0. 汇报目的

把设计组「**手里有 PSD，想用 AI 调**」的诉求，对照业内真实能力做一次收敛，避免：

1. 被「一键改 PSD」类营销话术带偏；\
2. 在大陆环境误把 **Adobe Firefly** 当默认可选项；\
3. 把本应 **设计主责的母版规范**，误当成「等技术做一个万能 Agent」。

---

## 1. 问题定义（对齐访谈）

### 1.1 电商设计侧（7/22）

| 现象 | 业务含义 |
|------|----------|
| 主图工作量大、依赖 PSD | 工程文件仍是交付与改稿中枢 |
| 文件过大、下载 15–20 分钟级、外网协作难 | 基础设施 + 资产形态问题，不单是 AI |
| Figma / MasterGo 迁移：费用、上手、**图层还原不全** | 历史资产绑定 PS，迁移 ROI 不清晰 |
| AI：字体乱、格子溢出、「抽卡」、详情页千篇一律 | **不适合**当前作为标准批量交付主路径 |
| 设想：运营改字改商品、模板系统、统一工作台 | 真需求，但是 **产品/模板问题**，不是「语义读 PSD」 |

**当时决议（访谈）：** 设计先收口痛点与初步方案 → 与技术评可行性/费用 → 小 Demo → 再向管理层要资源。\
**本次调研：** 提供外部方案地图，方便设计侧写「初步方案」。

### 1.2 品牌设计侧（7/22）

| 现象 | 业务含义 |
|------|----------|
| 多工具已在用（图生图/视频等） | 生成侧已自驱，不缺「再买一个会画的 AI」 |
| 抽卡、Token、高峰降质 | 产能与稳定性问题 |
| 丝印/小字/产品细节不可靠 | **商品事实层禁止 AI 直接生成** |
| 最终仍回 PS 精修 | 与业内共识一致 |
| Skill / 案例库 / 多工具串联 | 适合做 **沉淀与编排**，不是替换 PS 工程 |

## 2. 关键结论（业内共识）

### 2.1 能力边界

| 命题 | 结论 | 置信度 |
|------|------|--------|
| 是否存在「AI 完整理解任意复杂 PSD 并自然语言无损改稿」的成熟产品？ | **不存在** | 高 |
| AI 当前最稳场景 | 抠图、换背景、场景氛围、局部扩图/去杂、创意发散 | 高 |
| 可编辑交付中枢 | 仍是 **Photoshop（或高兼容 PSD 编辑器）** | 高 |
| 规模化批量 | **模板 + 智能对象 + 变量/动作/脚本**，AI 只在上游出素材 | 高 |
| 「导出 PSD」是否等于「编辑你们原 PSD」？ | **不等于** | 高 |

复杂 PSD 指：嵌套智能对象、实时字、蒙版、调整层、图层样式、混合模式、链接对象、插件数据等。\
学术侧仍把「自动生成/修改可编辑设计文件」视为开放难题（如分层 PSD 重建方向研究）；GUI Agent 在 PS 困难任务上成功率仍低（公开基准约一成多量级）。

### 2.2 大陆环境硬约束

| 约束 | 影响 |
|------|------|
| Adobe 官方：**Photoshop 生成式功能（含 Generative Fill 等）不对中国大陆用户提供** | 不能把 Firefly 写进大陆默认 SOP |
| 商品真实性 / 广告合规 | AI 场景不得导致功效、材质、价格等失真 |
| 生成合成内容标识要求（相关办法已施行） | 对外发布需按公司合规口径处理标识 |

## 3. 可行路径总览

### 3.1 路径地图（按「已有 PSD」场景）

```text
                    ┌─────────────────────────────┐
                    │  已有 PSD / 要交付分层工程   │
                    └──────────────┬──────────────┘
                                   │
           ┌───────────────────────┼───────────────────────┐
           ▼                       ▼                       ▼
    A. 单张局部改稿          B. 多 SKU 批量            C. 运营改字改价
    PS 母版 + AI 素材回填    模板母版 + 智能对象        稿定/Canva 类
    （大陆：非 Firefly）      + 变量/动作               （与 PS 工程解耦）
           │                       │                       │
           └───────────┬───────────┴───────────┬───────────┘
                       ▼                       ▼
                 人工终审（商品/价/Logo/法务 100%）
                       │
                       ▼
              交付：分层 PSD + 成品图 + AI 修改记录
```

### 3.2 路径明细

#### 路径 A · 单张局部改稿（大陆默认）

| 项 | 内容 |
|----|------|
| 做法 | 打开 PSD → 锁定商品/Logo/文字事实层 → AI **仅**生成背景/氛围平面 → 以智能对象或新层贴回 → 精修阴影透视 |
| 工具 | PS + 国内可用生图/抠图（即梦/通义/堆友等）或跨境抠图（Photoroom 等）+ Photopea（无 PS 时） |
| 图层 | **高**（工程仍在 PS） |
| 适合 | 主图改场景、去杂、扩画布后的素材补全 |
| 局限 | AI 不理解「价格层」业务语义；文字仍建议人工层 |
| 风险 | 云端上传素材的授权与留存；商品本体被 AI 改坏 |

#### 路径 B · 模板化批量（业内标准主线）

| 项 | 内容 |
|----|------|
| 做法 | 品类母版：商品位=智能对象；标题/价/促销=文字或变量字段；背景可换；Actions / Variables / Data Sets 批量导出 |
| 工具 | Photoshop 原生能力为主；上游 AI 批量出白底/场景图 |
| 图层 | **最高** |
| 适合 | 多 SKU、多语言、促销改价、平台多尺寸 |
| 局限 | 前期要规范命名与版式；长文案自适应仍要规则 |
| 风险 | 错价/错 SKU/字体授权，**不是**模型版权一项 |

#### 路径 C · 运营侧套版（减提需）

| 项 | 内容 |
|----|------|
| 做法 | 设计做好「可运营模板」；运营改字改图；设计只审关键节点 |
| 工具 | 稿定、Canva Bulk Create 等 |
| 图层 | 平台内可编辑；**PSD 往返低** |
| 适合 | 促销条、简单主图变体、渠道物料 |
| 局限 | 「PSD 转模板」≠ 原工程无损 |
| 风险 | 品牌走形、字体素材授权 |

#### 路径 D · 浏览器 PSD 轻改

| 工具 | 定位 | 说明 |
|------|------|------|
| **Photopea** | 成熟在线 PS 替代 | 开/存 PSD 能力强；**不是**语义 Agent |
| **Codia PSD Editor Online** | 2026-06 上线的在线编辑 + AI 辅助 | 可再导出 editable PSD；官方称不替代全功能 PS；复杂智能对象需回 PS 验证 |

#### 路径 E · AI 只做出图素材（不碰工程）

| 工具类型 | 代表方向 | 输出 |
|----------|----------|------|
| 跨境抠图/场景 | Photoroom 等 | PNG/JPG，**无 PSD 工程** |
| 电商平面套件 | Pic Copilot 等 | 平面图，**无分层工程** |
| 国产生成 | 即梦、通义、堆友等 | 平面/场景，回 PS 精修 |
| 品牌创意链 | 组内现有多工具 | 创意向；商品小字仍禁 |

#### 路径 F · Agent 遥控 Photoshop

| 项 | 内容 |
|----|------|
| 现状 | 研究/开源实验阶段；公开基准困难任务成功率低 |
| CLI-Anything 类 | 对闭源 PS 覆盖弱；不宜当生产 SLA |
| 适合 | 有人监督的重复动作（改名、导出、替换智能对象） |
| 结论 | **可观察，不可当 2026 交付主路径** |

#### 路径 G ·「从零生成可编辑稿」类

| 项 | 内容 |
|----|------|
| 代表讨论 | Seede 等「文生可编辑商业稿」 |
| 证据冲突 | 媒体/第三方称可导出 PSD；部分官方导出列表未见 PSD 或与第三方不一致 |
| 结论 | **可试用「新稿生成」**；**不得**写成「已验证的原 PSD 编辑方案」 |
| 姿态 | 标为 **不确定**，试点前要账号实测截图与导出结构抽检 |

## 4. 推荐 SOP（可直接贴组内 wiki）

### 4.1 局部改一张

1. 复制版本：原 PSD + 基线导出图\
2. 图层三分类：\
   - **事实层**（商品/包装/Logo/条码/价格字）：锁定\
   - **可调层**（蒙版/阴影/调色）\
   - **AI 层**（背景/氛围/局部补）：新建，不覆盖事实层\
3. AI 出素材 → 贴回 → 对光影透视\
4. **禁止** AI 重绘商品本体、丝印小字、Logo、色号\
5. 100% 检查轮廓/色差/字/Logo/倒影\
6. 交付：分层 PSD + 成品 + AI 来源记录\

### 4.2 批量 SKU

1. 建品类母版（命名规范统一）\
2. SKU 事实表：`sku_id`、商品图、标题、价格、颜色、促销、语言、法务、输出名\
3. AI 只做抠图/背景/场景；原商品图永久保留\
4. Variables / 智能对象替换 + Actions\
5. 先跑 20–50 个边界样（透明、毛发、玻璃、反光、白货、长文案）\
6. 自动查尺寸/命名；**价格/Logo/商品色/法务 100% 人审**\

### 4.3 旧详情页重做

1. 旧 PSD 当「历史证据」，不假设图层可继承\
2. 抽商品事实与授权素材 → **重建模块母版**\
3. AI 只助背景与版式方向\
4. 价格/参数/功效文案 **禁止 AI 瞎编**\

## 5. 与访谈「待办」的映射

| 访谈方向 | 本次调研给出的落点 |
|----------|-------------------|
| 收集痛点、写初步提效方案 | 本文 + `00` 一页纸可作方案骨架 |
| 评估费用与 Demo | 建议只 Demo **母版+变量 20 SKU** 或 **运营模板一条链路**，勿 Demo「语义改任意 PSD」 |
| Figma 迁移 | 调研不推荐作为当前主线；历史 PSD 还原仍是硬伤 |
| 云盘 PSD 缩略图 | 属于资产治理，可与 AI 解耦优先做（小投入、可感知） |
| 品牌 Skill / 案例库 | 与「母版规范」同一类沉淀；设计主 R 更合适 |
| 多工具 Agent 串联 | 创意向可远期；工程交付仍回 PS |

## 6. 组织与职责建议（避免扯皮）

| 角色 | 建议职责 |
|------|----------|
| **设计组** | 母版规范、禁改清单、质检标准、试点品类、工具账号与 Token 预算 |

| **合规** | 生成内容标识、商品真实性抽检口径 |

## 7. 汇报结语

1. **问题真实**：PSD 重、协作慢、AI 不稳定——访谈与业内现状一致。\
2. **解法清晰**：不是「更强的读 PSD AI」，而是 **母版工程 + 受控 AI 素材 + 人审**。\
3. **大陆约束**：Firefly 不可当默认；用国产/跨境素材工具回填。\
4. **下一步**：设计负责人确认是否启动 **单品类母版试点**；运营模板是否单独立项讨论。\
