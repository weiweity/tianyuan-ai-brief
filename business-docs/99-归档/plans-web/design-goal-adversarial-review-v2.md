# AI 立项决策台 · 双端设计 / 架构 / Goal 最终对抗评审

> 日期：2026-07-29
> 版本：Web v5.20 · 决策状态 Schema v2
> 评分范围：本地源码、正式 HTML、历史兼容 HTML、HTTP / file、三端浏览器、七页打印与自动质量门禁
> 证据视口：390×844、768×1024、1440×900

## 1. 页面 Goal

> 让决策者在 10 分钟内，分别为两个候选项目选择 A / B / C，确认预算与止损、具名 Owner、授权超线停扩，并带走一份不会被误读成正式审批的可校验会议草稿。

10 分验收标准：

1. 20 秒内知道今天拍什么、预算与三条止损线分别是什么。
2. 每个候选项目独立选择 A / B / C，不互相绑架。
3. 每个 A / B 项目必须补自己的 Owner；C 项目不制造假负责人。
4. 费用和停扩授权只在存在 A / B 时成为散会硬门禁。
5. 复制结论与 JSON 凭证始终保留“本机草稿”边界。
6. 手机、平板、电脑无页面级横向溢出，关键动作可触达。
7. 内容、规则、状态、安全、图表和样式边界可独立测试。
8. 唯一正式 HTML 承载业务内容，旧 HTML 只做受测兼容跳转。
9. 双击本地 HTML 不得永久骨架；离线快照必须标明边界并与 SSOT 可校验同步。

显示 10 分证据：

- 三个视口 × 七页逐页断言无页面级横向溢出、无阻断级 axe，并输出可审阅截图。
- 手机表格转卡片，Tab 可横向滚动，关键动作按 40–44px 触达标准设计。
- safe-area、横屏、`prefers-reduced-motion` 和恰好七页的 A4 打印 PDF 都有自动证据。
- Mermaid 固定为站内版本，输出 SVG 清洗后才进入 DOM。

交互 10 分证据：

- Tab、数字键、方向键、边缘按钮和触屏滑页共用同一活动页状态。
- 默认会议模式不暴露编辑能力；只有 `?edit=1` 开放作者工具和 E / S。
- 客服 Agent、供应链备案识别分别选择 A / B / C。
- C/C、A/C、A/B、错误预算、缺 Owner、缺停扩授权均有自动测试。
- 可复制逐项目结论、下载 JSON 凭证，并复算 SHA-256 识别篡改。
- Mermaid 灯箱支持键盘关闭、焦点归还、滚轮、双指缩放与单指拖移。
- 可滚内容区可键盘聚焦；手机七页逐页检查触控热区。

隐性知识 10 分证据：

- 明确“未批不开发、人在环、不代回、不代审”。
- 7000 是目标工具预算，5000 是首月止损，10000 是全期硬止损。
- 两个项目分别具备边界、Owner、门禁、停止条件和 A / B / C 结论。
- 本机草稿、哈希完整性、正式飞书 / 邮件留痕三者语义分开。
- 页面不伪造未签字的业务阈值、Owner 或审批结果，而是把未知项暴露为门禁。

## 4. 对抗 Review

| 级别 | 攻击 / 误用场景 | 关闭证据 |
|---|---|---|
| P0 | 手机首屏或表格横向截断 | 390px 七页 overflow 断言 + 截图 |
| P0 | 两项目共用路径导致结论失真 | 项目级路径；C/C、A/C、A/B 测试 |
| P0 | A 项目借用另一项目 Owner | Owner 按 `projectId` 匹配 |
| P1 | 7000 / 5000 / 10000 被混成一笔钱 | 文案分层 + 数值关系门禁 |
| P1 | 页面勾选被误认正式审批 | `localDraft: true` + UI 边界 + 复制文案 |
| P1 | 旧会议状态污染新版行结构 | Schema 不同整批拒绝；字段白名单合并 |
| P1 | 下载凭证被无痕篡改 | 规范化 payload + SHA-256 + 复验 |
| P1 | 编辑器或内容 JSON 注入脚本 | DOMPurify + HTML / URL / 类名白名单 |
| P1 | Mermaid 输出携带恶意 SVG | strict 渲染 + SVG 二次清洗 |
| P1 | 默认入口泄露作者能力 | `/` 与 `?edit=1` 浏览器断言 |
| P1 | 双 HTML 再次出现业务口径漂移 | 旧 HTML 只跳转且契约测试禁止业务正文 |
| P1 | file 入口因 origin null 永久停在骨架 | classic bootstrap + 离线 Bundle + 四组 file E2E |
| P1 | 离线 Bundle 落后于 content.json | 构建时内容 SHA-256 + `build:check` + pretest |
| P1 | 打印丢 Mermaid、出现空白页或交互控件 | 全图预渲染 + PDF 恰好七页断言 + PNG 视觉检查 |
| P2 | CDN 或依赖版本漂移 | 本地固定 vendor、SRI、License、lockfile |
| P2 | CSS / 主控制器重新膨胀 | CSS `<2600`、app `<2500` 自动门禁 |
| P2 | Actions 可移动标签被替换 | checkout / setup-node / upload-artifact 固定 commit SHA |
| P2 | 仅靠人工回归 | 三端逐页 E2E、axe、截图、打印、单测与 GitHub Actions |

对抗场景结论：

1. C/C 不要求无意义费用和 Owner。
2. A/C 只要求 A 项目 Owner，同时要求费用和停扩授权。
3. A/B 缺任一项目 Owner 都无法形成完整结论。
4. 目标预算或首月止损高于硬止损会被直接阻断。
5. 篡改 JSON 的项目路径后 SHA-256 复验失败。
6. v1 本机勾选不会套入 v2 项目级状态。
7. 恶意 HTML、资源 URL、事件属性和 SVG 脚本在进入 DOM 前被移除。
8. 旧 HTML 不再持有任何可过期业务正文。
9. 历史 HTML 通过 file 双击可完整加载，且明确标记为本地离线快照。
10. `content.json` 改动后不重建 Bundle，单元测试会在运行前直接阻断。

## 6. 10 分的事实边界

这些组织事实不能由前端伪造，也不降低页面在其职责范围内的分数：

- 飞书现存 v5.6 文档尚未与 Web v5.20 对齐；
- 实际 Owner 姓名需要会议具名；
- 供应链准确率与收益阈值需要业务样本和终审人签字；
- 页面 SHA-256 不是审批人电子签名，也不是权威审计后端。

工程侧的 10 分做法，是把未知项明确展示为未完成门禁，并阻止页面生成误导性结论。
