## 0. 我们到底在解决什么

### 0.1 战略一句话（来自 HR 总经理定调 · 7/21）

**AI 不是「多几个聊天框 / 自动回消息」，而是推动业务流程重组（BPR），用可度量样板验证方法，并在经营链路上保持布局（非只做客服小工具）。**

> 注意：HR 总经理**不掌握**各部门一线痛点细节；所有周报/汇报必须自带「业务背景翻译」。详见 `06-周报模板与第0期示例.md`、`05-各端口Goal周期收益对照.md`。

### 0.2 你的双重身份怎么摆

| 身份 | 该干什么 | 不该干什么 |
|------|----------|------------|
| **产品经理** | 定义问题、Owner、成功标准、优先级、跨部门对齐、翻译业务↔BI | 被每个部门的「想要」拖成无限需求池 |
| **AI 赋能工程师** | 判断 AI 适配度、做最小可用交付、沉淀 Skill/系统/数据口径、3 个月见效样板 | 接所有「上个大模型就行」的伪需求 |

**组合打法**：每个项目必须同时过两关——**业务愿不愿意用、技术能不能稳、能不能度量**。

### 0.3 成功长什么样（对齐 HR 总经理 + 转正）

| 时间 | 产品侧成功（她能听懂的） | 技术/运营证据 |
|------|--------------------------|---------------|
| **30 天** | 客服有一小波人**真在用**标准答法工具；周报说得清痛点与数字 | 话术库试点采用（周活/缺口）；非代回边界对齐 |
| **60–90 天** | 第二台阶：质检或评价或私域人效**其一**可见 | 同一文本智能底座扩展，或零成本 ETL |
| **全程** | 仓储不重复建设；备案有跟进；设计不乱接 | 查重结论 + 旁线状态一行 |
| **6 个月** | 2 个采用型交付 + 稳定周报 + 清晰不做 | 转正叙事完整 |

## 2. 产品视角：组合管理与筛选

### 2.1 价值分层（立项漏斗）

| 层 | 定义 | 在中台语境的例子 | 是否算「赋能成绩」 |

### 2.2 优先级打分（建议你统一用这张表）

每条需求打 1–5 分，总分 = **价值×2 + 急迫 + 可行性 − 依赖风险 − 组织风险**

| 维度 | 含义 |
|------|------|
| 价值 | 是否贴近愿景 L3/L4；能否量化（时效/人效/错误率/决策质量） |
| 急迫 | 业务是否天天痛；是否有明确 Owner 在催 |
| 可行性 | 数据是否可得；你已有资产能否复用；30–45 天能否 MVP |
| 依赖风险 | 是否卡 BI/接口/多系统/语义服务商/法务 |
| 组织风险 | Owner 是否清晰；成果是否会被其他部门「截走」；是否需自上而下推 |

## 3. 技术视角：怎么实现才不翻车

### 3.1 技术原则（建议写进你的工作协议）

1. **先工作流，后模型**：没有 SOP/标签/目标值，上模型只会放大噪声（VOC、质检同理）。  
2. **先数据可得，后智能化**：会话、班牛、ERP/有赞/私域赢家——拿不到数就只做流程设计，不承诺上线。  
3. **人机边界写死**：自动代回 / 全自动套版类默认拒绝；**检索、归类、报告初稿、异常预警、节点提醒**默认鼓励。  
4. **复用已有资产**：话术库 `dafuyan-wording`、飞书妙搭培训、知识问答定时推送——优先「插上业务」而不是重写。  
5. **交付形态分层**：  
   - L0 配置/SOP/模板（0 开发）  
   - L1 Skill + 人工触发（WorkBuddy/内部 Agent）  
   - L2 轻量应用（导入导出、看板、定时任务）  
   - L3 系统对接（接口/AOT/BI）  
6. **与 IT 边界**：你做方案与原型；BI/AOT 落数与生产接入（对齐中台老大组织设计）。

### 3.2 推荐技术架构（中台赋能「最小中台」）

```
┌──────────────────────────────────────────────────────────┐
│  业务入口（客服/私域/设计/备案 PM）                         │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│  应用层：话术检索 | 质检/分析报告 | VOC诊断 | 日报看板 | 备案校验 │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│  能力层：Skill/Agent | 标签体系 | 报告模板 | 规则引擎 | 定时任务   │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│  数据层：会话/评价/班牛/ERP/有赞/私域赢家/BI 口径字典          │
└───────────────┬──────────────────────────────────────────┘
                │
         权限 · 审计 · AI知识库 · 周报
```

**你一个人时的实现策略**：同一「文本理解 + 结构化输出 + 模板报告」底座，服务 **质检 / 评价 / 聊天分析 / VOC**；私域日报偏 **ETL+看板**；备案偏 **文档/图文 diff 校验**——三条技术栈，不要硬揉成一个大一统系统。

### 3.3 三条技术栈分工

| 栈 | 服务项目 | 关键组件 | 你已有/需补 |
|----|----------|----------|-------------|
| **A. 会话与文本智能** | C2 C3 C4 C5 C6 C11 | 标签树、质检规则、检索、报告生成 | 话术库已有；质检规则/会话接入待补 |

| **C. 文档与流程智能** | R1 R2 D2 D3 | 双稿 diff、节点状态机、Skill 库 | 上海线下会后定详设 |

## 4. 推荐优先级组合（产品拍板用）

> 假设：**你带宽 ≈ 1 人主 R + 温酒协调 + BI/AOT 按需 + 业务 Owner 配合**。  
> 原则：**同时最多 1 个「硬骨头」+ 1 个「快赢」+ 1 条「机制基建」**。

### 4.1 总优先级（建议版）

| 优先级 | 项目 | 产品理由 | 技术路径 | 周期直觉 | 成功标准（可度量） |

| **P1** | 评价分析报告（C3） | 易出报告样板 | 评价拉取 + 主题情感 + 周报模板 | 4–6 周 | 周更报告被班长使用 |

| **P1** | 设计 Skill/痛点方案（D2/D3） | 需设计 Owner 出方案，你评估+Demo | 提示词/Skill 库 + 小 Demo | 随设计节奏 | 1 个可演示流程 |
| **P1** | 项目节点提醒（R2） | 改变习惯，偏轻 | 飞书任务/机器人节点状态 | 上海会后 | 节点准时率 |
| **P2** | 聊天分析 / 聊天 VOC（C4/C6） | 价值高但数据未闭合 | 会话获取方案确定后启动 | 依赖解后 6+ 周 | 已购/未购流失点报告 |
| **P2** | 复盘 Skill（C7） | 有条件再上 | 逻辑说明书 + 指标字典 + Skill | 依赖数据治理 | 月报自动出初稿 |
| **P3** | 供应链 AI | 愿景大 | **只推 BI 治理议题，不接 AI 交付承诺** | 季度级 | 指标字典与看板权限 |

### 4.2 明确「不做清单」（保护带宽）

| 不做 | 原因 |
|------|------|
| 大模型 + RPA 全自动代回（客服/企微） | 稳定/合规/错答成本；与愿景的「重组」不符 |
| AI 全自动批量套版/精确改字 | 抽卡与品牌风险 |
| 客服侧泛问卷运营（抖音回流） | Owner 易漂移到会员/用户运营 |
| 供应链智能决策（当前阶段） | 无数据基建则输出不可信 |

### 4.3 30 / 60 / 90 天节奏（建议你对外用这张）

```
D0–D14   机制：知识库+周报+需求卡；快赢：品质问答推送；话术库试点准备
D15–D45  私域日报自动化 MVP；质检规则+抽检闭环；备案上海链路确认
D45–D90  评价周报 or VOC 单品类 MVP（二选一做深）；设计 Demo；复盘是否启动聊天 VOC
```

**关键决策点（建议你主动约中台老大 30 分钟）**：  
> 90 天样板主叙事选哪条？  
> **A 客服（质检+话术）** / **B 私域日报** / **C 备案校验** / **D 双样板（客服+私域，备案只跟进上海）**  
> 共创建议默认 **D**：一个对内人效（私域日报）+ 一个对外服务能力（客服质检/话术），备案作为组织最高优先但依赖上海会，你做方案与校验原型、不单线程死磕。

## 5. 各主项目一页纸（产品 + 技术）

### 5.1 客服会话智能（质检 → 评价 → 聊天 → VOC）

| 项 | 内容 |
|----|------|
| **问题** | 经验在人脑子里；报告散；老板看不到分析过程；培训慢 |
| **用户** | 客服经理、质检、抖音业务组一线、中台老板 |

## 10. 补充：各部门「预算气质」（影响交付形态，不改经营重要性）

> 来源：访谈显性信息 + 业务侧补充判断（2026-07-23 共创更新）

| 模块 | 预算气质 | 访谈/判断依据 | 对 AI 赋能交付的含义 |
|------|----------|---------------|----------------------|
| **私域** | **几乎无费用、排挤付费** | 接口约年 4–5 千已显贵；明确可「导表+程序」过渡；企微二次开发因成本暂不推 | **默认零采购方案**：定时导表/导出、本地或内网脚本、飞书/已有知识问答。不要把「买 API/买数云 AI」当前提。人效故事用 **省工时** 讲，别用「再花一笔软件费」。 |
| **供应链（备案/项目等）** | **相对可谈投入** | 甲方核心；经营权重高 | 治理/联办/准确率相关可谈；口径与责任仍是硬约束。 |
| **仓储物流** | **大概率不是有钱做新系统** | **BI 已接入**；ERP/金蝶等**已有接口**；访谈是愿望清单 | **先核实是否已做过**，再 **锦上添花**（异常提醒/助手/缺口）。不从零对接、不重复 BI。核实清单见 `00` §六。 |
| **客服** | **有一定软件预算** | 已有智能客服/RPA/班牛等工具链；业务提系统类需求 | **适合做「可采购 + 可自建」组合**：话术库/质检/分析类系统有付费空间；语义服务商、质检软件可进方案。仍守边界：预算买的是 **辅助与分析**，不是代回噱头。 |
| **设计** | **省钱、重 ROI** | Figma 费用卡、采购要算提效；已自费/共用 AI 会员 | 不主责；若协助也是 **低预算评估**，难批大采购。 |
| **备案/产研** | **愿为准确率付费（有条件）** | 免费视觉不够，提到需升级模型 | 付费模型/视觉可进资源表，但跟上海会与准确率共背，避免你一人背锅。 |

### 10.1 预算气质 × 交付策略（实操）

| 模块 | 推荐商务/技术策略 |
|------|-------------------|
| 私域 | **$0 路径优先**：导表 ETL → 看板；品质推送用现有知识问答。接口费仅在导表稳定证明价值后再提。 |
| 客服 | **可写进采购/试用**：会话/质检/分析工具；你方系统（话术库）可降低外购重复。 |
| 供应链 | **向老大要的是治理与集成资源**，不是私域式「别花钱」。可对齐 BI/AOT 正式项目池。 |
| 设计 | 不申请你主导的大预算。 |
| 产研备案 | 单独要「准确率相关」小额模型/视觉预算，绑定验收标准。 |

### 10.2 对优先级叙事的修正（有预算维度后）

- **私域仍真痛，但更像「零预算人效工程」**——适合快赢与信任，不适合当「要一大笔钱」的主标题。  
- **客服适合当「系统代表作」**——有预算土壤，和你技术栈匹配。  
- **供应链适合当「经营布局 + 可要资源」**——甲方内核；钱相对不是第一阻力，口径与组织才是。  
- **向老大要资源时分轨**：  
  - 私域：要 **权限与导表配合**，不强调花钱；  
  - 客服：可要 **软件/数据服务试用或预算**；  
  - 供应链：要 **BI 联办、治理排期、系统对接资源**（用经营语言，不是 AI 情怀）。
